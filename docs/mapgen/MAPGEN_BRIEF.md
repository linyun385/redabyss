# MAPGEN 设计简报（2026-10-30 用户口述，作为唯一需求来源）

> 这份是**原始需求**，不许在执行时被改写。细节展开见 `MAPGEN_DESIGN.md`（T54 产出）。

## 一、区域（生态网格）
- 每次开局，在一个大区域内按「单元格」生成区块，代表红渊的**生态**
- 生态数量、具体聚合程度 → 决定每个单元格的权重
- **总原则：同一种生态尽可能连成一片**（不是均匀撒点）

## 二、路线（线连事件格，不按格子走）
- 路线**不以单元格做具体匹配**，而是用**一条线把一个事件格连到另一个事件格**
- 事件格类型：战斗 / 精英 / 随机 / 商店 / 事件（就是现在点进去触发的那块）
- 线的**长度随机、方向随机**（斜向、不同角度、左右直着都行），但**总体向下**
- **大区域最下方向一定有事件格**
- 按「距底格的距离 = 深度」划**深度线**；从上一个深度线滑到下一个深度线的事件块**必然是 BOSS**
- 每个深度区内：设计具体有多少个不同类型的事件块（战斗/精英/随机/商店/事件），并**尽量分散**（两个同类事件尽量不相邻）
- 具体触发什么 boss / 怪 / 精英 / 事件 / 商店装备，由**生态区域 + 深度**共同决定

## 三、可见性
- 玩家**只能看到**：自己已经触发过的、以及**其周边**的事件块
- 需要两张图：
  - **总图**：自己点开看
  - **小图**：常驻游戏进程，显示玩家及其周边的事件块与区域

## 四、死路救援
- 走进死胡同 → 玩家可以**立即转到此前还没走过的另一条路径**
- 这个动作有**代价**：惩罚，或随机触发战斗事件

## 五、出口
- **最底下的格 = 最终 BOSS**（唯一）
