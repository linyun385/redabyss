# 02 · 语法课（一）：这个项目真正用到的六个基础

> 这篇只讲项目里**真实出现**的六个语法点，每个点都配项目里的真实行号，并回答同一个问题：「为什么这里这么写，不用这种写法会怎样」。看完你能读懂战斗引擎里九成的语句，并且敢改一个数值。一个要先说清的事实：**全项目没有一处模板字符串（`${}`）**——这一点在第六节按实情讲。

## 1. 变量与常量：`let` 与 `const` 的分工

看 `dealToEnemy`（对敌人扣血）的开头：

```js
  function dealToEnemy(C, enemy, amount) {
    if (enemy.dead) return;
    let dmg = amount;
    const absorbed = Math.min(enemy.block, dmg);
    enemy.block -= absorbed;
    dmg -= absorbed;
    enemy.hp -= dmg;
```

（[index.html:5923]。）同一个函数里，`dmg` 用 `let`、`absorbed` 用 `const`，区别是**这个值后面还改不改**：`dmg` 要先扣格挡再扣血，一路变小，所以是可变的 `let`；`absorbed`（格挡吸收量）算出来就不该再动，用 `const` 锁死——谁要是手滑在下面写了 `absorbed = 0`，代码当场报错，而不是让 bug 悄悄溜进血量里。这条纪律贯穿全项目：引擎里几乎每个函数都是「const 为主、只有真正变化的量才 let」。

如果全用 `let` 会怎样：功能完全一样，但读代码的人（三周后的你自己）再也分不清哪个变量是「算完就不动的中间值」、哪个是「会演化的状态」，改数值时容易踩到被复用的旧变量。如果全用 `const` 会怎样：`dmg -= absorbed` 这行直接报错，函数根本写不出来——这就是两者必须同时存在的原因。

## 2. 函数：普通函数与箭头函数为什么混用

普通函数（带名字、能被单独调用）构成了引擎的全部骨架，比如 `function playCard(C, handIndex, targetIdx)`（[index.html:5694]）——因为它要在很多地方被调用（前端 [index.html:6974]、引擎内部），需要一个稳定的名字。箭头函数则出现在两种地方：**回调**和**一次性小逻辑**。看 `render` 里给敌人框绑点击：

```js
    box.addEventListener('click', () => {
      if (e.dead || !C || C.over) return;
      if (pending !== null) doPlay(pending, e.idx);
    });
```

（[index.html:7828]。）这个函数没有名字、也不会被别人调用，它存在的唯一意义是「点击发生时执行这三行」。写成普通函数就得给它起名、还得想办法把 `e`（循环里的当前敌人）传进去——箭头函数直接「住在」循环体里，天生看得见 `e`，这叫闭包（03 篇展开）。

混用的规则可以总结成一句：**会被反复调用的逻辑起名字用 `function`；只在一个位置使用的逻辑就地用 `=>`**。如果全用普通函数：每个小回调都要命名加传参，[index.html:7874] 手牌循环里的十几个回调会各自膨胀成独立函数，读一次出牌流程要在文件里跳十几趟。如果全用箭头函数：`playCard` 这类核心函数没有名字，调试时调用栈里全是「匿名函数」，出了 bug 根本不知道是哪一环。

## 3. 对象与数组：一张卡是怎么被装下的

卡牌在 json 里是一个对象。`cards/diver.json` 第 28 行开始是下潜者的基础攻击牌：

```
  "id": "dive_0002",
```

（[cards/diver.json:28]。）从这一行往下十几行，是这个对象的全部字段：名字、类型、稀有度、脉、费用、效果、代价、风味文字、升级。效果本体在：

```
   "damage": 10,
```

（[cards/diver.json:38]。）一个对象用「字段名: 值」把这张牌的一切装在一起——`damage: 10` 表示打 10 点、`target: "single"` 表示单体（这些字段被谁读、怎么解释，是 04 篇的主题）。而牌库、手牌、弃牌堆是**数组**：对象是「一张卡的说明书」，数组是「一叠卡」。引擎把两者接起来的位置在 `startCombat`：`C.drawPile = shuffle(run.deck.map(c => Object.assign({}, c)), C.rng);`（[index.html:5710] 附近，对应 [engine/core.js:208]）——`map` 造副本、`Object.assign` 展开成新对象、`shuffle` 打乱顺序，最终牌堆就是「卡对象组成的数组」。

如果用「平行数组」（名字一个数组、伤害一个数组）会怎样：出牌时要先在名字数组里找下标、再去伤害数组取值，两个数组一旦顺序错乱就全乱了。对象把一张卡的所有属性捆在一起，永远不存在「对不齐」的可能——这就是数据驱动游戏都用对象的原因。

## 4. 条件判断：六道门的 `if`

`playBlockReason`（[index.html:7584]）是前端判定「这张牌为什么打不出去」的函数，连着的 `if` 各守一道游戏规则：

```js
function playBlockReason(card) {
  if (C.over) return '战斗已经结束';
  if (card._locked) return '锁死：这张牌本层无法再打出';
  const cost = uiCost(card);
  if (C.energy < cost) return '能量不足（需要 ' + cost + '）';
  if (card.effect && card.effect.gaze_cost && run.gaze < card.effect.gaze_cost)
    return '凝视不足（需要 ' + card.effect.gaze_cost + '）';
```

（[index.html:7584]。）每个 `if` 都对应一条玩家会撞上的规则，命中就**立刻 return**——后面的检查根本不执行。这种「早退」写法的好处是优先级天然成立：战斗都结束了，再谈能量没有意义。注意第四行的 `card.effect && card.effect.gaze_cost`：先确认 `effect` 存在再取它的字段，因为有些卡（比如 `basic_def` 缩起）的字段结构不完整，直接读 `card.effect.gaze_cost` 会在 `effect` 为空时让整个函数崩掉。`&&` 的这种用法叫「短路」：左边为假，右边根本不算。

如果写成一个大 `if/else` 嵌套会怎样：六条规则变成六层缩进的锯齿，改第四条规则要在五层 `else` 里找位置。早退式的平铺让每条规则互相独立、增删都不影响别人。

## 5. 循环：两段伤害的 `for` 与手牌的 `forEach`

伤害的段数循环用的是最老实的 `for`：

```js
      for (let h = 0; h < hits; h++) {
        targets.forEach(t => dealToEnemy(C, t, dmgEach));
      }
```

（[index.html:5829]。）外层 `for` 数段数（`hits` 是牌面写死的段数，比如 dive_0069 的 3 段），内层 `forEach` 对每个目标各打一次。两个循环的分工是「**循环次数已知且是数字**用 for、**对一个集合的每个成员做一件事**用 forEach」——段数是个数字，目标是个集合。

手牌渲染用的是同一思想的另一面（[index.html:7874]）：`C.hand.forEach((card, i) => {...})` 对手牌数组每张卡建一个 DOM。如果这里用 `for` 也可以，但 `forEach` 把「当前卡」和「下标」作为参数直接送到眼前，不用手写 `C.hand[i]`。反过来，伤害循环不用 `forEach` 是因为段数不是集合，硬凑成 `[...Array(hits)].forEach(...)` 反而绕。

如果循环写错边界（比如 `h <= hits`）会怎样：三段牌打出四段，伤害凭空多一段——这也是为什么练习篇（05）让你改数值而不是改循环：数值改错了看得见，边界改错了是暗伤。

## 6. 字符串模板：一个先说实话的章节

这一节的标题按任务书应该讲 `` `${}` ``，但先给一个 grep 事实：**整个项目（`index.html` 9137 行 + `engine/core.js` 1026 行）里 `${}` 出现 0 次**。项目里所有动态文字都用的老式加号拼接，比如日志：

```js
    if (dmg > 0) log(C, enemy.name + ' 受到 ' + dmg + ' 伤害。');
```

（[index.html:5930]。）这段代码把三个片段（敌人名、固定文字、伤害数）用 `+` 粘成一句话。它能工作，代价写在下面。任务书要求「解释模板比拼接好在哪」，这里用项目自己的代码来说明拼接的三个真实痛点：

第一，引号地狱。拼 JSON 或 HTML 时，最外层是单引号、里面属性要双引号，读 `'<svg class="esym ' + tierCls + '" aria-hidden="true"><use href="#' + tierSymId + '"/></svg>'`（[index.html:7795]）时要数着引号找边界。第二，变量藏在中间容易漏。`'凝视不足（需要 ' + card.effect.gaze_cost + '）'`（[index.html:7590]）里 `gaze_cost` 被加号夹着，删一个加号整句变 NaN 而不报错。第三，多行拼接要靠 `+` 续行，缩进一乱视觉上就断了。同样的句子用模板写是：

```js
log(C, `${enemy.name} 受到 ${dmg} 伤害。`);
```

变量直接嵌在反引号句子里，没有加号、没有断句。**但项目没这么写**——全项目从地图库到引擎到 UI 统一用加号，这是一种一致性选择：同一代码风格贯穿 9000 行，读任何一段都不用切换心智。所以这一节的真实结论是：`${}` 这个项目一处都没用；你读到的一切动态文字都是加号拼的，如果将来自己往里加一行日志，随大流用加号，别开先例。

## 7. 变量与常量：再补三个真实例子和一个反例

**例 A——累加器必须 let**：`cardCost`（[index.html:5765]）的第一行 `let c = card.energy || 0;`（[index.html:5766]）。`c` 是费用累加器，干旱层、冷洞层、遗物改费会依次往上加（[index.html:5767]-[index.html:5782]）——一路变化的量，用 `let` 是它的本分。注意 `|| 0`：`card.energy` 若没写（undefined），`undefined || 0` 得 0，函数不崩。这种「取值顺手兜底」的写法在引擎里到处都是，是防脏数据的第一道习惯。

**例 B——整块状态对象用 const**：`startCombat`（[index.html:5507]）用 `const C = {`（[index.html:5509]）一口气声明战斗容器——十几个字段装一个对象。`const` 锁的是「C 这个名字永远指向这个对象」，不是「对象的内容冻结」；整个战斗过程往 C 里塞血量、共振、手牌，都合法。如果你试图 `C = 另一个新对象`，立即报错——这正是设计者要的：战斗容器一场一个，不许中途整个换掉。

**例 C——常量提取成大写名**：`HAND_LIMIT`（[index.html:5373]）、`DRAW_PER_TURN`（[index.html:5374]）、`BASE_ENERGY`（[index.html:5375]）。全大写 + 下划线是「这是我拍板的规矩」的视觉信号；它们被引擎到处引用（抽牌 [index.html:5679]、回合能量 [index.html:5619] 附近），改一处全局生效。新手最容易犯的错是把这些数直接写死在使用处——`draw(C, 5)` 而不是 `draw(C, DRAW_PER_TURN)`——三个月后想调节奏时就得全文件搜数字。

**反例——`const` 的常见误读**：看到 [index.html:5732] 的 `C.playedThisTurn = true;` 会不会疑惑「C 不是 const 吗怎么还能改」？能。`const` 禁止的是**重新绑定**（`C = ...`），不禁止**修改内容**（`C.xxx = ...`）。真想冻结内容得用 `Object.freeze`，本项目一处都没用——因为引擎需要不断往容器里写状态。反过来说，mapgen 库里还有一批 `var`（[index.html:4544] 的 `var w = p.grid.w`）——那是老写法的残留，功能与 `let` 几乎相同但作用域规则更松（函数级而非块级），新代码学引擎侧用 `const`/`let`，别学地图库用 `var`。

## 8. 函数：再补三个真实例子和一个反例

**例 A——返回函数的函数**：`makeRng`（[index.html:5401]）返回的不是值而是函数（03 篇第 1 节已拆）。这里从语法角度看它：`return function () {...}` 这种「函数里造函数再交出去」的写法，是普通函数与闭包能力的合流点——普通函数的语法、箭头函数的语义，两种都能写，项目选了普通函数（它出现在 [index.html:5403]，带名字便于调试栈阅读）。

**例 B——一行函数也值得有名字**：`function shopPrice(a, b) { return a + Math.floor(run.rng() * (b - a + 1)); }`（[index.html:6802]）。只有一行，还是写了 `function` 带 `shopPrice` 名字——因为它被 `buildShopStock` 调用两次（卡价 [index.html:6807]-[index.html:6809]、遗物价 [index.html:6814]），**被复用就要有名字**，哪怕只有一行。判断「该用箭头还是命名函数」的实用标准就是调用次数：一处 → 箭头，多处 → 命名。

**例 C——嵌套命名函数**：`campOpt`（[index.html:6681]）定义在 `showCampfire`（[index.html:6671]）内部，缩进两格。它只在宿主函数里用，嵌进去让「篝火选项怎么造」的阅读距离保持在十行内。引擎侧的同款是 `hasDownPotential`（[index.html:4673]）嵌在 `growDAG` 内。嵌套函数不是坏味道——**使用半径决定嵌套**。

**反例——忘了回调契约会让队列卡死**：动画队列的成员是 `(done) => {...}` 形状（[index.html:7837]），`pumpAnim`（[index.html:7671]）靠 `done()` 才放行下一个。反例场景：你给队列塞了一个回调，里面某分支 `return` 之前忘了调 `done()`——整个动画泵停摆，之后所有飘字不再出现，且不报任何错。教训：**箭头函数当参数传时，先读宿主的调用约定**（它给你几个参数、期望你返回什么、要不要回报完成）。

## 9. 对象与数组：再补三个真实例子和一个反例

**例 A——数组里装对象**：敌人定义是「对象组成的数组」，`enemies/all.json` 第 1 行起的每个敌人有 `id/name/hp/intent_pattern` 字段，其中 `intent_pattern` 自己又是一个「对象数组」（每条 `{type, value}`）。套了两层的结构在引擎里被这样消费：`C.enemies = enemyDefs.map((d, i) => {...})`（[index.html:5543] 附近）把定义数组变成战斗实例数组。读嵌套结构的诀窍：先画 `数组 → 对象 → 数组` 的层次，再一层层对字段。

**例 B——对象当字典用**：`CLASS_POOL`（[index.html:6420]）用职业 id 当键、卡数组当值：`{ diver: [...], tremor: [...], ... }`。取值全靠方括号动态查：`CLASS_POOL[run.classId]`（[index.html:7173]）。这种「字典对象」在本项目里比比皆是（`MOD_E`、`NODE_GLYPH` [index.html:6515]、`TYPE_WORD` [index.html:8337]）——**固定键集合的映射**用对象就够，不必上 Map 类。

**例 C——浅拷贝与深拷贝混用**：`Object.assign({}, c)`（[index.html:5570]）是浅拷贝（嵌套的 `effect` 对象仍然共用），`JSON.parse(JSON.stringify(src))`（[index.html:6397]）是深拷贝（彻底断开）。项目在「战斗副本」用浅拷贝——省性能，且 effect 本来就不该被战斗改；在「池子适配」用深拷贝——adaptCard 要改 special 结构，绝不能碰真源。什么时候用哪个，判据是**你要改的深度**。

**反例——`|| 1` 会吞掉拼错的键**：`weight[c.rarity] || 1`（[index.html:7178]）。若某天加一个新稀有度却忘了在权重表登记，代码不会报错，而是安静地按权重 1 处理——卡「莫名其妙地常见/稀有」。反例的教训：兜底写法要写在你**预期可能缺失**的地方（`energy || 0`），而不是可能**拼错**的地方（稀有度这种受控词表，拼错应当大声失败）。

## 10. 条件判断：再补三个真实例子和一个反例

**例 A——switch 分发**：`applySpecial`（[index.html:5855]）用 `switch (sp.code)` 把 14 种特殊效果分给 14 个 case。分支多且同构时 switch 优于 if 链；末尾的 `default`（[index.html:5874] 附近）会给未实现的 code 打一句红字——**分发器必须有 default**，这是「json 里写错 code」不静默失败的唯一防线。

**例 B——链式取值的防御**：`run.classId === 'cangmin' && C.world === 'dream'`（[index.html:5946] 附近）这类多条件与，顺序有讲究：便宜的、常假的放前面（职业判断是字符串比较，先做），贵的放后面。引擎里 `if (card.effect && card.effect.gaze_cost && ...)`（[index.html:5709]）是同一思想：先确认对象存在，再谈字段。

**例 C——反向条件的早退**：`currentPattern`（[index.html:6063]）先处理「没有相位的敌人」（`if (!e.phases || !e.phases.length) return e.def.intent_pattern ...`），把主逻辑留给真有相位的——与 `playBlockReason` 的早退链同款。早退不止能用于错误检查，也用于「特例先行」。

**反例——真值判断的 0 陷阱**：`if (e.damage)`（[index.html:5823]）在 `damage: 0` 时整段跳过——一张写了 `damage: 0, special: [...]` 的卡，special 会结算而伤害段安静消失。再比如 `if (C.resonance)` 这类判断，共振恰好为 0 时分支不进。**真值判断把 `0` 当假**，凡是 0 是合法值的地方都要写显式比较（`=== 0` 或 `!= null`）。引擎里保留 `if (e.damage)` 的前提是「0 伤害没有意义」——你新加字段时要自己回答一遍这个问题。

## 11. 循环：再补三个真实例子和一个反例

**例 A——倒着循环**：渲染战斗日志是 `for (let li = lastLine; li >= 0; li--)`（[index.html:7930]）——最新的在最上面（注释 [index.html:7928] 写明是用户拍板）。倒序遍历同时服务两个目的：显示顺序、以及「先处理最新」的逻辑优先级。

**例 B——带守卫的抽样循环**：`resolveNode` 选敌人用 `while (picks.length < n && bag.length)`（[index.html:6642]）——从袋子里无放回抽样，`bag.length` 守卫防「要 2 只但池里只有 1 只」时死循环。**while 的循环条件永远要含一个会必然变假的量**，这条纪律在无放回抽样里尤其要命。

**例 C——循环里建 DOM**：手牌渲染 `C.hand.forEach((card, i) => {...})`（[index.html:7874]）每次执行重建全部手牌 DOM——没有 keyed diff、没有虚拟 DOM，就是「全删全建」。它的代价与收益：代码极简单（十一节讲过整屏重画的节奏），代价是出一次牌重画一次手牌。数据量小（手牌 ≤10）时这是正确取舍——**别为不存在的性能问题引入复杂度**。

**反例——forEach 里改正在遍历的数组**：`draw`（[index.html:5679]）循环往 `C.hand` push 的同时判断手牌上限；假如它写成 `C.hand.forEach(...)` 边遍历边 push，行为在 JS 里是「遍历到新追加的元素」——死循环风险。引擎所有「边遍历边增删」的场景（`endTurn` 的敌人状态结算 [index.html:6022] 附近）都刻意用 for 下标循环或先收集后删。记住：**遍历与增删不同时做**，否则循环边界会悄悄漂移。

## 12. 字符串拼接：再补两个真实例子和一个反例

**例 A——多段拼一句的样式**：`progressText`（[index.html:6517]）拼 HUD 进度：`'第 ' + run.depth + ' 层　' + L.name + ' · 第 ' + at + '/' + rows.length + ' 行'`。注意中间那个全角空格——拼接出来的句子要人读，排版字符也是拼接的一部分。这类「界面句子函数」在项目里全部保持一个模式：纯函数、无副作用、只拼字符串。

**例 B——拼接 HTML 与拼接文本的分界**：[index.html:7795] 拼 SVG（`eart.innerHTML = '<svg ...'`）走 `innerHTML`；[index.html:7811] 拼敌人名走 `el('div', 'ename', e.name)`（内部是 `textContent`，[index.html:6432]）。分界线是**内容来源**：代码常量拼 HTML 无妨；凡带数据（敌人名、卡名）的文本走 `textContent`——数据里若混进 `<` 符号，textContent 让它显示为字符而不是被当标签执行。

**反例——拼接出来的 SQL 式错误在本项目的镜像**：拼接最经典的事故是「值里含分隔符」。本项目最接近的现场是 `d.title = [card.flavor, ...].filter(Boolean).join('\n')`（[index.html:7893]）——若风味文字里恰好有换行，title 会多出几行，视觉上像 bug 但逻辑没错。项目用它，是因为 title 是低风险输出；同样的 join 若用于拼 HTML 属性就会变成真漏洞。**拼接的安全性取决于你把它喂给谁**，这句话值得在每次 `+` 之前过一遍。

## 14. 作用域三问：变量住在哪里、活到什么时候

第一问：**块级还是函数级？** `let`/`const` 是块级——只在最近的一对 `{}` 里活着；`var` 是函数级——整个函数都能看到。项目里的现成对照：引擎侧 `for (let h = 0; h < hits; h++)`（[index.html:5829]）的 `h` 出了循环就消失；地图库侧 `for (var i = 0; i < need; i++)`（[index.html:4560]）的 `i` 在循环外仍然可读。这就是为什么本篇反复强调「新代码别学地图库」。

第二问：**同名遮蔽。** 内层 `{}` 里再声明一个同名 `let`，外层那个被遮住。项目里最容易被误读成遮蔽的现场其实是**参数**：`dealToEnemy(C, enemy, amount)`（[index.html:5923]）的 `C` 遮住了外层任何同名变量——引擎函数一律从参数拿容器，从不读全局，这让每个函数都能单独读懂。

第三问：**活得最久的变量是什么？** 是 IIFE 里的闭包状态（`makeRng` 的 `s`，[index.html:5402]）和文件顶层的模块级状态（`let run = null, C = null, pending = null;`，[index.html:6437]）。前者被函数背走、后者贯穿整局。改代码前先问一句「这个变量活多大」——决定它是局部常量、参数、还是模块级状态。

## 15. `this` 在本项目里的缺席（为什么你读不到它）

教科书 JS 绕不开 `this`，但这个项目的业务代码里几乎碰不到它。原因有二：其一，引擎函数全是**纯函数风格**——数据从参数进、结果从返回值出，不挂在对象上，自然没有 `this`；其二，所有回调用箭头函数（[index.html:7894]、[index.html:7837]），箭头函数没有自己的 `this`，直接沿用外层——而外层也没在用。全项目真正用对象方法的场景只有 `Heap`（[index.html:4076]）那一个构造器内部。所以读这个项目可以放心地忘掉 `this` 的四种绑定规则——这不是缺点，是把「规则」与「数据」分离之后自然得到的简化。

| 方法 | 项目用法 | 行号 | 选它的理由 |

## 17. 三元、`||` 与布尔 coercion 的分层

**三元 `?:`** 用在「二选一的值」上：`card.type === 'attack' ? '攻' : card.type === 'power' ? '势' : '技'`（[index.html:7884]）——嵌套三元读起来像电梯逐层下落，两级是可读极限，三级就该改 switch。伤害公式里的 `(C.activeProtocol === 'purge' ? 3 : 0)`（[index.html:5825]）是三元的模范用法：一行表达「条件加成」。

**`||`** 用在「缺省值」上：`card.energy || 0`（[index.html:5766]）、`e.hits || 1`（[index.html:5824]）、`sp.v || 1`（[index.html:5860]）。要记住它的脾气：**左边是任何假值（0、''、null、undefined）都取右边**——所以它只适合「0 和空串本来就是无效值」的字段。`sp.v || 1` 意味着「写 0 也按 1 算」，这在本项目是可接受的（没有 v=0 的合法状态），换个项目就未必。

**隐式布尔**：`if (e.damage)`（[index.html:5823]）、`if (C)`（[index.html:7704]）、`if (!card)`（[index.html:6967]）。三处的共同前提是「假值不构成合法状态」。第 10 节反例讲过 0 的陷阱，这里补另一头：空数组 `[]` 是**真值**（数组永远是真值），所以 `if (targets)` 判断不了「有没有目标」，必须用 `targets.length`——项目里 `if (!alive.length) return null;`（[index.html:8061]）就是正确示范。

## 22. 数值与位运算：`>>> 0` 和它的邻居们

`makeRng` 里的 `(s * 1664525 + 1013904223) >>> 0`（[index.html:5403]）是全项目唯一的位运算。`>>> 0` 的语义是「按无符号 32 位整数重新解释」——乘加溢出 32 位的部分被自然丢弃，等价于「自动取模 2³²」。这正是一个廉价可复现随机源需要的性质，不需要任何库。为什么不用 `% 4294967296`：效果近似，但 `>>> 0` 同时把结果约束成整数、且避免负数取模的歧义，一行顶三行。

它的邻居们：`Math.floor(base * 0.75)`——虚弱状态下的伤害七五折向下取整（[index.html:6107] 附近）；`Math.ceil(overflow * 0.5)`——梦境反噬的「溢出一半向上取整」（[index.html:5963] 附近，向上取整意味着反噬永远不白给）；`Math.hypot(dx, dy)`——直角三角形斜边长，拖拽 8 像素判定用它（[index.html:7983]）；`Math.max(0, ...)`——全项目最常见的「不许为负」钳制（[index.html:5835]、[index.html:5929]）。读这些函数的要点是**看方向**：floor/ceil/max 各自回答「这个值允许往哪边偏」，数值设计的意图就写在取整方向里。

## 23. 时间三兄弟：Date.now、setTimeout、requestAnimationFrame

`Date.now()` 只在两处出现：种子缺省值 `seed === undefined ? Date.now() : seed`（[index.html:5402]，两份引擎各一）——「不给种子就用当前毫秒数」，这正是「每局随机、记下种子可复现」的实现。`setTimeout` 家族负责延时动作：toast 自动消失（[index.html:7606]）、飘字 450 毫秒后自删（[index.html:7664]）、hitflash 130 毫秒后摘除（[index.html:7842]）、战斗结束后 450 毫秒进结算（[index.html:6990]）。`requestAnimationFrame` 只有动画泵在用（[index.html:7674]）——它是浏览器「下一帧再执行」的正式通道，比 setTimeout(0) 更守时。

三者的一条纪律在项目里执行得很一致：**延时的回调里只做视觉，不改数据**。数据变化（引擎状态）都是同步完成的，延时只负责「让玩家看清」。你如果往延时回调里塞状态修改，就会制造「两次点击、一次生效」的时序 bug——这是 UI 编程第一大坑，本项目靠纪律躲开了它。

## 24. 防御清单：这个项目怎么防止「脏数据进来」

| 防御手段 | 现场例子 | 防的是什么 |
|---|---|---|
| `x \|\| 默认值` | `e.hits \|\| 1`（[index.html:5824]） | 字段缺失 |
| `a && a.b && a.b.c` 链 | `card.effect && card.effect.gaze_cost && ...`（[index.html:5709]） | 对象中途为空 |
| `Math.max(0, ...)` / `Math.min(...)` | 共振下限 0（[index.html:5734]）、格挡吸收上限（[index.html:5926]） | 越界值 |
| `try/catch` 包 localStorage | [index.html:7615]、[index.html:6472] | 环境不允许（隐私模式） |
| 函数入口早退 | `if (!C) return;`（[index.html:7704]）、`if (enemy.dead) return;`（[index.html:5924]） | 非法时机 |
| switch 的 default 红字 | 未实现的 special code（[index.html:5874] 附近） | 词表拼错静默失败 |
| `Array.fill(null)` 预占位 | 地图格子表（[index.html:4548]） | 稀疏数组的 undefined 陷阱 |

读懂这张表的意义：防御不是随机撒的，是**按数据边界撒的**——每一处 try/catch 都在「项目控制不了的外部世界」（浏览器存储、URL），每一处 `||` 都在「json 手写数据进引擎的门口」，引擎内部的函数之间反而几乎不设防（信任参数，靠 01 篇讲过的六道门统一把关）。改代码时遵循同一条边界：**外部输入处设防，内部约定处直行**。

## 25. 你改这里会发生什么（第三批修改点）

**修改点七：把 [index.html:5402] 的 `Date.now()` 缺省种子改成固定值 `12345`。**
会发生的连锁：不给种子开局时，每一局的抽牌/洗牌/血量序列完全相同——「每局随机」消失，游戏第二次玩就背版。地图种子不受影响（它有自己的 URL 参数入口，[index.html:8661]）。验证：连开两局，前三个回合的抽牌顺序逐张一致。这个修改点是「可复现性」的反面教材——复现是测试需要的性质，不是玩家需要的性质。

**修改点八：把 [index.html:5929] 的 `enemy.hp -= dmg;` 之前加一行 `dmg = Math.min(dmg, enemy.hp);`。**
会发生的连锁：敌人血量永远精确归 0，不再出现「10 血挨了 24 点」——视觉上 `hp` 数字不再跳成负数再被 [index.html:5931] 钳回 0。看起来更「干净」了，但 `dealToEnemy` 的返回值没有变，日志「受到 X 伤害」里的 X 仍是无钳制值（[index.html:5930] 在钳制行之后、用的是局部 `dmg`）——**日志与真实扣血会出现两套数字**。这个修改点演示「防御性钳制加错位置会制造数据分叉」：要么都钳，要么都不钳。

## 28. 反例补遗：三个容易读错的真实现场

**反例 A——`typeof sp === 'string'` 的兼容层**：[index.html:5854] 的 `if (typeof sp === 'string') sp = { code: sp };`。它说明 json 数据在历史上存在两种形态（裸字符串或对象）。读到这行的正确反应不是「学它」而是「警惕它」：兼容层是债务，新数据应统一走对象形态，让兼容层自然退役。

**反例 B——`e.def && e.def.tier` 的重复出现**：[index.html:7792]、[index.html:7813] 附近反复出现 `e.def && ...`。敌人实例理论上都有 `def`，但前端渲染代码不敢信任——因为 render 是「全屏重画」，任何时刻都可能拿到半初始化的实例。防御密度与数据来源的信任度挂钩，这条在第 24 节的表里已列，此处是它的重复出现规律：**同一个防御在一个函数里出现多次，说明该函数处理的数据边界不止一个**。

**反例 C——魔法数字与命名常量混住**：[index.html:8062] 的 `const GIVE = alive.length === 1 ? 170 : 70;` 把两个裸数字提成命名常量，而同函数的 8（[index.html:7983] 的拖拽阈值）仍是裸数字。同一个文件里两种习惯并存——现实项目就是这样。你能做的是新代码向「命名常量」靠拢，并接受旧的不必一次改净。

## 29. 缩进与风格的三个观察

观察一：**缩进是层级的唯一证据**。项目统一两空格缩进，`startCardPointer`（[index.html:7966]）里四层嵌套的 onMove 定义靠缩进读出作用域——没有花括号高亮工具时，缩进就是全部。

观察二：**注释写「为什么」，不写「是什么」**。抽样：[index.html:7970]「一开始就抓指针（快速甩手时 pointermove 会跑到别的元素上）」、[index.html:8023]「不用 elementFromPoint（松手瞬间命中的是卡片自己）」、[index.html:5714] 附近「层规则额外加价时必须说明白」。三条都在解释**决策理由**，而不是翻译代码。模仿这个密度：十行一注、每注一个「为什么」。

观察三：**代码分节靠横线注释**。`/* ───────── 营火 ──── */` 一类的分节符把 9000 行文件切成可检索的段（[index.html:6661]、[index.html:6793]、[index.html:6882]）。读大文件的正确姿势是先扫分节符建骨架，再进感兴趣的段——00 篇第六节的分区表就是这么来的。

## 31. 本篇刻意没教的四样东西（以及为什么）

**`class` 与 `new`**。全项目只有一个 `Heap`（[index.html:4076]）用了 `this` 与构造器调用——引擎、UI、生成器没有一处 `class` 声明。这不是项目落后，是数据驱动的自然结果：卡是 json、状态是对象字面量、行为是函数，没有需要「类」来封装的东西。教你 class 你在项目里找不到第二处用它，属于浪费篇幅。

**`async/await` 与 Promise**。项目零处出现（唯一接近的是 `setTimeout` 排队与 `requestAnimationFrame`）。原因是它是单页本地游戏：没有网络请求，没有异步 I/O，一切「等待」都是动画时长而不是数据等待。等你哪天给这个项目加联机或云存档，再学不迟。

**模块系统（import/export）**。页面只有 `<script>` 标签顺序加载（[index.html:972]、[index.html:3943]、[index.html:3950] 三个块），模块间通信靠全局变量（`window.RedAbyss`、`window.ART`、`window.MapGen`）。这是「双击即玩」约束下的选择；代价是加载顺序不能乱、全局名不能撞。core.js 末尾的 `module.exports`（[engine/core.js:1023]）是唯一向 node 侧开的口子。

**继承与原型链**。项目里没有任何对象继承另一个对象的写法——卡牌之间的差异全部用**字段差异**表达（一张 json 对象 vs 另一张），而不是「子类改父类方法」。这是数据驱动的核心信念：**用数据的不同表达行为的不同，不用类型的不同**。你在这个项目里想给「某张特殊的卡」开小灶，正确做法是在 json 里加字段、在 applySpecial 加 case，而不是造一个继承结构。

把这四样点名出来，是为了让你在读其他教程时不被骗走注意力：那些教程教的是「通用 JS 世界」，而这个项目在刻意收敛语法面——**能不用的不用，用到的都贯彻到底**。收敛是有代价的（见第 6 节的字符串拼接），但换来的是 9000 行里读任何 20 行都不需要超出本篇的知识。这是真实项目里少见的品质，也是本篇敢于只讲六个点的原因。

## 33. 格式事实：分号、行宽、注释语言

分号：全项目**带分号**（抽查 [index.html:6436]、[index.html:6802]、[engine/core.js:54]），无一省略。行宽：多数语句在 120 字符内，但存在长行——RAW 那一行是刻意的一整行（[index.html:6391]），绑定表行 [index.html:973] 同理；这类超长行都是**构建产物**，人工代码最长见 [index.html:5825] 的伤害公式（一行容纳四项加法，注释在上方补了上下文）。注释语言：中文为主（决策记录式注释），但变量名、字段名、日志前缀是英文——读注释学意图，读标识符学结构，两条信息通道别混。

还有一个容易忽略的格式事实：**同一文件的缩进层级混着 1 空格与 2 空格**。json 文件（如 [cards/diver.json:28] 起）是 1 空格缩进，JS 是 2 空格——因为 json 由导出脚本生成（`JSON.stringify` 的缩进参数），手写 JS 保持 2 空格。见到缩进风格突变，先想到「这里是产物还是手写」，再想到「风格不统一」。
