# 05 · 动手练习：改一句话、改一个数、看一条钩子

> 这篇是三个自己动手的练习，由易到难，全部**不破坏游戏**：每一步都给「改哪一行、改成什么、怎么验证、改坏了怎么撤」。按教学包的规矩，本篇只写步骤，没有真的改任何文件——文末有核对方式。

## 练习一（容易）：改一句卡面风味文字

**目标**：把聚能枪的风味句换成你自己的话，刷新页面就能看到。

1. 打开 `cards/diver.json`，找到第 42 行（`dive_0002` 聚能枪对象内，从 [cards/diver.json:28] 起第 15 行）：

```
  "flavor": "填弹的时候它自己热了。这里没有火。",
```

2. 只改引号里的字，比如改成 `"flavor": "填弹的时候它自己热了。这里只有你。",`。注意：**外层双引号和行尾逗号都不能动**——json 对引号和逗号敏感，少一个逗号整个文件就加载不出来（症状是游戏白屏或卡池全空）。
3. 重建页面：在 `game` 目录跑 `node tools/_t46_wire.js`。这一步把 json 重新拼进 `web/index.html` 的 RAW 行（原理见 04 篇第 2 节）。如果没有 node，用临时法：直接打开 `web/index.html`，搜「填弹的时候它自己热了」，只改那一句（这改的是产物行，下次重建会被 json 覆盖——适合先试手感）。
4. **验证**：刷新浏览器（临时法直接刷新；json 法刷新前先确认重建脚本报了成功），进一局下潜者，战斗奖励或商店里拿到「聚能枪」，鼠标悬停卡面——悬停提示的第一行就是风味文字（绑定在 [index.html:7893] 的 `d.title`），或者看卡面下方的斜体小字（[index.html:7892] 渲染 `card.flavor`）。
5. **撤**：把第 42 行改回原文即可：

```
  "flavor": "填弹的时候它自己热了。这里没有火。",
```

改坏了-json 打不开的情况：把整行删掉重抄上面这行原文；症状若持续，说明动到了相邻行的逗号，对照 [cards/diver.json:41]（`"cost_text": ""` 行）检查上一行末尾的逗号还在不在。

## 练习二（中等）：给聚能枪的伤害 +2

**目标**：伤害 10 → 12，打一次牌看数字真的变了。

1. 还是 `cards/diver.json`，第 38 行：

```
   "damage": 10,
```

2. 改成 `   "damage": 12,`（保持三个空格缩进；缩进不强制，但保持原样最稳）。
3. 重建 + 刷新（同练习一第 3 步）。
4. **验证**：进战斗，把聚能枪拖到敌人身上。飘字显示的不是 12 而是 **12 + 连携加成×2 + 力量**——01 篇第 4 节的公式（[index.html:5825]）。干净看数法：这一回合一张同脉牌都没出、没有力量 buff 时，飘字正好是 12。另一个不看运气的验证：卡面描述直接显示「伤害 12」——描述是 `cardDesc` 从字段现算的（[index.html:8108]），拿到卡就看得见，不用真打。
5. **撤**：第 38 行改回：

```
   "damage": 10,
```

再重建一次。改多了找不回原文：任何一张下潜者卡的效果字段都能对照 `docs/content/cards_diver.md`（导出表）核对，但**以 json 为准**——两边不一致时改 json 那份。

顺手理解一层：为什么飘字可能不是 12？因为伤害公式的每一项都在引擎里现算（[index.html:5825]：`e.damage + bonus + strength + 协议`），json 里的 12 只是其中一项。这就是「数据驱动」的边界——数据给基数，规则给放大。

## 三个练习共同的保险丝

- **只改给的位置**。练习一、二只碰 `cards/diver.json` 的第 38/42 两行；练习三只在 [index.html:7624] 插一行。json 是「改一行重建一次」，页面是「改完强刷」。
- **改坏的最快恢复法**：json 的两处改坏不会传染——重抄原文行即可；`index.html` 是 9137 行的构建产物，真正的恢复法是重跑重建脚本（它只重写 RAW 一行，你手插的 console.log 在 RAW 行之外，不会被冲掉）。仓库没有 git（`git status` 确认 fatal: not a git repository），所以「撤」全靠本文贴出的原文行，练习前可以把对应行复制到一个空文本文件里存着。
- **怎么确认自己没改坏别的**：三个练习做完后，对照源文件——练习一、二的 `cards/diver.json` 应只在第 38/42 行与原文不同（练习全部撤掉后应逐字还原）；练习三的 [index.html:7623]-[index.html:7627] 应与本文第 3 节贴出的五行一致。本教学包交付时**没有动过任何文件**：以上全部只是步骤，`git status` 输出 fatal（无仓库），`cards/*.json` 与 `web/index.html` 均保持交付前原样。

## 自测题

1. 改了 json 但刷新后卡面没变，最可能漏了哪一步？
2. 练习二里飘字显示 15 而不是 12，哪几个加成可能参与了？（看 [index.html:5825]）
3. 为什么练习三不用重跑重建脚本？
4. 一次性把 `"damage": 10` 改成 `"damage": "12"`（多打了引号），游戏会怎样？（提示：`e.damage + bonus` 的加法）

**答案**：1）漏了重建——`node tools/_t46_wire.js`，页面读的是 RAW 行不是 json。2）连携（同脉第二张起 +1、加成 ×2）、力量 buff、清剿协议的 +3；12+3=15 最常见的是 1 次连携（bonus 2? 注意 bonus=chain×2，chain=1 时为 0——所以 15=12+3 是协议，或 12+2+1 是「bright 层光脉 +2 与 1 力量」的组合，按当时局面查 [index.html:5825] 各项）。3）它改的 `web/index.html` 就是浏览器直接加载的文件本身；`cards/*.json` 才需要经脚本拼进页面。4）数字变成了字符串，`"12" + 2` 在 JS 里得到 `"122"`——伤害变成一百多，这就是 json 里数值不能带引号的原因。

## 七、第三批练习：改一行档（练习 11-15，每题只改一行）

这一档开始动手。统一纪律：**改前把原行抄下来，改后能逐字还原**。

**练习 11：手牌上限 10 → 8。**
改 [index.html:5373] 的 `const HAND_LIMIT = 10;` 为 8。**验证**：战斗中刻意囤牌，手牌到 8 后 `draw`（[index.html:5682] 的上限判断）不再塞入。观察点：抽牌堆的牌没消失（只是堆着），弃牌洗回照常。**撤**：改回 10。

**练习 12：篝火回血 50% → 30%。**
改 [index.html:6689] 的 `Math.floor(run.maxHp * 0.5)` 中的 0.5 为 0.3。**验证**：走一次篝火选「静日」，回血数字是最大生命的 30%（向下取整，`Math.floor` 在同一行）。**撤**：0.5 原样贴回。观察点：同行的 `Math.max(1, ...)` 保证至少回 1——把 0.3 改成 0.001 再看一眼这个下限的作用，一题两吃。

**练习 13：冷洞层的首张加价 1 → 2。**
冷洞加价在 `cardCost` 内（[index.html:5772] 附近的 `c += 1;`，其上两行是 cold 判断与首次警告）。把那一行改成 `c += 2;`。**验证**：打到第 2 层（外层冷洞），每回合第一张牌的费用角标 +2（角标是 `uiCost` 现算的——注意它只算 dry 与遗物，不算冷洞！对比 [index.html:7577] 发现界面显示与实扣的差异，这本身是本练习的隐藏收获：**引擎与界面各有一份费用逻辑，改引擎侧会造成显示不同步**——看到的警告「冷洞…多花 1 点」的文字也过时了，它在 [index.html:5771]）。**撤**：`c += 1;` 贴回。这是 15 题里唯一「改完会露馅」的题——它教你改规则要连显示一起改。

**练习 14：Boss 金币 50-80 → 100-130。**
改 [index.html:7155] 的 `const g = 50 + Math.floor(run.rng() * 31);` 为 `const g = 100 + Math.floor(run.rng() * 31);`。**验证**：打死一个 boss 节点，结算面板金币 +100 到 +130 之间。**撤**：原行贴回。观察点：`* 31` 是 [a, b] 区间宽度的标准写法（50 到 80 共 31 个整数），对应 00 篇清单里 `randInt` 的公式——区间改对了，随机才均匀。

**练习 15：toast 停留 1600ms → 3000ms。**
改 [index.html:7606] 的 `ms || 1600` 为 `ms || 3000`。**验证**：能量不足时拖一张卡，提示浮出明显变久；而显式传了 ms 的调用（如 onceHint 的 3000，[index.html:7616]）不受影响。**撤**：原样贴回。观察点：`||` 的缺省语义——练习 02 篇第 17 节讲过，这里是它的实战面。

## 八、第四批练习：加一个小功能档（练习 16-20）

这一档每题「加几行」，做完你就具备了给这个项目写补丁的全部基本动作。

**练习 16：音效计数器。**
在 `playSfx`（[index.html:7623]）函数体第一行加这两行（缩进两个空格，与上下行对齐）：
`  window.__SFX_COUNT = window.__SFX_COUNT || {};`
`  window.__SFX_COUNT[code] = (window.__SFX_COUNT[code] || 0) + 1;`
**验证**：打几场牌后控制台输入 `__SFX_COUNT`，看到每个音效的调用次数统计。**撤**：删两行。观察点：这两行是「全局对象做累加器」的惯用法——与 [index.html:7624] 的 `__SFX_LOG` 是同一模式，只是从数组换成了字典。

**练习 17：死亡结算页显示「死时共振」。**
在 `showGameOver` 的统计区（[index.html:7455] 的 addStat 金币行之后）加一行（与相邻 addStat 对齐）：
`  addStat(p, '死时共振', C ? C.resonance : 0);`
**验证**：死一场，结算页出现「死时共振 N」。**撤**：删一行。观察点：`C ? ... : 0` 的防御——showGameOver 也可能从事件致死路径进入（[index.html:7403]），那时战斗容器状态不确定；这个防御是你必须写的，不是可写的。

**练习 18：卡面悬停提示加费用。**
改 [index.html:7893] 的 title 拼接，在 flavor 之前插入费用段，整行改成（单行替换）：
`    d.title = [uiCost(card) + ' 费', card.flavor, card.cost_type !== 'none' ? '代价：' + card.cost_text : ''].filter(Boolean).join('\n');`
**验证**：悬停任意卡，第一行是「N 费」。**撤**：原行贴回。观察点：`uiCost` 而非 `card.energy`——必须用现算费用（含层加价），否则显示与实扣不一致（练习 13 刚踩过的坑，这里给出正确姿势）。零费卡显示「0 费」也能接受；想更讲究就 `''.filter(Boolean)` 思路把 0 费滤掉。

**练习 19：加一条自定义组合彩蛋。**
在 `EASTER_EGGS` 表（[index.html:6994]）末尾按现有格式加一项：选两张你喜欢的卡 id（先 grep 确认它们没有被别的彩蛋用过），`line` 写一句你的话，`fx` 先留空函数 `fx: () => {}`（最小可用形态）。**验证**：一回合内先后打出这两张卡，弹出你的台词。**撤**：删一项。观察点：判定在 `checkEasterEggs`（[index.html:7025]）——它是「同回合打出配对」的判定器，读完它你就明白 `fx` 拿到的 `C` 能干什么（改血、加抽牌都行）——彩蛋表是全项目最容易的「给游戏加内容」入口。

**练习 20：警告行加视觉前缀。**
改 [index.html:7935] 的日志行构造，把 `const line = warn ? raw.slice(1) : raw;` 改为（单行替换）：
`    const line = warn ? '⚠ ' + raw.slice(1) : raw;`
**验证**：到第 1 层（no_light）打一张光脉牌，事件栏红字前面出现 ⚠。**撤**：原行贴回。观察点：`raw.slice(1)` 已经剥掉了引擎的 `\u0001` 控制标记（[index.html:7933]），你在剥离之后追加视觉标记——渲染层修饰执行层标记，两层职责分明。

## 九、练习篇特供：你改这里会发生什么

上面 20 题覆盖了三种「会坏」的方式，集中点名以免你撞上才认识：

**会坏显示**（练习 13）：引擎逻辑与界面现算各一份，只改引擎侧则数字对不上——修复姿势是找到界面镜像（uiCost/cardDesc/intentHtml 各管一摊，00 篇第六节检索表可查）一起改。
**会坏节奏**（练习 11、15）：纯数值改动牵动玩家的时机感——这类改动「错了不报错，只是不好玩」，验证只能靠玩。
**会坏持久性**（练习 17 的反面）：往结算页加数据不涉及持久化，安全；但若你想把某个数存进 localStorage（比如最高共振记录），就要套上 try/catch（03 篇第 12 节的纪律）并在 startRun 决定是否读回——持久化让练习从「改一行」升级成「设计一个生命周期」，建议作为第 21 题（自拟）。

## 十一、自拟练习：五道留白的题（21-25 的起点）

二十题做完，真正的毕业考是自己出题。这里给五个方向与最低要求，题目内容由你补全——这是教学包里唯一「没有标准答案」的部分：

**自拟 24：让彩蛋有奖励。** 给练习 19 的彩蛋补上 `fx: (C) => { C.run.hp = Math.min(C.run.maxHp, C.run.hp + 2); }`（参照 [index.html:6996] 的 fire_med）。验证：彩蛋触发的瞬间回 2 血（floatText 不会播——fx 是纯数据结算，想飘字要另学 enqueueAnim，这是 21-25 里最深的一题）。
**自拟 25：读一份你还没读过的函数。** 从 00 篇第五节的检索表里挑一个本篇没碰过的函数（推荐 `applyRelicTurnStart` [index.html:6903] 或 `grantRelic` [index.html:7214]），按 01 篇第八节的格式自己写一张逐行拆表。验证：表里每行都有行号与一句人话。

## 十三、练习故障排查 FAQ

**Q1：改了 json，游戏里完全没变化？**
三层检查：① 跑 `node tools/_t46_wire.js` 了吗（[tools/_t46_wire.js:9] 的正则必须命中 RAW 行）；② 浏览器强刷了吗（Ctrl+F5，普通刷新可能用缓存）；③ 改的文件是 `game/cards/` 下的吗（不是 `docs/content/`——那是导出产物）。

**Q2：改了 index.html，刷新后没生效？**
确认改的是 `web/index.html` 而非 `engine/core.js`（后者页面不加载）；确认保存成功（编辑器标题没有未保存圆点）；确认浏览器没有缓存（强刷）。若改的是 RAW 行内部，注意它是一整行 JSON——一个逗号都会让整页白屏，白屏时按 F12 看 Console 的报错行号。

**Q3：白屏了怎么救？**
看 Console 报错的行号与信息；若是 json 重建后白屏，多半是 json 语法坏了——用 `python -c "import json;json.load(open('cards/diver.json',encoding='utf-8'))"` 快速定位（报错会给行号）；若是手改 RAW 坏的，重跑重建脚本覆盖回来（这就是「产物可以随时重生成」的保险）。

**Q4：练习 17 的 `C` 在结算页一定有值吗？**
`showGameOver` 的三条进入路径（引擎死亡 [index.html:626] 附近、事件致死 [index.html:7403]、`finishCombatFlow` [index.html:7113]）里 C 都已创建，但事件致死时战斗可能未开始（`resolveNode` 事件选项直接扣血致死）——此时 C 是上一场的旧容器或 null。`C ? ... : 0` 不是过度防御，是把「三条路径」的差异吞进一行。

**Q5：能不能把练习做的改动永久保留？**
可以，但记得两件事：引擎侧改动要同步 `engine/core.js`（双份誊抄，00 篇第 4 节）；改动要记进 `TASK_DONE.md` 或自己的笔记——「我改过什么」是这个项目目前没有任何工具追踪的，唯一账本是你自己。

## 十四、收束：练习做完后你在什么位置

二十题加五道自拟题做完，你在这个项目里的位置是：**读**——六篇教学覆盖的函数（引擎 40 + 流程 80 + 地图模块 37 里的常用部分）你都能逐行读懂；**改**——数值、文案、显示、小功能四类改动你都有完整的手感与撤销手段；**没到**——架构级改动（加一个系统、改数据流、删一个大模块）还需要 T340-T343 施工包那样的逐条施工单，那是设计侧与你的下一层接口。

往上走的路也只有一条，和这一夜所有任务的路一样：选一个真实需求，写一份带行号的施工单，改，验证，撤或留。教学包到此交棒。

## 十八、夜里做练习的三条环境建议

第一，**开着两个窗口**：左边编辑器停在你正在改的行，右边浏览器开着游戏与控制台——三个练习档都依赖「改完立刻看见」的反馈回路，来回切窗口的时间会吃掉一半手感。

第二，**每题一个存档点**：动手前把要改的行复制到一个 `练习备份.txt`（一行原行 + 一行题号），做完撤销后也留痕。项目没有版本库，这个文本文件就是你的私人 diff——十二题以上的连续练习后，它是唯一能证明「改了什么」的东西。

第三，**失败两次就翻答案**：验证步骤连续两次与预期不符，回到对应篇的「你改这里会发生什么」看连锁反应——大多数「不生效」都是容器选错（04 篇第 30 节的四容器判断）或双份没同步（00 篇第 4 节）。这条建议与队列规则同构：同一件事不许重试第三次，教学包的练习也适用。
