## 3. 图的加载语义（ART 表用法核对）

- 引用机制唯一：`window.ART = {...79 项...}`（:3941，`assets/art/*.webp` 相对路径，非 data: URI），运行时三处消费——卡面 `art.style.backgroundImage`（:7285）、敌人 `.eart`（:7757）、结算立绘（:7474），职业模态立绘（:6894/:8184）。**全部是渲染到对应内容时才赋背景引用，即按需/懒加载**，首屏不发任何 art 请求。
- 首屏静态 `<img>` 仅 4 张职业卡面（`assets/class/*.webp`，T78 纯卡面选择页）；详情模态立绘是点开才构建（T78 实测 modalInDom=false）。
- **覆盖率**：磁盘 607 个 art 文件中仅 79 个被 ART 表引用；**未引用 528 个 / 39,151,664 B（占 art 字节 95.2%）**——含 evt_*/dive_0059/anm_0041 等卡面与事件图（全文件 grep 0 命中）。它们不影响加载，但占仓库/发布体积。

## 4. 首屏关键路径结论

首屏关键路径 = `web/index.html` 本体 + 4 张职业卡面，**无字体、无外链**：

| 项 | 字节 | 说明 |
|---|---|---|
| index.html | 634,119 | CSS 49.3 KB + JS 574.3 KB（引擎/数据/地图模块全内联） |
| assets/class/*.webp ×4 | 133,110 | 唯一首屏图片请求 |
| **首屏合计** | **767,229（≈ 749 KB）** | |
| 字体 | 0 | 无 @font-face，系统等宽栈（ui-monospace/Consolas） |
| 外链 | 0 | check_web 第 2 段拦截 fetch/XHR/import()/http(s) 资源，当前 0 命中；`<img>` 5 处全站内相对路径（脚本已验证） |

结论：**首屏 ≈ 749 KB，全部本地、自包含，无网络依赖**；单文件 634 KB 主体是内联 JS 数据（卡牌/事件/地图生成器），对本地 file:// 与局域网部署无压力；若上公网，压缩（gzip/brotli）后 JS 数据可压缩比高，预计传输 ~200 KB 量级（推算，未实测）。

## 6. 建议（本次均未实施，不改文件）
