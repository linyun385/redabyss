# T322 · 单调性诊断与方向建议

> T320 说了「分布是什么」，这一篇只回答「为什么单调」。四条诊断各有独立的成因，都在代码与数据里有实物证据；后面给出六个新机制方向，每个都写清落地结构与风险。

## 第一部分：诊断

### 诊断一：卡与敌人之间几乎没有交互，敌人却在单方面玩弄玩家的牌

全池 267 张卡的效果由 12 个顶层键（block/damage/hits/draw/resonance_gain/heal/gaze_cost/resonance_cost/resonance_drain/gaze_gain/target/special）和 14 个 special code 组成（T320 全量清单）。这 26 个键里，**没有一个键读取或改变敌人的意图，没有一个键转移牌的归属，没有一个键延迟生效**。玩家能做的只有三件事：打它、挡它、攒自己的资源。

而敌人那边是另一回事。引擎里敌人的攻击可以按玩家上一回合的出牌数加伤（`mirror`，[engine/core.js:735]）、可以从弃牌堆吃掉一张牌（`drain_discard`，[engine/core.js:739]）、可以从玩家手里偷走一张牌（`steal`，[engine/core.js:777]）。也就是说：**敌人会偷牌、吃牌、读节奏，玩家对此没有任何反制手段**——没有护牌、没有偷回、没有弃牌保护。交互是单向的：只有敌人 interact 玩家。

更基础的一层：敌人意图只有 4 种（`attack` 217 处、`defend` 123 处、`buff` 31 处、`debuff` 20 处， enemies/all.json 全量统计），且轮转方式是固定指针取模（[engine/core.js:695]，`intentIdx % pat.length`）——完全可预测、完全不受玩家影响。可预测性本该催生「针对意图」的玩法（他下回合要打 12，我攒个大的；他要上盾，我挂灼烧），但卡池里没有任何一张卡的效果字段引用意图类型。113 个敌人的 `traits` 字段全部为空数组，这是个埋了没填的钩子。

### 诊断二：状态效果是贴上去的数字，不是体系

玩家能给敌人上的状态一共 4 种：burn（9 张卡）、weak（2 张：dive_0030、cng_0037）、frail（2 张：dive_0022、trem_0034）、poison（1 张：anm_0039）。四种合计 14 卡次，摊在 267 张卡里。更致命的是引擎实现：`applySpecial` 里 `t.status.burn = {v, turns}` 是**直接覆盖**（[engine/core.js:494]）——第二辆烧车不叠加，只重置。trem_0017 再接 trem_0017，第二张的 burn 2×2 直接覆盖第一张。**灼烧卡之间在引擎层就没有协同**，这从数据侧解释了 T321 发现的「灼烧模板 8 张一个模子」：既然叠不上，设计成同一个模子也确实没有损失——引擎先关了门，数据再从门缝溜走。

状态与状态之间也没有转化、扩散、消耗关系。weak 只在敌人攻击时乘 0.75（[engine/core.js:745]），frail 在引擎里甚至**没有结算点**（enemyAct 只处理 weak，frail 的减伤没有实现，trem_0034 挂上 frail 后什么都不会发生）。做了字段的机制，结算没跟上。

### 诊断三：资源名义上有两种，实际只有一条半，还有两种被锁在职业内部

共振与凝视是全游戏唯二有系统级意义的资源：共振跨 10/20/30 阈值触发层模式反应（[engine/core.js:301]，MODE_REACTION 见 [engine/core.js:29]），凝视是跨战斗的全局负债（每 10 点让所有敌人伤害 +10%，[engine/core.js:731]）。但 T320 已证：共振卡 54 张、凝视卡 19 张，疯先知两者皆 0，维护者只做减法。资源语言只有震语者在说，下潜者半懂。

同时引擎里明明还有两种职业内资源没有进入卡池语言：疯先知的**清醒度**（clarity，[engine/core.js:82]，入梦扣、梦中每 3 回合扣，[engine/core.js:246]）和黯民的**零件**（parts，击杀掉落，[engine/core.js:573]；salvageUpgrade 花零件强化手牌 [engine/core.js:859]，dismantle 花零件换遗物 [engine/core.js:876]）。零件只能被两张职业机能消费，卡池 50 张黯民卡没有一张能读写它；清醒度只有切世界一个出口。**引擎养了四个资源，卡池只认两个。**

### 诊断四：每张卡的决策都是「打不打」，没有「什么时候打」

全池没有任何延迟生效结构（无 `delay`/`charge`/`countdown` 键）。时间维度上唯一存在的机制是：special:retain（6 张，回合结束留在手里，[engine/core.js:234]）、cost_type lock（每层一次，[engine/core.js:546]）、cost_type vitality/memory（把「何时打」折算成「付多少」，[engine/core.js:533]）。脉连携是唯一的顺序机制（同回合同脉第 2 张 +1、第 3 张起 +2，[engine/core.js:440]），但它每回合清零（[engine/core.js:263]），且没有一张卡以连携本身为对象——它是一个玩家无法投资的系统。

后果是节奏塌平：敌人意图可预测 + 玩家无延迟工具 + 共振过 30 反而自伤（[engine/core.js:311]）→ 每回合最优解都是「把伤害倾泻干净，挡住算出来的那一刀」。**攒爆发的理由不存在，抓时机的工具不存在。**「什么时候打」这个决策维度在引擎里只对疯先知存在（预兆 3 回合倒计时，[engine/core.js:943]），而预兆是系统随机给的，玩家不能主动布置。

## 第二部分：方向建议

六个方向，全部能用现有 effect 结构的一个新键表达，不推翻任何现有卡。

### 方向一：倒吊（延迟生效）

| 项 | 内容 |
|---|---|
| 一句话规则 | 打出时不立即生效，吊在场上一侧，N 回合后自动结算牌面全部效果。 |
| 解决的诊断 | 诊断四（无「什么时候打」）；顺带救诊断一（倒吊给敌人的回合制造了「未来已定」的预告层）。 |
| 加在哪个职业 | 疯先知。引擎已有 3 回合倒计时的预兆系统（[engine/core.js:943]），倒吊等于把预兆改成玩家可控——技术路径完全现成，且疯先知是机制最平的职业（T320：平均 1.34 种/卡）。 |
| 与共振/凝视怎么咬合 | 倒吊牌每被共振阈值反应推一次（跨 10/20/30），倒计时减 1——红光在催你。凝视≥10 时倒吊效果按 gazeMul 放大，让负债变成杠杆。 |
| 落地形态 | `"effect": {"hang": {"turns": 2, "effect": {"damage": 18, "hits": 1, "target": "all"}}, "target": "self"}`，引擎在 beginTurn 里 tick 悬挂区（参照 tickOmens 的结构）。 |
| 风险 | UI 需要悬挂区展示（现在没有这个面板位）；与预兆的视觉语言要区分开，否则玩家分不清哪个是自己的布置、哪个是系统砸的。 |

### 方向二：听骨（针对意图的反制）

| 项 | 内容 |
|---|---|
| 一句话规则 | 若目标敌人本回合的意图是攻击，这张牌追加结算一次附加效果。 |
| 解决的诊断 | 诊断一（无意图交互）。意图是游戏里信息量最大的公开数据，现在没有任何卡消费它。 |
| 加在哪个职业 | 震语者。听地断脉本就是它的叙事身份（trem_0009「断脉」、trem_0008「问地」都在「听」）；且震语者 10 张 gaze_cost 卡需要更多凝视出口。 |
| 与共振/凝视怎么咬合 | 反制成功时凝视 +1（听得越清，看得越真）——凝视负债从纯惩罚变成震语者主动踩的油门，trem_0055/trem_0066 两张 gaze_gain 卡从此有了体系。 |
| 落地形态 | `"effect": {"damage": 8, "hits": 1, "target": "single", "counter": {"intent": "attack", "effect": {"block": 8, "target": "self"}}}`，applyCardEffect 在伤害结算前查 `e.intent.type`。 |
| 风险 | 反制窗口的表述必须精确（敌人行动发生在回合结束，玩家在行动前打牌，窗口天然成立但要说清）；数值上 counter 效果免费时容易超标，附加效果应低于正常卡。 |

### 方向三：回收（偷取/清除敌人增益）

| 项 | 内容 |
|---|---|
| 一句话规则 | 偷走目标身上的攻击强化，转为自己的力量。 |
| 解决的诊断 | 诊断一 + 诊断二。敌人 buff 31 处意图、buffAtk 无限叠加（[engine/core.js:773]），玩家只能硬吃——这是敌人单向交互最扎眼的一处。 |
| 加在哪个职业 | 维护者。anm_0008「报废清单」、anm_0017「回收协议·总则」、anm_0049 已经在做「把东西收回来登记」的叙事，这是补全主题而非新开主题。 |
| 与共振/凝视怎么咬合 | 回收动作 resonating：偷到 buff 的瞬间自己的共振流失 1（维护者本来就有 3 张 resonance_drain，主题一致：动别人的东西，自己的共振要静一静）。 |
| 落地形态 | `"special": [{"code": "steal_buff", "fallback": {"block": 3}}]`，applySpecial 新 case；无 buff 可偷时走 fallback（写进 json，不靠运行时判断）。 |
| 风险 | 空 fallback 的兜底数值要压低，否则它变成无风险的对精英神器（精英 buff 意图最多）；偷来的力量是永久的，堆叠上限需要定。 |

### 方向四：押牌（把牌本身变成资源）

| 项 | 内容 |
|---|---|
| 一句话规则 | 从抽牌堆顶押 N 张牌面朝下进「押堆」，立即获得共振；本局内特定卡可赎回。 |
| 解决的诊断 | 诊断三（资源只有两种半）。牌库是最被低估的资源：memory 代价在删它、敌人在吃它，玩家却不能主动经营它。 |
| 加在哪个职业 | 震语者。它的 memory 代价卡 10 张（全职业最多）已经在表达「牌=记忆」，押牌是同一命题的主动式。 |
| 与共振/凝视怎么咬合 | 押进去的牌每张折 2 共振（共振的实体化：声音压进了岩层）；赎回卡要求共振归零才能抽回——共振与押堆互为存取，同一次资源有了两个状态。 |
| 落地形态 | `"effect": {"pledge": 2, "target": "self"}`；引擎加 C.pledgePile，赎回键 `"redeem": 1`。 | 
| 风险 | 与 memory 代价形成双重删牌压力时牌库见底极快（押堆不是弃牌堆，不参与洗回），押堆上限要定；UI 需要第三堆的显示位。 |

### 方向五：余震标记（连携的跨回合化）

| 项 | 内容 |
|---|---|
| 一句话规则 | 给敌人挂一个脉标记：接下来 N 回合内，你打出的同脉牌连携计数起点 +1。 |
| 解决的诊断 | 诊断四。连携是现成的顺序机制，但每回合清零、无法投资（[engine/core.js:263]）——标记让「经营连携」从一个被动事实变成可布置的东西。 |
| 加在哪个职业 | 下潜者。它的共振线 14 张攒、只有 4 张花，需要第二种「共振的用法」；下潜者也是 5 脉卡分布最均匀的职业（T320 骨架表），标记给它最不偏科。 |
| 与共振/凝视怎么咬合 | 挂标记时共振 +2；若本回合连携达到 3，标记刷新——共振攒得快，余震挂得久。 |
| 落地形态 | `"special": [{"code": "echo_mark", "vein": "tremor", "turns": 3}]`，veinChainBonus 读取 C.enemies[].echoMarks，起点从 prev+1 改为 prev+1+marks。 |
| 风险 | 连携加成是 ×2 折进伤害的（[engine/core.js:448]），起点 +1 意味着 +2 伤害/格挡，多标记叠加容易失控，封顶必须在 json 里写死；理解成本是六个方向里最高的。 |

### 方向六：供灯（层规则对策）

| 项 | 内容 |
|---|---|
| 一句话规则 | 本回合你的光脉牌视为带着光：断光层不失效、微光层吃加成。 |
| 解决的诊断 | 诊断一的暗面。no_light 层光脉牌整张失效（[engine/core.js:451]），下潜者 24 张光脉卡在第一层是死牌，现在唯一的对策是 share_0001「强行供能」（rule_bypass，全局仅此一张、代价是扣最大生命）。 |
| 加在哪个职业 | 下潜者（光脉卡最多，24 张，受 no_light 影响最大）。 |
| 与共振/凝视怎么咬合 | 供灯烧的是共振：供灯期间共振上限视为 -5，攒不满阈值——光和共振在抢同一份红光。 |
| 落地形态 | `"special": [{"code": "lamp", "turns": 2}]`，applyCardEffect 的 no_light 判断加一条 `C.lampTurns > 0` 豁免（与 ruleBypass 并列，[engine/core.js:451] 处）。 |
| 风险 | 这是对层规则的直接对冲，数量必须极少（2-3 张、rare 起），否则 8 层的环境轮换（core.js LAYERS 表）形同虚设；与 rule_bypass 的语义边界要写清（lamp 只豁免光脉失效，bypass 豁免一切）。 |

### 六个方向的取舍关系

六个方向各自独立，但按解决诊断的覆盖看优先级：诊断四（时机）被方向一、五同时覆盖，诊断一（交互）被方向二、三覆盖，诊断三（资源）被方向四覆盖，诊断一的环境侧被方向六覆盖。若只能先做两个，**方向一（倒吊）与方向二（听骨）性价比最高**：一个复用现成的倒计时结构（tickOmens），一个复用现成的意图数据（e.intent.type），都不需要新的系统状态，json 层面各加一个键即可。

## 决定记录

- 「状态效果」在引擎里的实现分玩家侧（buffs/debuffs，[engine/core.js:161]）与敌人侧（status，[engine/core.js:194]）两套，本篇诊断按「玩家可主动施加的状态」统计。
- frail 无结算点这一条来自代码通读（enemyAct 只结算 weak 的 0.75 系数，frail 无引用），已按「看不懂的代码不许猜」原则标注为「实现未跟上」，而非猜测其意图。
- 方向建议中的 json 结构均为新键设计示意，未改动任何现有文件（本任务禁改 json/代码）；方向一引用了预兆系统的实现位置作为「技术路径现成」的依据。
- 敌人意图的 4 类分布（attack 217 / defend 123 / buff 31 / debuff 20）统计自 `enemies/all.json` 全量 113 个敌人的 `intent_pattern` 字段；JSON 无行号可引，故以文字标注来源，未写 `[文件:行号]` 引用。
