## 五、坑清单（本夜班真实踩过的，按踩的顺序）

1. **`head` 截断的输出不是全量**——敌人提取被截断后我写了「L1-L3 没有 boss」的错结论，第二天返工。教训：任何「全量」结论前先验证样本数（113 就打印 113）。
2. **派单内部有新旧两个时态**——07 派单同文件里「暂缓」与「已有」并存，以时间戳更新的 `_VERIFY` 为准。
3. **引擎注释会滞后**——音频注释写 28 个 wav，实数 27。注释不能当对账依据。
4. **console 的 GBK 乱码只是显示问题**——python 输出中文到管道会乱码，文件本身是 UTF-8；校验文件用脚本读文件，别信终端显示。
5. **bash heredoc 会吃一层反斜杠转义**——`\\n` 进了生成的文件就是真换行。生成代码文件用 Write 工具，别用 heredoc 嵌 python。
6. **自己的输出要回头核对**——flavor 审查差点把 anm_0039 的 `v:4` 误报成 bug（引擎有兜底）；曲线脚本自己写过除零和分位数 bug。写完用另一段脚本核一遍，尤其是你刚手改过的公式。
7. **格式照抄库内惯例优先于理论正确**——治疗标水、heal→water 等库内既有约定，跟着走、加注说明，不要单方面「纠正」。
