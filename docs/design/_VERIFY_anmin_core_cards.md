## 二、第二轮的两个机制（你给的方案）

### 2.1 悬浮体：用「发牌」模拟「留场」

**你的原话**：打出去后有一个战斗内每回合都触发的随机效果，再次打出会再触发一个，直接写成「悬浮体会触发一张能造成那些随机效果的牌」，然后每回合开始自动获得使用此牌。

**实现**：

```
打出 anm_0053
  → C.floatingCount += 1
  → 每回合开始（beginTurn）：
      往手里塞 C.floatingCount 张「悬浮触发」牌
      （0 费、打出去随机给一个效果、不进牌组、战斗结束随 C 消失）
```

打 2 张悬浮体 = 每回合开始手里多 2 张触发牌。这就是你说的「大量随机效果」。

**为什么这个思路好**：绕开了「卡牌留场」这个引擎根本没有的机制。不用处理留场卡被打死、战斗结束去哪、卡面怎么显示一个不在手里的东西。

**两个细节**：
- 触发牌带 `_token: true`。**弃牌堆洗回抽牌堆时会把它过滤掉**，否则会被洗回牌库、越打越多
- 塞牌**不受手牌上限（10）约束**，否则「大量」就被卡死了。但留了个 20 张的硬顶防溢出

### 2.2 子代理：塞进敌方列表的「伪敌方」

**你的原话**：把这个召唤物定成敌方，然后这个召唤物会攻击自己的「队友」，真正的敌方会优先攻击这个「敌方」。

**实现**：

| 你担心的 | 我怎么处理的 |
|---|---|
| 它会不会被当成敌人算胜负 | `checkCombatEnd` 改成只看**非 minion** 的敌人 |
| 玩家全体攻击会不会打到它 | `target:'all'` 的目标列表排除 minion |
| 它自己怎么行动 | `enemyAct` 开头就分叉：minion 找存活的真敌人打，不打玩家 |
| 真敌人打谁 | 攻击循环里先找存活的 minion，有就让它承伤。**贯骨振动（pierce）例外** —— 那是「从骨头里响起来的振动」，挡不住 |
| 威胁等级 / 事件「局部失控」会不会加强它 | 都加了 `!isMinion` 过滤 |
| 它死了会不会掉零件 | `dealToEnemy` 里 minion 死亡直接返回，不给零件、日志写「散架了」 |
| 每回合成长 | `beginTurn` 里：+5 血 +2 攻，扣 1 零件。**零件不够就不长，不消失** |
| 玩家能不能手动选它当攻击目标 | 渲染时 minion 不加 `targetable` 类 |

## 六、已知限制

| 项 | 说明 |
|---|---|
| 子代理只有一种 | 它是「伪敌方」，不是通用单位系统。再设计第二种召唤物要先说明区别 |
| 子代理不吃玩家 buff | 它不在玩家身上，`buffs.strength` 对它无效 |
| 悬浮体触发牌打出去后进弃牌堆 | 带 `_token`，不会洗回牌库，战斗结束随 C 消失 |
| 手牌可能很长 | 5 张悬浮体 = 每回合多 5 张，手牌 15 张。UI 能滚动，但观感需要你试过才知道 |
| `engine/core.js` 未同步 | 它仍是旧副本（`BASE_ENERGY=3`、没有这批新 code）。页面不加载它，但 `tools/sim.js` 会 —— 用它跑模拟看不到这些行为 |
