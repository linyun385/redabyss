## 〇、方法与覆盖面

- **扫描范围**：`docs/design/**` 全部 331 个 `.md` + `cards/*.json` 13 个文件，共 **344 个文件**，全文词频统计（Python 子串计数，非抽样）。
- **判定方法**：先跑候选词对的总频次 → 对疑似冲突的词做**语境抽样**（前后 25–30 字）判定是否真指同一物 → 同义的立条，不同义的排除（排除项也记录在文末）。
- **结论**：立条 15 条。其中 5 条是「孤例对齐」（一个词只出现 1–4 次，对面是压倒性主流叫法），3 条是本夜班产出自身的混用/自创（自首条）。

## 判定清单

### 1. 职业名：维护者 vs 黯民（最重的一条）

- **维护者**：875 次 / 135 文件；**且是引擎 UI 的职业显示名**（`web/index.html` startRun 职业定义 `name: '维护者'`）
- **黯民**：52 次 / 20 文件；是 08 派单的叫法（「四个职业：下潜者/震语者/黯民/苍民」），也是卡池文件名 `anmin` 的中文对应
- 两者**从未以「维护者（黯民）」的配对形式出现过**（该写法 0 次）——两边各说各的。
- **建议**：职业名统一「**维护者**」（UI 既成事实 + 用量 17:1 压倒）。「黯民」不删，定义为**族群名**（维护者这个职业所属的族群），并写进 `glossary.json`。
- **理由**：玩家在界面里看到的、引擎里存的名字是唯一无法「改文档」就能改的既成事实；文档跟着 UI 走，代价最小。

### 2. 职业名：疯先知 vs 苍民

- **疯先知**：UI 职业显示名（同上，`name: '疯先知'`）；**苍民**：49 次 / 17 文件（08 派单叫法）。
- **建议**：与第 1 条同案——职业名「**疯先知**」，「苍民」为族群名。
- **理由**：同上。四职业的 UI 名（下潜者/震语者/疯先知/维护者）全是「角色名」，文档里的「黯民/苍民」全是「族名」——这其实是**一套没写下来的双轨制**，补进 glossary 就化冲突为结构。

### 3. 玩家的牌的集合：卡组 / 牌库 / 牌组 / 卡池

- **卡组**：115 次 / 47 文件；**牌库**：66 次 / 39 文件；**牌组**：12 次 / 10 文件；**卡池**：85 次 / 44 文件。
- 语境抽样证实混用：`CARD_EFFECTS_AUTO.md`「随机删掉**牌库**里的 1 张牌」（引擎 `deleteRandomCard` 实际删 `run.deck`——此处「牌库」=deck）；`class_pick_hint.md`「**牌库**是他们的货架」（此处=可获得的全体=pool）；`DESIGN_TODO.md` 用「牌组本体」。
- **建议**：deck 统一「**卡组**」；可获得的全体统一「**卡池**」；战斗中正在抽的那摞=「**抽牌堆**」（已有 15 次先例）；「牌库」「牌组」两个词废弃，文档迁移。
- **理由**：deck 与 pool 是两个必须分开的概念，现在有四个词、三种语义映射，写作时无法自洽。

### 4. 子代理的机制名：召唤物 / 伪敌方 / 友方单位

- **召唤物**：10 次；**伪敌方**：6 次；**友方单位**：3 次。三词同指（anm_0052 落地的那个单位）。
- **建议**：机制文档统一「**伪敌方**」（`_VERIFY_anmin_core_cards.md` 的实现用语，准确描述它是「塞进敌方列表的己方单位」）；「召唤物」只在泛指这类机制时用；「友方单位」废弃（它暗示通用单位系统，而引擎没有）。
- **理由**：06 铁律之一是「不要再设计第二种召唤物」——「友方单位」这个词会诱导设计者以为有通用系统。

### 5. 凝视值 → 凝视

- **凝视值**：1 次（孤例）；**凝视**：1277 次 / 169 文件。
- **建议**：孤例改「凝视」。
- **理由**：机制名从不带「值/度」后缀（对照：共振 1534 次也无「共振值」）。

### 6. 巡检 → 例检

- **巡检**：1 次（孤例）；**例检**：93 次 / 36 文件（黯民题材核心词）。
- **建议**：孤例改「例检」。
- **理由**：例检是黯民世界观的专属词（例检条款 24 次），巡检是通用词，混入会稀释。

### 7. 层的规矩 → 层规则

- **层的规矩**：4 次；**层规则**：163 次 / 65 文件。
- **建议**：4 处改「层规则」。
- **理由**：主流叫法已定型，孤例是笔误级别的漂移。

### 8. 悬浮体发出来的那张牌：触发牌 / 悬浮触发 / 临时牌

- **触发牌**：9 次；**悬浮触发**：1 次（引擎卡面名就叫「悬浮触发」）；**临时牌**：1 次。
- **建议**：文档统一「**悬浮触发牌**」——用引擎卡面全名，一次说清来源与身份。
- **理由**：三处三个名，新读者无法确认是不是同一个东西；这张牌又是本作唯一的 token，名字值得锁死。

### 9. 工号 vs 编号（建议写分工规则，不合并）

- **工号**：51 次 / 32 文件（工号牌 43 次）；**编号**：84 次 / 37 文件。
- 语境抽样：工号=**活着的员工**的个人标识（anm_0009「料仓认工号」、登记工号牌）；编号=**被系统登记的对象**的序列（anm_0008「七个编号同时注销」、anm_0028「被注销的编号」）。
- **建议**：不合并，把分工写进 `glossary.json`：「工号=在册员工的个人标识；编号=系统登记（含注销）的对象标识，人与物通用」。
- **理由**：两词在黯民文案里承担不同的冷度——工号是「你还算个人」，编号是「你只是条目」。合并会丢这个区分。

### 10. glossary 的精英/巨物组与实际名单漂移

- `glossary.json` 的 `creatures.elite` 组里有「**震耳蝠兽**」「**稳定海红腔豚**」——两者在 `RAW.enemies`（113 只）里**不存在**；实际精英（噬骨菌群/盲眼红腔鱼/气腔洞鼹兽/铁细菌膜母体/辐射金属鳞鳄王/震语苔丛/墟影残片/墟腔/空壳旧光者）里，前两只又**不在** glossary 的 elite 组。
- 同组键名用英文（`normal_d1_d2` / `elite` / `giant`），文档语言用中文（精英 337 次 / Boss 285 次），`giant` 组的四只（穹顶之影/震喉/光蛭母/墟蛹）文档里全部叫 Boss。
- **建议**：glossary 的 elite 组补齐实际 9 只；「震耳蝠兽」「稳定海红腔豚」若未实装，移入一个 `unimplemented`（未实装）组或加注；组名键加中文对照（elite=精英，giant=Boss 或「巨物」，二选一定死）。
- **理由**：glossary 自称「所有命名从这里取」——权威表与实际数据不一致时，新词会被从已废弃的名字里取。

### 11. 渊民 = 统称，未标注

- **渊民**：53 次 / 19 文件。语境抽样（渊民文明/渊民的规矩/渊民采集）显示它是**洞内所有居民的统称**，不指任何单一职业。
- **建议**：在 `glossary.json` 显式写「渊民=统称，不指单一职业/族群」。
- **理由**：它与 苍民/黯民 只差一个字，不标注迟早被当成第五职业或拼错。

### 12. 稳定海 vs 稳定空洞海（低危）

- 层名全称「**稳定空洞海**」30 次；简称「稳定海」在文档里 0 次，只出现在 glossary 复合生物名「稳定海红腔豚」里。

- **理由**：简称只活在权威表里、正文从不出现，属于反向漂移。低危，顺手修。

### 13. 第八层 vs L8（低危）
