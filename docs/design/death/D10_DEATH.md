# D10 · 失败与死亡设计

> 引擎事实：死亡 = run.hp ≤ 0（[engine/core.js:626]）→ showGameOver（[index.html:7441]）统计页（到达层/战斗/击杀/事件/凝视/金币 + runMemoryLine + deathHint [index.html:7079]）→ 重新开始 / 凝视 ≥15 进静默段。**无存档、无继承**——死亡是彻底的（restart 全清）。

## 一、死亡的时刻：现在发生什么

| 步 | 行为 | 行号 |
|---|---|---|
| 1 | run.hp 归零、run.dead = true | [engine/core.js:626]-[engine/core.js:631] |
| 2 | 前端 450ms 后 finishCombatFlow → showGameOver | [index.html:6990]、[index.html:7113] |
| 3 | 统计页：到达层/战斗/击杀/事件/凝视/金币/回忆行/死亡提示 | [index.html:7449]-[index.html:7458] |
| 4 | deathHint 按死因给一句提示 | [index.html:7079]（内容未逐条核） |
| 5 | 凝视 ≥15 → 「进入静默段」按钮 | [index.html:7463] |

## 二、死亡的记忆点（D10 设计：死后留下什么）

| 设计 | 内容 | 引擎落点 |
|---|---|---|
| 死亡地点碑 | 死在哪一层哪一格——下一次开局在同格画一个小记号（「上一次你在这里停下」） | initRun 的 st.region 生成时读上次死亡坐标（redabyss_last_death 存 layer+band） |
| 遗言牌 | 死亡时手里最后一张未打出的牌，下局以「遗言」名义 0 费出现在开局牌库（限 1 张，用完即消） | showGameOver 读 C.hand，取最后一张存 localStorage（新键 redabyss_lastcard） |
| 递增的墓志 | 每次死亡统计页追加一句递进文案（第 1 次「你的血在红光里流尽了」→ 第 5 次「你已经很熟悉这里的红色了」） | showGameOver 按 run.stats.deaths（新计数）选文案 |
| 死因分类 | 被打死/被环境烧死/反噬死（dream）三类，各配不同 deathHint | damagePlayer 的 source 参数已有（[engine/core.js:586]），传到 run.stats.last_death_source |

## 三、挫败感 → 动力的三段转化

| 段 | 玩家状态 | 设计回应 |
|---|---|---|
| 即时 | 「差一点就过」的懊悔 | 结算页的「到达层」数字放大（视觉强化进步）+ deathHint 给一条具体建议（deathHint 已有框架 [index.html:7079]） |
| 短期 | 「再试一次」的冲动 | 静默段入口（现成）+ 遗言牌（新）——两次开局之间有一根线 |
| 长期 | 「我变强了吗」的怀疑 | 死亡地点碑的累积（同一个地方死三次，碑上会叠三层记号——进步可视化）+ 结局收集表的进度感 |

## 四、不要做的

- **不做血量/伤害继承**——T29 §五 的 roguelike 铁律；死亡的资源惩罚就是资源惩罚。
- **不做「复活一次」**——静默段已经是「第二次机会」的实现，加复活会让死亡失去重量。
- **不做负面继承**（下局更难之类）——红渊的敌意来自环境不来自系统报复。

## 决定记录

- 遗言牌是本篇最大的新机制（死亡→下局的唯一物质纽带）——它不破坏 roguelike（不是数值继承），是叙事继承。实现需新键 redabyss_lastcard + startRun 读取逻辑，改动量小。
- 死亡地点碑依赖地图可复现性（?mapseed 或固定序列）——若地图随机则碑是「象征性的」而非「地理性的」，两种都可接受（象征版实现成本更低，先做象征版）。

## 五、静默段（黯星回响）的深化设计

现状：凝视 ≥15 解锁、anmin 职业重开、anminEnemies 池——它是一个「换角色短局」。D10 建议把它的定位从「换角色」升为「死者的余波」：

1. 回响局开头看到一段死者的旅程日志（死因/到达层/手里最后的牌——D10 的遗言牌机制在这里复用）。
2. 回响局结算不按金币——按「替死者多走了几层」，层数记入主周目的死亡地点碑。
3. 回响局里死者的最后一张遗言牌出现在 anmin 的开局牌库里（与主周目的遗言牌机制共用存储键）。

这三条让静默段从「换个角色再打一次」变成「死者的故事还没有结束」——红渊的死亡设计从「终局」变成「回响」。

## 六、deathHint 的三类建议（按死因分类）

deathHint（[index.html:7079]）的现有实现按到达层给通用提示。D10 建议按 damagePlayer 的 source 参数（[engine/core.js:586]）分三类：

| 死因 | 提示方向 |
|---|---|
| 敌人攻击（source = 敌人名） | 「它用的是 X——下次在这一拍交盾/先杀」——具体到敌人 |
| 环境（source = 灼烧/辐射/清剿） | 「这一层的规则不是给你的——对策是 X」——具体到层规则 |
| 反噬（source = 梦的反噬） | 「梦破了。下一次入梦前算清楚 dreamHp」——具体到清醒度经济 |

三类提示的落点都是 damagePlayer 已有的 source 字段——不需要新追踪机制，只需要 showGameOver 读 run.stats.last_death_source（新增）并按值选文案。

## 七、死亡地点碑的实现细节

死亡地点碑的核心是「让你下一次路过同一个地方时看到不同」。实现需要两个数据：死在哪（坐标）、死了几次（计数）。

坐标数据：引擎的战斗容器 C 有 layer 字段（[engine/core.js:151] 附近的 startCombat 初始化）——这就是「你在哪一层」。但地图模块（T56）有更精确的 band 和节点 id（[index.html:8660] 的 initRun 里 st.currentId）——如果要做「格级」精确碑，需要从前端读。两种精度都可以：层级的碑用 LAYERS 表的 name 加上死亡计数（「你在 L5 停下了 · 第 3 次」），格级的碑用 placeName（[index.html:8363] 的地名函数）加方向性描述（「在熔阶焰厅的入口」）。

计数数据：`redabyss_death_L{n}` 或 `redabyss_death_{nodeId}`——localStorage 按位置存计数，每次死亡 +1。读取时机是 startRun 之后的 showMap——地图模块在 [index.html:8918] 的 initRun 里检查 `st.region` 是否已存在，这里可以顺便读 death 计数并标记到节点数据上。

## 八、遗言牌的边界（不是什么）

遗言牌不是「复活卡」——它不能让你在死亡时回到战斗。它是「死亡结算完成后、下一局开始时」的一张纪念牌，出现在牌库里但强度刻意压低（使用时消耗、0 费 0 效果——「遗言」只有叙事价值没有战斗价值）。这样做的目的是确保遗言牌不会改变 roguelike 的平衡——它的功能是让你想起上一次的死法，而不是帮你活过这一次。

遗言牌也不是「永久记忆」——每一局只带一张（最后死时手里最后一张未打出的牌），新的死亡覆盖旧的遗言。你记不住所有的死法，只记得最后一次——这正是 roguelike 死亡设计的本意：每次都是新的。
