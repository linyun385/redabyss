## 字段落位（设计稿 → json 时每段文字去哪）

| 设计稿文字 | json 字段 | 说明 |
|---|---|---|
| 卡名（如「焊渣罐」） | `name` | 与 `name_suffix`（升级后 ·XX）配套 |
| 副标题 20-35 字 | 卡面小字行 / cardDesc 的补充段 | cards 现结构没有独立 subtitle 字段——落进 `cost_text` 位（cost_type=none 时该位为空）或直接并入 `flavor` 首句；**不建议为此加新字段** |
| flavor 单句 | `flavor` | 沿用现池惯例：单句、第一人称或物称、不解释机制 |
| 图鉴三段 | lore 侧（data/lore2 或 glossary 扩展） | 不进 cards json |

## 三条硬规则的自查

1. **不许解释机制**：19 条副标题与 flavor 里没有一条出现「造成 X 点/抽 X 张/持续 X 回合」——数值留在 effect，文字只负责温度。
2. **物称优先**：19 条里 16 条第一主语是物（回声壁/潜望镜/记账机/焊渣罐/香/拳头/链/印章/回执/令纸/指标灯/令卷/泉/石/瓮/钟影），3 条以人形动作开（捧水/翻身/摊开）——物称率 84%，与真池语系一致。
3. **官僚用语密度**：6 条含登记/规程/编号/批文语汇（焊渣罐/静默段结算/废料谐振器/采掘许可证/报废记忆回执/清剿令）——维护者系全部命中，符合四职业叙事分工（T320 骨架表）。

- 副标题不新增 json 字段：并入 flavor 首句或 cost_text 位——「不破坏已有数据」优先于「结构漂亮」。
