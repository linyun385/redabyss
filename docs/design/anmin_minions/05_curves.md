# 05 · 零件经济曲线：收入 / 支出 / 汇率

> 本文只做**纸面推演**，全部数字可回溯到 `cards/anmin.json` 与 `cards_draft.json`。

## 一、基准锚点（全部来自已落地核心卡，不是本批复明的）

| 锚点 | 卡 | 换算 |
|---|---|---|
| 1 能量 ≈ 9 伤 / 7 挡 / 2 抽 | 0002 / 0004 / 0009 | 类内既有基准 |
| 1 零件 ≈ 1 能量 + 1 张牌 | 0056 重铸（0费1零件→抽1+回1能量） | 零件**效率上限**，低频兑现 |
| 永久力量 ≈ 2 零件/点（批量） | 0054 试验（3零件+1费→永久1+3伤）、0061（4零件+2费→2）、0064（6零件+1费→3） | 永久成长**基准价** |
| 弃牌 ≈ 1~2 零件/张 | 0057 换代（1/张）、0059 批量报废（2/张） | 收入端单价带 |

**从锚点推出的三条定价线**（本批新卡全部按线走）：

1. 低档（1 零件）：+2~3 点即时数值，或 +1 张牌。对应 0074（1零件→6伤，0费基准≈4伤）、0075（6挡）、0077（抽3，0费基准 2 张）。
2. 中档（2~3 零件）：一份当轮收益。对应 0076（2零件+1费→15伤）、0079（3零件→本场力量2）、0081（2零件→随机5选1）。
3. 高档（4~6 零件）：持续性收益或战略一击。对应 0078（4零件→双钩子）、0080（5零件+2费→28伤）、0061/0064（永久力量）。

**批量折扣是刻意的**：单点买永久力量（0054）实际约 3.3 零件/点（把 1费和 3 伤补贴折进去），批量买（0061/0064）降到 2 零件/点+小额费。鼓励存钱，不惩罚小额。

## 二、mech_grow 冲突矩阵（本批最大的已知坑，先说清）

引擎实现是**赋值不是累加**（`C.buffs.mechGrow = V`，web/index.html 6025 行）。同一回合打多张带 `mech_grow` 的牌，**只有最后一张的值生效**：

| 同回合打出顺序 | 该回合每张牌产零件 |
|---|---|
| 0051 增生(1) → 0058 加班申报(1) | 1（覆盖无感） |
| 0051 增生(1) → 0060 余量入库(1) | 1（覆盖无感） |
| **0051·Ⅱ(2) → 0058/0060(1)** | **1（被降速）** |
| 0058/0060(1) → 0051·Ⅱ(2) | 2（升速，无损失） |

- 本批的规避：新卡全部 `value:1`，与 0051 基础形态互覆无感；唯一坏 case 是「升级后的 0051·Ⅱ 同回合被 0058/0060 后手压回 1」。
- 彻底解决要动引擎（handler 改累加，或新增 `mech_grow_add`）——列入 `06_needs.md` 引擎侧待确认，本批数据层无法表达「叠加」。

### 单回合极值推演（worst case，纸面）

```
手牌 10 张全收入件的最坏回合：
  0059 批量报废（1费，弃8→+16）
  → 0077 预载料斗（1零件，抽3）
  → 0065 清仓入库（1费，弃4→+4）
  净：-2零件 -2费，+20 零件，本回合没打任何攻击/格挡
```

- 这就是收入上限的形状：**约 10 零件/费**，但整回合零产出。正常构筑收入卡占比 20~30%，折算 **2~3 零件/回合** 是常态。
- 不存在复利循环：零件→牌/能量的每次兑换都要消耗卡位，兑换链两步就断（重铸→料斗这类链路每步净亏 1 卡位）。
- 崩盘假说「存一局零件、最后全换永久力量」：8 场战斗 × 常态 2~3 零件/回合 × 3~4 回合 ≈ 全局收入 60~90 零件，即使一半存下 ≈ 30~45 零件 ≈ **+15~22 永久力量**——这个数字**偏大**，但没有算的机会成本（那些卡位本可以打伤害/格挡，命都未必撑得到第 8 层）。

## 四、为什么「不会崩」目前只是推演（诚实声明）

| 结论 | 状态 |
|---|---|
| 汇率三档互相不套利（零件→能量→数值无复利） | 纸面成立 |
| 收入卡全带能量/卡位机会成本 | 纸面成立 |
| 「+15~22 永久力量/局」是否过强 | **未验证**：需要整局模拟或人工试玩；sim.js 引擎副本过旧，跑不了 |
| 0059/0065 空手代价是否足以制衡爆发收入 | **未验证**：取决于层规则与敌方压力曲线 |
| mech_grow 覆盖问题的实际发生率 | **未验证**：取决于 0051·Ⅱ 与 0058/0060 的同抽率 |

**给维护者的观测指标**（实装后看这三个数就行）：
1. 每场战斗结束的零件结余/（本场收入总量）——结余率长期 >60% 说明收入过剩或支出端没吸引力。
2. 整局结束时 `run.strength` 累计——>15 说明永久线太肥，先砍 0064 的量（6→7 零件）别动单价。
3. 0080/0064 的选取率——高价件没人选说明中档把预算截走了。
