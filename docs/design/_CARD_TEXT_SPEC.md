# T4 · 卡面文案规范 · 2026-11-08 白班

> 方法：从现有 226 张卡抽 20 张做样本（覆盖四个职业 + shared、五种 cost_type、attack/skill/power、特殊码密集卡），逐张对齐三个文本层；再以全池统计校验样本结论。
> 引擎事实：卡面「效果区」文字**不是数据字段，是引擎生成的**——`cardDesc`（web/index.html L8565-8602）从 `effect` 字段 + special 标签表（L8581-8590）拼出；零件代价固定放最前（L8569）。

## 一、三个文本层的分工（归纳自样本 + 全池统计）

| 层 | 来源 | 职责 | 全池覆盖 |
|---|---|---|---|
| **effect_text（效果区）** | 引擎生成（L8565-8602） | **机制事实**：数值、状态、触发、上限。一个字都不叙事 | 226/226 由引擎生成（数据缺字段就缺字） |
| **cost_text（代价区）** | 数据字段 | **代价的体感**：这一下付出去了什么。不解释规则、不复述数值 | vitality 13/13、memory 11/11、lock 11/11、mark 7/7 非空；cost_type=none 时 184 张里仅 4 张非空——全是 part_cost 卡（见下） |
| **flavor（风味区）** | 数据字段 | **机制的情绪意象**：这张卡在世界里是什么。不出现数字、不解释规则 | 226/226 全覆盖 |

三层互斥：机制进效果区、体感进代价区、意象进风味区。任何一层越界都会和另外两层打架。

## 二、各层写法（样本归纳，例句全部出自卡池原文）

### effect_text（引擎生成，设计侧只管数据）

- 只写引擎可结算的字段；玩家读到的每个字都来自 effect + 标签表。
- **新增 special 码必须同步 L8581-8590 标签表**，否则效果区静默漏字。样本实测两处断点：
  - `summon_minion` 无标签 → anm_0052 卡面效果区只显示「零件 -5」，**召唤 10血3攻这件事在卡面上不存在**；
  - `rule_bypass` 无标签 → share_0001 强行供能效果区为空（L8591 `if (!m[s.code]) return;` 直接跳过）。
- 双写会重复显示：dive_0003 曜元 `effect.exhaust` 与 `special:[{code:exhaust}]` 同时存在 → 卡面显示「抽 2　消耗　消耗」。数据二选一。

### cost_text（代价区）

写法：**一句话，代价发生的那一瞬**。主语是身体或物件，不出现规则词汇（「本场」「每回合」「消耗」这类词属于效果区）。

- vitality（最大生命-1）：「签约的手指失去了指纹。」（u_0006）、「你的指尖凉了一下。」（share_0001）
- memory（删一张牌）：「回传清单把你的童年标成了冗余数据。」（dive_0008）、「编号注销。」（anm_0028，短到极致的一种）
- mark（凝视+1）：「光看清了你。你也就被看清了。」（trem_0030）
- lock（本场一次）：「这张牌本场锁死，只能长出这一回。」（anm_0051——**例外**：这张把规则写进了代价区；对照 dive_0058「火漆烧穿了封皮。这一次没有人按住它。」是纯体感写法。两种并存，前者更清楚，后者更有味道）
- **part_cost 卡的第二用法**：cost_type=none 但有 part_cost 时，cost_text 直接写数值「零件 -5」（anm_0052/0053/0055/0056 四张，全池仅有的 none+非空）。注意 cardDesc 也会显示「零件 -N」（L8569）——**同一句在代价区和效果区出现两次**（样本实测 anm_0052 两处都是「零件 -5」）。

### flavor（风味区）

写法：第一人称或冷叙述，一句到两句；意象必须从这张卡的机制里长出来。

- 贴判定/概率：「他可能是坏的。」（u_0017）
- 贴重放：「它不学新打法。它把你刚才最好的那一段，原样再放一遍。」（dive_0085，_TXT_draft_cards.md 稿）
- 贴代价方向：「管子一头插在伤口里，另一头插在你嘴里。」（u_0003，heal=回自己）
- 升级追加 flavor_add 承接原句的意象并推进半步：「第二次按下去，你已经知道要疼多久了。」（share_0001·Ⅱ）；全池 223 张有 upgrade 的卡 **223 张全部有 flavor_add**（无一缺）。
- 禁忌（由反例归纳）：不写具体数字（数字归效果区）；不写操作指导（「配合水牌轮转」这类属于 design_note 的 play_idea）；不复述 cost_text 已说的痛。

## 三、判定表：什么进卡面，什么只能进 design_note

| 内容 | 去处 | 依据 |
|---|---|---|
| 伤害/格挡/抽牌/回血/状态数值 | **effect（结构化字段）** | 引擎生成效果区的唯一来源（L8565-8602） |
| 状态回合数、hits、目标全体 | **effect 的字段**（turns/hits/target） | 同上；标签表已支持显示（L8593-8596） |
| part_cost | **card.part_cost 字段** + cost_text 写「零件 -N」 | 引擎读 card.part_cost（校验 L5822-5823），显示双通道见上 |
| 代价的体感瞬间 | **cost_text**（cost_type≠none 或 part_cost>0 时） | 全池惯例：none 且无 part_cost 一律留空（184-4=180 张全空） |
| 机制的情绪意象 | **flavor** | 全池 226/226 有 flavor，是硬性完整度 |
| 升级后的风味延续 | **upgrade.flavor_add** | 223/223 全覆盖 |
| 升级后的数值/机制变化 | **upgrade.effect**（special 合并语义见 upgradeCard L6655-6679：默认追加，`special_mode:'replace'` 整体替换） | 引擎行为 |
| play_idea（这张卡想让玩家怎么玩） | **只进 design_note** | 指南 §0.2 要求它存在，但它不是卡面文案；写上卡面=教玩家玩游戏 |
| 数值理由 / 上限为什么是这个数 | **只进 design_note** | 卡面出现「因为」「为了防止」= 文案事故 |
| 与其他卡的组合意图 | **只进 design_note** | 组合是涌现的，写死在卡面会锁死玩法（0085×0083 即设计师认可的意外） |
| 拍板口径 / 未实装说明 | **只进 design_note 或 docs** | 卡面只描述已实装行为；引擎对未实装码有红字警告（applySpecial default，L6156-6159） |
| 「永久」「本场」这类时间层措辞 | **效果区语义 + flavor 回避** | §0.1：永久=本场；flavor 不承诺战斗外效果（_TXT_draft_cards.md 校对口径） |

## 四、写新卡时的顺序（从样本流程反推）

1. 先写 effect（引擎可结算的最小集）——卡面效果区自动成立；
2. cost_type / part_cost 定了，cost_text 才动笔（none 且无 part_cost 就留空）；
3. flavor 最后写，从 effect 里挑一个意象，不碰数字；
4. upgrade：数值进 upgrade.effect，意象递进进 flavor_add；
5. 若用了新 special 码：**先在 L8581-8590 加标签，再入池**——否则效果区漏字（本条同时是 T12 引擎审查的输入）。
