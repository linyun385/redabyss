## T-D1 · 污染牌机制设计（未开始，不着急）

**来源**：2026-11-04 用户提出「白板卡是不是用来当污染牌库的代价」。

**已确认的现状**（2026-11-04 核对代码）：
- 全卡池 219 张里只有 `u_0016 越权的批文` 一张白板卡（effect 只有 `target:"self"`），是漏了效果的 bug，不是设计
- 引擎的敌人意图只有四种：`attack` / `defend` / `buff` / `debuff`，**没有往玩家牌组塞牌的能力**
- 要做必须新增机制

**设计维度**（不是选项，是可以同时存在的参数，一张牌可同时占多个格子）：

| 维度 | 取值 |
|---|---|
| 塞进哪 | 抽牌堆（顶 / 底 / 洗入）、弃牌堆、手牌、牌组本体、消耗堆 |
| 谁塞 | 敌方意图、你打出某张牌的代价、事件选项、遗物、升级升歪了 |
| 几张 | 1 张 / N 张 / 随层数递增 |
| 战斗结束 | 清除 / 保留到本局 |
| 能不能打出去 | 能打（付能量清掉）/ 不能打（只能靠弃牌或消耗清） |
| 打出去之后 | 消失 / 回弃牌堆 |
| 有没有副作用 | 纯占位 / 挂着就掉血 / 挂着就涨凝视 |

**关键差异（照搬会不适配）**：
《月圆之夜》的污染牌是塞进牌库，而它**回合结束不弃手牌** —— 污染牌会一直卡在手里，压力逐回合累积。
红渊是**回合结束弃掉手牌**，污染牌会落进弃牌堆，要等洗牌才回来，威胁被稀释。
所以不能直接照搬张数和惩罚强度，得按红渊的洗牌节奏重算。

**另需决定**：污染牌必须单独一个类别（如 `status` / `curse`），**不能放 `shared`** ——
`shared` 是通用奖励池，玩家通关会抽到，等于凭空塞废牌，会被当成 bug 而不是设计。

## T-D2 · 与同类卡牌游戏对账（等 T-D1 基本设计做完再做）

**用户原话**：「等我做完基本的设计后和相似实现的卡牌游戏对对账就好，对完了改就行」。

**为什么列这条**：
用户自己意识到风险 —— 「我确实有可能受到印象的影响自动的把某张别的游戏的实现当成自己的想法」。
机制撞车在卡牌游戏里几乎不可避免，真正要防的是**数值曲线、触发条件、文案气质整套一起端过来**。

**做法**（对账时用）：
1. 先把自己写的设计定稿，**再看**别人怎么做的（顺序不能反，否则会被带着走）
2. 逐条比对：机制是不是同一个、数值量级是不是一样、触发条件和限制是不是一样
3. 只改「撞得太像」的部分，不改「本来就该一样」的部分（比如「造成伤害」不是抄）
4. 改完在对应设计文档里留一行来源说明

**已知的外部参考**（用户回忆，不精确，仅供参考）：
- 《月圆之夜》：污染牌塞牌库；回合结束不弃手牌；有能量 / 行动力 / 随便打的卡等多个维度

**注意**：用户明确说「具体的东西我肯定记不清了」，所以对照时以实际查到的为准，不要拿这些回忆当定论。

## T-D3 · 底层机制差异化（用户 2026-11-04 提出，未开始）

**用户原话**：「这里我们的设计其实很类似杀戮尖塔，这块才是要考虑的地方，到时候我可能要创新一下底层机制。」

**先分清两种相似**（否则会把不该改的也改掉）：

*品类通用语 —— 不算抄，改了反而不好玩*
能量费用、抽牌堆 / 弃牌堆 / 消耗堆、格挡、回合结束弃手牌、格挡回合清零、
力量 / 敏捷、虚弱 / 脆弱 / 中毒 / 灼烧、遗物、地图分岔、篝火升级。

*真抄 —— 要防的是这个*
照搬某张牌的效果组合与数值、照搬某个遗物、照搬敌人意图的固定序列。

**红渊已经有的差异化**（核对代码确认，都不是抄的）：

| 机制 | 在哪 | 尖塔有吗 |
|---|---|---|
| 属性脉连携（同脉连打：第2张+1、第3张起+2，再 ×2 进效果） | `veinChainBonus` 5787 | 没有（尖塔的连击是单卡概念，这里是牌流） |
| 凝视（负资源，越积越被盯上，和正资源对冲） | `run.gaze` / `addGaze` | 没有 |
| 共振（第二资源，可被锁定 `resonanceLock`） | `C.resonance` | 没有 |
| 梦 / 醒双抽牌堆（部分牌只在梦里可用） | `pileWake` / `pileDream` 5565 | 没有 |
| 层规则（整层禁某脉 / 强化某脉） | `layer.rule: no_light / bright` | 没有（尖塔只有单点诅咒，无整层规则） |
| 职业专属资源（维护者零件+协议、疯先知梦境） | `C.parts` / 职业分支 | 没有 |

**判断框架（不是结论，是给用户拍板用的）**：
- 框架相似不是问题，问题是有没有**别人没有的核心循环**
- 五个差异化里，脉连携 / 凝视 / 层规则这三个能撑起完整的 build 方向，另两个偏辅助
- 真要创新，优先考虑这三者的**交叉**（例如：凝视反过来影响层规则的松紧、脉连携被凝视打断），
  而不是另起一套框架 —— 另起框架等于把已经做好的差异化扔掉

**待用户决定**：创新落在哪个机制上，定了再展开设计。

## T-D4 · 脉象系统（2026-11-04 讨论三轮，方案未定稿）

**用户要做的事**：把「不在本块生态就无法使用该脉牌」的二元开关，改成**脉象等级**（0~N）。

### 用户已明确的规则

- 脉象是属性，在相关生态中或打特定牌时**积累**
- 离开生态**不能积累**（但不下降）
- **某些生态中会下降**
- 每级有不同效果：伤害增加、代价减免、按层级使用不同能力的牌
- 会配「脉象转换」类核心卡 —— 一局里玩多种脉象

### 结构方案（用户第三轮拍定）

| 放哪 | 放什么 |
|---|---|
| **通用池** | 各脉的**配套牌**，所有角色都能用，**不放核心卡** |
| **角色池** | 各脉的**核心卡**，每个角色的**各不相同**（维护者的矿核心 ≠ 疯先知的矿核心） |
| **角色技能 + 初始卡** | 职业分量的主要来源，不占奖励池 |

用户认为：“成型快”的差异化要做成**可感知的特色**（该脉在该角色手里有独有表现），不是同一套牌加速。

### 已核实的引擎现状

- `veinChainBonus`（5787）现在是**本场战斗内该脉累计打出次数**，只增不减，从不重置（不是“连击”）
- 第 1 张 ×0，第 2 张 +1，第 3 张起 +2（封顶），连携加成进 block/damage 前 ×2
- 层规则 `no_light` 是**整张牌失效**，`bright` 是光脉 +2 —— 都是二元开关
- 可以复用 `veinChain` 改造成脉象，不必另建一套

### 卡住的真问题：薄脉撑不起核心卡

| 角色 | 最薄的脉 | 张数 |
|---|---|---|
| 维护者 | 热 | 2 |
| 下潜者 | 水 | 2 |
| 疯先知 | 震 | 3 |
| 震语者 | 水 | 4 |

最厚的脉 19~23 张，最薄 2 张，差 10 倍。核心卡没有配套牌就是废纸。

### 两个走法（待用户选）

**A. 补约 60 张脉牌**，实现真正的「任意角色任意脉」
成本最高，要一到两周，期间其他事全停。

**B. 每个角色只做 3 条脉的核心**（它本来厚的那些），另 2 脉只有通用散件
工作量约 30 张。强脉能成型，弱脉能打但不成型。
**推荐这个** —— 能先跑起来验证「同脉不同角色」到底有不有趣，而不是写到第 40 张才发现问题。

### 设计约束（必须写进任务书）

**通用池的配套牌不许假设任何核心机制。**
只提供中性的东西：脉标记、数值、简单条件。
凡带「配合某核心」的，一律放角色池。否则同一张通用牌对某个角色就是废牌。
