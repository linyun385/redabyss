# P01 · 伤害与受击的反馈序列

## 现状
出牌→扣血→飘字→敌人闪红。序列=1 拍：`doPlay` 内同步调 `dealToEnemy`（core.js），`render()` 刷新血条，`floatText()` 产生飘字（animation 0.4s），`.hitflash`（0.12s）。震屏 `body.shake`（0.22s）在玩家受伤时触发。
无中间拍。卡牌飞出动画 `.ghost-fly`（0.22s）与伤害飘字**同时**发生。

## 玩家在这里会遇到什么
打出一张 10 伤的牌 → 卡飞出 + 敌人血条同步跳 + 飘字 + 闪红，四件事同时发生。玩家不知道哪个数字对应哪个敌人（多敌时尤其）。

## 方案
- **A 两拍**：卡飞出（0.22s）→ 伤害数字+血条变化（0.3s）。优点=因果清晰；缺点=多敌连打会排队。
- **B 保持一拍但分层 z-index**：卡飞出 z-40 在下、飘字 z-50 在上、闪红 z-5 在下——用空间层替时间层。零改动成本。
- **C 按目标分批**：多敌时逐个 target 串行 0.15s 间隔。优点=清晰；缺点=改动 doPlay 循环逻辑（引擎侧）。

## 推荐
**B**。不改引擎，只调 CSS z-index 与 animation-delay。具体：`.float { animation-delay: .15s }` 让飘字比卡飞出晚 0.15s——玩家先看到卡飞出，再看到数字。一行 CSS。

## 落地成本
CSS 1 行。无引擎改动。
