## 0 · 计算前提（全局基线）

| # | 前提 | 值 | 依据 |
|---|---|---|---|
| B1 | 全局盒模型 | `box-sizing: border-box` | `:16 *{box-sizing:border-box}`；故本表所有 `width`/`height` 均含 padding 与 border |
| B2 | 基准字号 / 行高 | 14px / 1.5（无量纲）→ 21px 行盒 | `:22 body{font-size:14px}`、`:23 line-height:1.5`；无量纲行高随该元素自身字号缩放 |
| B3 | 内容梁宽度 | `--lane: 1240px` | `:41 :root{--lane:1240px}`；被 `:35`、`:43`、`:329` 三处 `max-width` 引用 |

| B5 | 三屏切换 | `.hidden{display:none !important}` + `showScreen()` 移除 `.hidden` | `:27`、JS `:6516–6519`；同一时刻只有 1 个 screen 参与 flex 高度分配 |
| B6 | **无宽度断点** | 全文 `@media` 仅 1 条：`(prefers-reduced-motion: reduce)` | `:517–524`；**不含任何宽度/分辨率条件** |

> **B6 的直接结论**：两种视口下**没有任何字号发生变化**。字号差异只可能来自 B7 的 `body.style.fontSize` 交互，不来自视口。
> **B7（字号缩放交互）**：`fontbtns` 点击后 `document.body.style.fontSize = s + '%'`（JS `:8376` / `:8381`，s∈[80,150]，步长 10 见 `:8374`/`:8379`）。百分比基准是 `html` 的 font-size，而 `html` 在 `:17` 只声明了 `height:100%`、**无 font-size** → 基准取 UA 初始值 `medium`，**具体 px 未验证（代码不可定）**；因此 s=100 不等于 14px。且本表所有显式 `px` 字号（`:44`、`:196`、`:232` 等）不随该内联样式变化。

**「未验证」的统一口径**：宽度或高度由文本内容行数 / 子元素数量 / flex 剩余空间 / JS 注入值决定，而 CSS 未给定值时，写「未验证：<原因>」；只给可确定的下限/上限与算式，不把算式当实测值。

### 存疑声明（`font: …px/… inherit`）

`#hud-mapbtn` `:709`、`#btn-fullmap` `:725`、`#fm-zbar button` `:795` 三处写的是 `font: 12px/1.4 inherit`。
`inherit` 是 CSS-wide 关键字，按 CSS 规范不能作为 `font` 简写的分量（`font-family` 需为 `<family-name>`/`<generic-family>`），该声明整体应被丢弃；若如此，这三个按钮的字号回落到 UA 默认值（`<button>` 无 `font:inherit` 全局规则，见 `:471`）。
→ **代码有、运行时不保证**。本节按「声明值 12px」计入低于线；**实际运行时字号未验证（未开浏览器）**。这一条同时是 X2「用了但可能无效」类问题的旁证，但本篇不越界做变量清点。

## 边界声明

- 我没开浏览器，所有尺寸是**按 CSS 算的**，不是实际渲染值。
- CSS 优先级打架时，写了也未必生效；这类标「代码有、运行时不保证」（本篇涉及 `:709`/`:725`/`:795` 三处 `font` 简写、JS 内联覆盖 `:8595–8596`、主题覆盖 `:281`/`:534`/`:670` 等处仅改颜色不改尺寸）。
- 主题：`<html data-theme="C">`（`:2`），B/C/A 主题覆盖规则（`:536–605`、`:670–673`）**只改颜色，不改任何宽高/字号**，故不影响本篇数值。
- 本篇仅新增 `docs/design/ui/x1_sizes.md`，未修改 `web/`、`engine/`、`cards/*.json` 或任何源文件。
- 复算方式：所有 `vw/vh` 按 1280×720 / 1920×1080 代入；`min()`、`calc()`、百分比按 CSS 声明顺序展开；`box-sizing:border-box`（`:16`）贯穿全部宽高计算。
