## 四、已知风险（按概率排序，超过这五条的不太可能发生）

1. **改 json 手滑（逗号/引号）→ 游戏白屏**。概率最高。自救：`python -c "import json;json.load(open('cards/diver.json',encoding='utf-8'))"` 会告诉你坏在哪一行；或用备份 *.bak-20261104 覆盖回去。
2. **忘了跑重建脚本 → 改动「不生效」**。json 是真源、网页读的是拼好的副本——跑了 `_t46_wire.js` 才算数。症状：怎么刷新卡面都是旧的。
3. **删卡后美术账本出现孤儿记录**（58 张卡的图与文案登记还在）——无害，游戏不读它们；看着烦的话按 T340 §四.5 重导出，属于洁癖项不是错误项。
4. **通用牌强度失控**（尤其 u_0016 越权的批文：清剿协议是全场自伤+双方加攻的高压开关）。游戏不会崩，但可能「太容易/太难」——平衡结论要等模拟器修好建模缺口之后才有数字（docs/BALANCE_T29.md 第六节），先靠玩感判断。
5. **两份引擎副本不同步**（若有人顺手改了 engine/core.js 或网页里内联的那份）——症状：游戏行为与模拟器结果不一致。本施工包不需要动引擎，出现此症状说明动了别的，回滚即可。
