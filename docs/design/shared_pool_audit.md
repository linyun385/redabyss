# T416 · 通用池 11 张逐张审查

> 审查判据（T400 通用池设计约束 + §2.1）：
> 1. **换到别的角色手里还能用 → 通用池；只有某个角色用才有意义 → 角色池**（方案 C：通用池不放核心卡）
> 2. 通用牌**不许假设任何具体核心机制**，只提供中性脉标记、数值、简单条件
> 3. §2.1 通用判据：遮住脉名能猜出脉吗；效果能否挂在别的脉上
> 数据源：`cards/shared.json`（11 张）。无数字结论，无脚本复算。

## 汇总

- **通用性全部成立**：11 张里没有一张「只有某个角色用才有意义」——方案 C 的红线（通用池不放核心、不许假设核心机制）目前没有被违反。
- `core: true` 字段检查：11 张里 **0 张**带 core 标记——与「核心卡放角色池」的方案 C 完全一致。
- **脉标签是通用池的主要瑕疵**：5 张带脉标签的卡里 4 张的标签按 §2.1 读不出对应味道（u_0007/u_0009/u_0011/u_0013，u_0012 边缘）——通用池的脉标签当前更像「贴上去的分类」，不是味道声明。这与 T406 的全池发现一致，在通用池里尤其明显（因为它本来就该是中性的）。
- **无脉 4 张**（share_0001/u_0003/u_0006/u_0016）：T400 目标「无脉压到 0~1」——u_0003/u_0006 在 T408 里已有归矿建议；u_0016 效果为空待确认；share_0001 保持无脉合理。
- **u_0016 的呈现是通用池唯一硬伤**：机制（purge 协议点火）生效且通用，但 effect 字段空 → 卡面零描述 + rare 位。修呈现不修机制。

## 与 T400 补牌计划的衔接

T400 通用池账：光 3→7、水 1→7、热 2→7、震 4→7、矿 2→7（要补约 23 张）。按本审查：现有 11 张的「通用性」没问题，补牌时只需要保证**新牌的脉标签真的长那条脉的味道**（现有 4 张标签瑕疵卡就是反例教材）；「无脉压到 0~1」的重心是把 u_0003/u_0006 挪走或给脉、处理 u_0016。
