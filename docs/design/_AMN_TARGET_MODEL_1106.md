# 维护者 · 目标模型改造 + 子代理可 buff（2026-11-06 上午）

> 压缩前落盘。本文是「维护者附属卡重做」的地基记录。

## 一、用户定下的三条设计核心（原话转述）

1. **零件换取战斗外成长**（最大生命等）
2. **卡牌消耗零件，局内产生效果**（伤害、回复、抽牌等）
3. **围绕核心卡设计，但卡牌本身要有效**

补充三条（当天后续）：
- 普通给角色上 buff 的卡，**应该能直接给子代理上 buff**（不是另开一套卡）
- 数值给得太慷慨，体感上「完全没有难度」
- GLM 的 24 张附属卡有机制重复（0059 vs 核心 0057）、辅助卡效率超过核心卡（永久力量）的问题

## 二、引擎改造：统一目标模型（已完成，实测 56/56）

### 目标分类

| `target` | 落到谁 |
|---|---|
| `self` | **玩家 + 场上所有存活子代理**（2026-11-06 用户定：子代理是身体的延伸） |
| `ally` | 一个友方（选到子代理就给它，选不到回落到自己） |
| `all_ally` | 玩家 + 所有存活子代理（与 `self` 当前行为一致） |
| `single` | 一个敌人 |
| `all` | 全体敌人（**不含**子代理） |

### 关键实现

```js
// web/index.html · resolveTargets(C, e, targetIdx)
// 增益落到目标：'self' → 玩家 buffs；子代理 → 它自己的字段
// 力量→攻击力，再生→每回合回血，荆棘→反伤；敏捷对子代理无意义，静默忽略
function applyBuff(C, tg, code, V) { ... }
```

- 增益类（strength / dexterity / regenerate / thorns）从「硬编码写到 `C.buffs`」改成**走目标**
- 负面状态（burn / poison / weak / frail）加了 `!t.isMinion`，不会误伤自己的造物
- `heal` 也走目标（`healOne`：'self' 是玩家，其余是子代理）
- 子代理数据结构新增 `regen` / `thorns` 字段，回合开始结算再生，被攻击时反伤

### 验证

| 测试 | 结果 |
|---|---|
| `tools/_test_anmin_core.js` | **56 通过 / 0 失败** |
| `tools/_test_minion_support.js` | **12 通过 / 0 失败** |
| `tools/check_web.js` | 7 段 script 全可解析，0 警告 |

关键断言：
- `target:self` 的普通 buff 卡 → 玩家 +2 力量、**子代理攻击 5→7**
- `target:ally` → 只给选中的子代理，玩家没动
- `all_ally` → 两边都有再生，子代理回合开始真的回血
- 荆棘 → 敌人打子代理被反伤 4

## 四、数值基准（实测算出，重做时按这个）

```
全池 219 张：伤害 7.2/费，格挡 6.0/费（中位数）
黯民池：伤害 7.5/费，格挡 6.0/费
```

### GLM 那 24 张的诊断

**花零件的卡其实偏贵**（按 1 零件 = 1 能量折算）：
- 0080 原型机点火：等价费 7 换 28 伤 = 4.0/费（低 44%）
- 0076 液压猛冲：等价费 3 换 15 伤 = 5.0/费（低 30%）
- 0074 快换钻头：等价费 1 换 6 伤 = 6.0/费（低 17%）

**慷慨的是 8 张不花零件的纯数值牌**——主效果按基准给，再白送一个副效果：
- 0066 外挂装甲：6 挡（正好基准）+ 白送荆棘 2
- 0070 双层甲板：7 挡（超 17%）+ 白送保留
- 0071 主承重结构：16 挡/2 费 = 8.0/费（超 33%）
- 0069 循环液补给：抽 1（值 1 费）+ 白送回 5 血
- 0073 液压助力：5 挡 + 白送敏捷 2

**结论：慷慨的根源不是数值超模，是「一张牌当一张半用」。**
