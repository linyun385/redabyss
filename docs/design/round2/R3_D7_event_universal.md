# R3-D7 · 事件分支与通用牌的联动

> 第一轮 D7 给 16 个事件加了分支；第一轮 T341 设计了 17 张通用牌；T333 提出了 card_reward=universal 的改法。这一轮把三者串起来：**每个事件的 universal 分支最应该给哪张通用牌**。

## 联动的实现

上表的「最适配」不是硬编码——它是设计建议。实现方式有两种：

1. **事件 json 的 result 加 card_id 字段**：`"result": {"card_id": "u_0002", "card_reward": "universal"}`——指定给哪张而不是随机抽。引擎改动：chooseEventOption 读 card_id 直取（[index.html:7401] 附近）。改动量小但降低了事件的随机性。
2. **事件的 result 加 card_pool 字段**：`"result": {"card_pool": ["u_0002", "u_0003"], "card_reward": "universal"}`——从指定池随机抽。改动量更小（只需在 cardsOfRarity 加一个池过滤），保留了随机性。

建议用方案 2——保留随机性但约束范围，与 T333 的改法一（card_reward 增加新值）兼容。

## 决定记录

- 「最适配」的判断依据是「层的规则 × 牌的机制 × 玩家在此层的需求」三方交叉——不是客观最优解而是设计推荐。
- 16 个事件只覆盖了 17 张通用牌中的 16 张（u_0014 共鸣腔未分配——它是 rare 且效果是系统级改写，不适合作为事件奖励）。共鸣腔的正确获取路径是商店 rare 位。

## 16 个事件的层位覆盖分析

16 个事件覆盖了全部 8 层（每层 2 个）——但它们只覆盖了 17 张通用牌中的 16 张（u_0014 共鸣腔未分配）。这个覆盖密度意味着：**在一局正常的 8 层游戏中，玩家会经过 16 个事件节点，每个节点都有机会获得一张「层适配」的通用牌**——但概率上不是每个事件都会给 universal（T333 的改法是 card_reward 增加新值，不是把所有事件都改成给通用牌）。

实际期望：如果 16 个事件中只有 30% 走 universal 分支（约 5 个），玩家在一局中会通过事件获得 2-5 张通用牌——加上商店获取，总数在 3-8 张之间。这个数量足够支撑 R2-D1 分析的三种三卡组合原型。

## 层适配的设计逻辑

「最适配」的判断不是随意的——它遵循三条规则：

规则一：**层的资源压力决定通用牌的用途**。L1 的压力是「光脉牌不能用」（no_light），所以给无脉的守夜人的钟；L5 的压力是「环境在磨血」（heat_tick），所以给有回复的活水引泉；L7 的压力是「手牌在被烧」（burn_hand），所以给有保留机制的钟（第二张）。

规则二：**层的敌人构成决定通用牌的针对方向**。L4 的红腔鱼群是三只同场（AoE 价值高），所以给散落的铅字；L5 的精英是三拍复合攻击（需要全机制应对），所以给减压舱（万能解）。

规则三：**层的位置决定通用牌的稀有度容忍**。L1-L2 的新手不应该拿到 rare（太强的牌破坏学习曲线），所以 L1-L2 的事件分给 common/uncommon 的通用牌；L6-L8 的老手可以拿 rare（他们已经理解了游戏），所以 L6-L8 的事件分给 rare 的通用牌。

## 分层适配的期望获取路径

| 层 | universal 事件的期望产出 | 累计通用牌 |
|---|---|---|
| L1 | u_0002 或 u_0006（common） | 1 |
| L2 | u_0003 或 u_0007（uncommon） | 1-2 |
| L3 | u_0009 或 u_0010（uncommon） | 2-3 |
| L4 | u_0012 或 u_0013（uncommon/rare） | 2-4 |
| L5 | u_0011 或 u_0016（uncommon/rare） | 3-5 |
| L6 | u_0004 或 u_0005（common/uncommon） | 3-5 |
| L7 | u_0002（第二张）或 u_0017（rare） | 4-6 |
| L8 | u_0001 或 u_0003（第二张） | 4-6 |

这条路径的核心是「从生存到构筑到体系」：L1-L2 给生存工具，L3-L4 给构筑积木，L5-L6 给体系零件，L7-L8 给终结手段。
