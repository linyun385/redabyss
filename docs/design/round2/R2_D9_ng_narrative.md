# R2-D9 · 多周目的叙事弧线

> 第一轮（D9）拆了每个结局的机制与继承；这一轮问：**四个结局连起来读，是什么故事？**——多周目不是「同一个游戏打四遍」，是「一个故事的四种讲法」。

## 四结局的叙事序（不是游玩序）

| 叙事序 | 结局 | 故事线 |
|---|---|---|
| 第一讲 | 背身 | 「我进去看了一眼，退出来了。不敢回头。」——红渊第一次遇见你，你选择了逃。 |
| 第二讲 | 同行 | 「我走完了。红光跟着我。我没死也没变成它。」——你第二次进去，这次走完了全程，什么也没发生。 |
| 第三讲 | 回头 | 「我到了最底下。我放弃了一切，走了回来。」——你到了终点却选择放手——这是「同行」的否定：不是不够强，是不想要。 |
| 第四讲 | 长审 | 「我一直在看它。它也一直在看我。最后我们分不开了。」——你终于不躲了。你不走了。你和红渊融在了一起。 |

这个叙事序的逻辑是「渐进的卷入」：逃 → 走完 → 放下 → 融入。每一步都是玩家对红渊的态度的深化——从恐惧到接受到放手到合一。

## 游玩序 vs 叙事序

玩家的实际游玩顺序大概率不是叙事序——他们可能先拿到长审（因为凝视是最容易无意识积累的资源），再拿到同行（默认），再回头（主动选择），最后刻意走背身（需要全程控制凝视 ≤5）。

这个「游玩序 ≠ 叙事序」不是设计缺陷——它意味着**每个玩家自己拼出故事的方式是独一无二的**。两个人都打了四局、拿到四个结局，但先后顺序不同 = 他们的红渊故事不同。这是「多周目叙事」最高级的形态：不是预设一条线让玩家走，是给四块拼图让玩家自己拼。

## 多周目继承的叙事层

| 继承 | 叙事含义 |
|---|---|
| dive_0056 死亡合同（增补条款） | 「签过一次，第二次签得更熟练」——你跟红渊的关系有了历史 |
| 凝视初始值 +3（D9 建议：长审后） | 红渊记得你——「你已经被看过」是长审的余波 |
| maxHp +10（D9 建议：回头后） | 「放过一切的人身体记得」——回头的代价变成了铠甲 |
| 事件记忆（redabyss_evlog） | 「上一次你选了 X」——红渊的记性比你好 |

这四层继承合起来讲的是：**红渊在学你，你也在学它**。每一周目不是重置，是关系的深化。


## 多周目的「关系深化」设计

D9 的多周目建议（凝视初始值/概率修正/事件记忆）共同讲一个故事：**红渊在学你，你也在学它**。这个故事不是通过追加剧情文本讲的——是通过游戏机制的微调讲的。

| 二周目机制 | 玩家感受到的 | 红渊「学会」了什么 |
|---|---|---|
| 长审后凝视 +3 | 「开局就不一样了」 | 红渊记得你——它在你来之前就开始看 |
| 背身后 gift -50% | 「敌人不送东西了」 | 红渊知道你不喜欢被看——它学会了克制 |
| 回头后 maxHp +10 | 「血变多了但牌变少了」 | 放过一切的人身体变厚了——但手上少了工具 |
| 事件记忆 | 「它记得我上次选了什么」 | 红渊的记性比你想象的好 |

四条机制的共同点是：**它们都让红渊「更像一个角色」而不是「更像一个系统」**。标准 roguelike 的多周目继承是数值系统（+伤害/+血量/+金币），红渊的多周目继承是关系系统（记得/克制/变厚/留痕）——这不是更好的设计或更差的设计，是不同的设计：它把 roguelike 的「重复游玩」从「变强再打」变成「关系加深再走」。

## 四结局连读的一个隐藏发现

把四个结局的文案并排读，会发现一个统一的第一人称叙事结构：

| 结局 | 第一句 | 最后一句 |
|---|---|---|
| 长审 | 你停下来。 | 你就站在那里，被看成了它的一部分。 |
| 背身 | 谐振器没有声音。 | 你没有回头。回头的人要留下来解释。 |
| 同行 | 谐振器没有声音。 | 下面没有更深的层了。你还是往下迈了一步。 |
| 回头 | 放弃带走的一切，原路回去。 | （引擎无独立文案，markCleared 只记录） |

四个结局的叙事重量不均匀——长审、背身、同行有完整的文案段（[engine/core.js:831]-[engine/core.js:843]），回头只有一个按钮标题。D9 建议给回头补一段与前三者等长的文案——这是四个结局中唯一缺文案的那个，也是「多周目叙事弧线」上唯一没有闭合的环。


## 多周目的「红渊视角」

D9 的四条二周目建议全部从玩家视角出发——这一节从红渊的视角重新审视。

红渊在多周目中做了什么？从引擎的角度看：它记住了你通关过（markCleared）、记住了你拿到过哪些结局（redabyss_endings）、记住了你死过多少次（D10 的死亡计数）——这些记忆全部存储在 localStorage 里，不在游戏逻辑里。

也就是说：**红渊的「记忆」是浏览器的存储，不是游戏世界的状态**。你第二次开局时，游戏世界是完全一样的（同一批敌人、同一张地图结构、同一套层规则）——变化的是「你带了什么进来」（dive_0056、不同的凝视初始值）。

这意味着红渊的「学你」不是真的在学习——它是**一个不会变的世界在对照一个会变的人**。红渊从来没有变过，变的是你对它的理解和它对你的标记。这个发现的叙事含义是：多周目不是「红渊在进化」，是「你在进化，而红渊是最好的镜子」。

这个发现也解决了 D9 第一轮的一个悬而未决的问题：「红渊在学你」的机制设计（凝视 +3 / gift -50%）到底是不是在「改变红渊」？答案是：不是——它改变的是**你进入红渊时的状态**（初始凝视、遭遇概率），红渊本身永远不变。这就是为什么引擎的 newRun 每次都创建全新的战斗容器（[index.html:5512]），而 LAYERS 表和敌人定义永远从同一份 json 读取。

## 多周目叙事的三个层级

| 层级 | 内容 | 实现 |
|---|---|---|
| 机制层 | 凝视初始值/概率修正/开局牌变化 | newRun 的条件分支 |
| 文本层 | 事件记忆/死亡文案递进/结局收集 | localStorage + showGameOver 的文案选择 |
| 世界观层 | 红渊是镜子不是对手——它不变，你变 | 不需要实现——这是玩家自己构建的理解 |

三个层级中，世界观层是唯一不需要代码的——它从机制层和文本层自然涌现。这也是「多周目叙事」的最高境界：**不是你写了故事让玩家读，是玩家在你的机制里自己找到了故事**。

## 决定记录

- 叙事序「背身→同行→回头→长审」是本篇的分析工具——不要求玩家按此顺序游玩。
- 「红渊在学你」的多周目叙事定位与引擎的 markCleared + endings 收集表设计吻合——引擎已经在记录「你和红渊的关系史」，D9 只是把这件事从数据层提升到叙事层。

## 补充：回头结局的文案建议

回头是目前唯一没有完整叙事文案的结局——它的「叙事」只有一个按钮标题（「回头」）和一句话 title（「放弃带走的一切，原路回去」）。D9 建议给它补一段与前三者等长的文案。方向：不写「你做了什么」，写「你放下了什么」——放下的是你带下来的每一张牌、你杀过的每一个敌人、你攒过的每一点凝视。放下之后，路还是那条路，但你走的时候手里是空的。
