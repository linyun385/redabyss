## 三、黯星回响（静默段）的定位

现状：死亡时凝视 ≥15 解锁（[index.html:7463]）→ startEchoRun 用 anmin 职业重开（[index.html:7474]）→ echoEnemyPool 取 anminEnemies（[index.html:7487]）。它是「死亡不是结束」的现行实现——D10 的前身。

D9 建议：回响局通关后「凝视结算减半记入主周目结局账」——让短局有长局意义。引擎落点：markCleared 的 endings 表加 echo 结果键。

## 决定记录

- 多周目继承的边界卡在「roguelike 铁律」（T29 §五：不追求通关率）与「二周目差异化」之间——本篇只建议**叙事/资源微调**（凝视初始值、概率修正、卡面纪念），不动牌库与遗物继承的底线。
- 事件选择记忆（redabyss_evlog）是 T333 requires 门槛建议的前置依赖——两个方向共用一份存储设计。

## 四、结局与层制的关系（为何结局不只是分数线）

长审在 L7-L8 最容易触发——burn_hand 层逼你丢手牌，唯一补偿是 mark 代价（每张 cng_0050 凝视 +1）；同行在 L4-L5 最常见——共鸣/热泉的资源自然漂移让凝视在 6-19 之间浮动；背身需要全程刻意控制——每一个 gift 意图（[engine/core.js:788]）都要拒绝，每一个 mark 代价都要付出 maxHp 或共振。三个结局对应三种「与红渊的关系」——被看（长审）、躲着看（背身）、对视（同行）。

层制对结局的影响不只是数字：burn_hand（L7）的每回合丢牌 + mark 代价的每张凝视 +1 意味着「越深层越难背身」——L7-L8 的自然漂移方向是长审。设计意图：**红渊在深处在看你，不是你在看红渊**。这句引擎注释（[engine/core.js:849] 的三段结局文案）是整个凝视系统的世界观锚点，D9 的多周目建议全部围绕它展开。

## 五、D9 增量的实施优先级

1. 长审二周目（凝视初始 +3）：改动量最小（newRun 一行），叙事增量最大（红渊记得你）——先做。
2. 回头二周目（maxHp +10）：同样一行，但「放过一切的人身体记得」需要美术配合（回头画面的变化）——次之。
3. 事件选择记忆（redabyss_evlog）：改动量中等（新 localStorage 键 + chooseEventOption 写入），但解锁的是全部重复事件的「上一次你选了 X」——基础设施。
4. 背身/同行的二周目修正（概率/卡面）：依赖美术，最后。
