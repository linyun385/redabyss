# 一、共享池 5 张

## u_0017 命运的旧日左轮（shared · attack · uncommon · 1 费 · 光）

**design_note**：进行一次判定，50% 概率造成 5 点伤害，如果成功，再执行一次，最多 4 次。（升级：6 点 / 最多 5 次）

1. **触发时机**：打出时，触发一条「判定链」：判定→成功则造成伤害并再次判定→失败则停止；总判定次数上限 4（升级 5）。
2. **目标**：单体敌人（`effect.target: 'single'`，resolveTargets L5948-5951）。
3. **数值与上限**：每次成功 5 伤（升级 6）；判定链上限 4 次（升级 5）→ 单次打出伤害区间 0 ~ 20（升级 0 ~ 30）。稿面无其他数值。
4. **引擎现状**：**不支持**。① 引擎没有任何卡牌侧的概率判定机制：`hits` 是固定次数循环（applyCardEffect L5997-6003），不做逐次判定；全文检索 `50%` 仅命中 CSS 动画与注释，`0.5` 仅命中地图权重（L4025-4027）、梦反噬系数（L6252）与奖励（L7029/L7146），`randInt`（L5439）只用于敌方掉落（L6226）与金币（L6508）。② 最接近的随机先例是悬浮体的 `random_effect`（L6128-6142）：从**硬编码 5 项池**中随机取 **1** 项执行——它是「随机选效果」，不是「概率判定 + 可能连击」。③ 基础伤害/多段本身支持（L5996-6004）。需要引擎新增：带概率与次数上限的判定链 special 码（随机源可用现成 `C.rng`，L6141 有用法先例）。
5. **边界**：① 不会无限循环——判定次数有硬上限（4/5 次），判定失败即终止；② 与连携加成（veinChainBonus L5918-5936，bonus×2 计入 L5997-6000）如何叠加需要定：是每次判定都吃力量/连携，还是整卡一次——现状 applyCardEffect 是按「每 hit 同值」结算（L6001-6003），照搬会把 bonus 也放大到最多 4 次；③ 概率判定若走 random_effect 的 `C.rng()` 模式，与存档回放/随机种子的一致性未确认（未确认：`C.rng` 的种子化机制，未在本任务范围内追查）。

## u_0018 追逐光（shared · skill · rare · 0 费）

**design_note**：恢复一点能量。（升级：恢复一点能量，抽一张牌）

1. **触发时机**：打出时。
2. **目标**：自己。
3. **数值与上限**：能量 +1（升级再加抽 1）。无稿面上限。
4. **引擎现状**：**支持，可直接实装**。① 加能量：`energy_gain` special 码（applySpecial L6120-6123，`C.energy += V`）；0 费卡的打出流程照常（playCard L5807 起，0 费走 L5818-5819 检查通过）。② 升级加抽牌：`effect.draw`（applyCardEffect L6010，draw() L5790-5804）。同类 0 费卡先例：dive_0071 灯序表（0 费抽 1）。
5. **边界**：① `energy_gain` 没有上限校验（L6121 直接加），但能量在下回合开始被 L5680 重算覆盖，所以收益只在本回合有效——不会跨回合累积；② 本回合内多张 0 费 +1 能量卡连打可以持续净赚能量，这与审核报告顶部「更正 2」的口径一致（该类组合是否放行属设计决策，此处只陈述机制）；③ 抽牌受 HAND_LIMIT=10 限制（L5793）。

## u_0019 旧日的回响（shared · skill · rare · 1 费 · 光 · cost_type: custom）

**design_note**：从弃牌堆取回一张牌，如果取回的牌属性为光，则消耗减少 1；代价：超忆，下回合开始能量减 1。（升级：取回一张牌，能量加 1，光牌则消耗减 1，代价不变）

1. **触发时机**：打出时取回；「下回合开始能量减 1」在下回合 beginTurn 结算。
2. **目标**：弃牌堆 → 手牌（单张）；能量结算对象是自己。
3. **数值与上限**：取回 1 张；光脉牌费用 -1；下回合能量 -1；升级版能量 +1。「取回哪一张」如果由玩家选，需要选择 UI；「随机取一张」则不需要——稿面未写明，需设计师拍板。
4. **引擎现状**：**大部分不支持**。① **从弃牌堆取回到手牌：不存在**。弃牌堆现有操作只有：整堆洗回抽牌堆（draw 内 L5794-5800）、敌方随机「吃掉」一张进消耗堆（drain_discard L6406-6411）。全文检索 `取回` 无命中。② **「取回的牌费用 -1」：不存在**。cardCost（L5896-5916）只读卡的基础 `energy`（L5897）、层规则（L5899/L5901）、遗物脉费修正（L5909-5913）——没有任何「对某一张牌的临时减费」通道。③ **「下回合开始能量减 1」：有半成品**。结算公式 L5680 已读取 `C.energyPenalty`（扣减项），层事件 `locked` 会赋值 `C.energyPenalty = 1`（L5416）；但它与一次性字段 `nextTurnBonusEnergy` 不同——后者用完即清（L5681-5683），`energyPenalty` **没有任何清零处**（全文仅 L5416 赋值、L5540 初始化、L5680 读取），照搬会把减费变成整场持续。一次性扣减需要新增字段或给 energyPenalty 加清零。④ **cost_type: custom：引擎不做任何事**。applyCardCost 的 switch 只有 memory/vitality/mark/lock 四个 case（L6176-6195），无 custom；全文检索 `custom` 无命中。cost_text 只是文案。⑤ 「光属性」判断可行：卡的 `veins` 数组可直接查 `'light'`（L5984 有读 veins 的先例）。⑥ 「超忆」：全文检索无命中，**未确认**（引擎无此机制；design_note 中它像是对「下回合能量-1」的叙事命名，是否为独立机制需设计师确认）。⑦ 升级版「能量+1」：`energy_gain` 支持（L6120-6123）。
5. **边界**：① 取回的若是一张 `_token` 临时牌（悬浮触发牌）：token 正常打完进弃牌堆（L5889），取回它没有意义但不会崩；② 取回「本场锁死」的卡：`card._locked` 标记仍在卡对象上（L6193），取回后照旧打不出（L5834）——行为合理但值得在实装时写死预期；③ 若取回目标带 `retain`，它会在 beginTurn 的保留判定里留存（L5630），不冲突；④ 弃牌堆为空时的行为稿面未定义。

## u_0020 模仿手（shared · power · special · 1 费）

**design_note**：选择一个敌方的意图，实现其效果并指定对象释放。

1. **触发时机**：打出时（power 类型照常进场上限结算——引擎的 power 无持续组件概念，见 applyCardEffect，打完即结算完全部 special）。执行时点有两种理解（打出时复制当前意图 / 持续每回合复制新意图），稿面未写明，需设计师拍板。
2. **目标**：复制敌方意图的效果；最终效果对象「指定释放」——即由玩家再选一次目标。
3. **数值与上限**：稿面无数值；效果完全继承所选意图。敌意图类型现有四种：attack（L6394）/ defend（L6444）/ buff（L6452）/ debuff（L6457，含 steal/gift/weak/poison/burn 五种子类型 L6458-6477）。
4. **引擎现状**：**不支持**。① **没有玩家侧的意图执行器**：意图数据结构存在（`e.intent = {type, value}`，nextIntent L6344-6349、currentPattern L6352-6361），但唯一消费者是 enemyAct（L6379-6479），它写死了「敌人打玩家」的方向（L6429-6434）；没有「以玩家为主体执行 intent」的函数。② **没有卡牌驱动的选择 UI**：全文 `choose` 只命中事件的选项（chooseEventOption L7722/L7728），卡牌打出流程是同步的（playCard L5807-5894 无交互断点）。③ 目标二次指定需要复用现有拖拽选目标（UI 层 dropEnemy L8446 附近有目标点选）——可行性未确认（未确认：`dropEnemy`/`targetIdx` 的完整交互链路）。④ special 稀有度在池内有 14 张先例，power+special 有 3 张（anm_0050、cng_0025、cng_0050）。
5. **边界**：① 各意图类型语义异构：defend 意图是「敌人给自己加 block」（L6445），玩家执行它是给自己 block 还是给敌人？buff 意图是敌人给自己加攻（L6454）——「实现其效果」的方向映射需要逐类型定义；② 与凝视增伤的关系：enemyAct 里的伤害吃凝视倍率（L6392），玩家执行的复制品是否也吃，需定；③ 死亡敌人的意图是否可选未定义。

## u_0021 可控地震（shared · attack · common · 3 费）

**design_note**：对所有敌人造成 25 点伤害，自己受到 10 点伤害。

1. **触发时机**：打出时。
2. **目标**：全体敌人 + 自己。
3. **数值与上限**：全体 25 伤；自伤 10。固定值，无上限递归。
4. **引擎现状**：**一半支持**。① 全体 25 伤：完全支持——`damage: 25, target: 'all'`（resolveTargets L5947 返回全部非 minion 敌人；伤害结算 L5996-6004）。② **自伤 10：不支持**。applyCardEffect 没有任何「对自己造成伤害」的字段或 special 码（special 码全表 L6057-6154 无 self_damage；全文检索 `selfDamage` 无命中）。函数 `damagePlayer(C, amount, source)` 存在（L6237-6284）且能直接复用，但没有从卡牌效果到它的接线。需要引擎新增一个 special 码（例如把 `damagePlayer` 包一层）。③ 力量加成会作用于 25 这个基数（L5999-6000），自伤 10 是否吃力量——稿面未写，实装时需定。
5. **边界**：① 自伤走 damagePlayer 会被格挡吸收（L6241-6243）——「自己受 10」是否无视/吃格挡，稿面未写；② 25 伤对有 block 的敌人先被吸收（dealToEnemy L6210-6212），设计里这张卡没有「无视」字样，照常吸收；③ 全体目标**不含子代理**（L5947 过滤 `isMinion`），若场上是子代理 + 敌人，25 伤只落真敌——这是现行目标模型的事实，不是本卡特有；④ 苍民梦中自伤会打到 dreamHp 并触发破梦链（L6245-6271）——跨职业行为需过一遍。

## anm_0051 机械增生（anmin · power · uncommon · 0 费 · 光 · lock）

**design_note**：打出后，本回合内你每使用一张牌，获得一点零件。（升级稿：「能量+1」，并保留每牌+1零件）

1. **触发时机**：打出时置位标记；之后每次打出其他牌时结算 +1 零件；本回合结束清零。
2. **目标**：自己（零件库存）。
3. **数值与上限**：每牌 +1 零件；**无稿面上限**（一回合打多少张就得多少）。实装值 value=1（卡池 upgrade 版 value=2）。
4. **引擎现状**：**已实装**。① 卡池：anmin.json 中 anm_0051 已有 `special:[{code:'mech_grow'}]`、cost_type lock、0 费；upgrade 为 mech_grow value 2。② 引擎：置位 L6115-6119（`C.buffs.mechGrow`）；每牌结算在 playCard——打出前先记录 `growOnBefore`（L5852），效果结算后补发零件（L5870-5874）；回合开始清零（L5688）。③ **draft 与卡池差异**：draft 的 upgrade_note 写「能量+1」，卡池实装的 upgrade 是 mech_grow value 2（每牌 2 零件）、**没有能量**——两版 upgrade 不一致，需设计师定。
5. **边界**：① 打出机械增生那张牌本身不给自己算零件（L5852 在 applyCardEffect 之前取值）——即「打出后」每**再**打一张才算，与 design_note 口径一致；② 与 0 费循环卡（重铸）叠加：每打一张重铸 = 得 1 零件、花 1 零件，净 0，不构成零件无限循环；③ mechGrow 在 beginTurn 清零（L5688），不会跨回合。

## anm_0052 子代理（anmin · skill · uncommon · 3 费 · 矿 · part_cost 5）

**design_note**：消耗 5 零件，创造一个 10 血 3 攻的己方生物，意图是每回合发动一次攻击，该生物优先承伤，登场后每回合额外消耗 1 点零件，增加 5 血 2 攻。（升级：15 血 5 攻）

1. **触发时机**：打出时召唤；此后每回合开始：扣 upkeep 零件→加成长值→刷新意图（L5646-5657）；敌攻时优先承伤（L6417-6424）；它自己的回合攻击真敌人（L6383-6390）。
2. **目标**：召唤物进 `C.enemies` 列表（L6151）；承伤面向玩家；攻击面向真敌人。
3. **数值与上限**：召唤 10 血 3 支（升级 15/5），part_cost 5；成长每回合 +5 血 +2 攻（升级稿写 +6 血 +3 支，见下）；每回合 upkeep 1 零件，零件不够**不成长但不消失**（L5654-5655）。成长值无上限。
4. **引擎现状**：**已实装**。① 卡池：anmin.json anm_0052 `part_cost:5`、`summon_minion {hp:10, atk:3}`、upgrade `{hp:15, atk:5}`、cost_type none。② 引擎：召唤 L6149-6154；makeMinion L5764-5788（intent 固定 attack L5775；**growHp:5 / growAtk:2 / upkeep:1 为硬编码** L5784-5786）；每回合成长+扣零件 L5646-5657；minion 死亡不产零件（L6218-6221）。③ **draft 与卡池差异**：a) draft 的 `cost_type: "vitality"` 在卡池实装里是 `none`——若按 draft 打出还要**最大生命 -1**（vitality 处理 L6183-6187），卡池版没有这条；b) draft 升级稿写成长 +6 血 +3 支，但引擎成长是全 minion 共用的硬编码 5/2（L5784-5786），卡池 upgrade 也没有改成长——按现引擎，升级版成长仍是 +5/+2。
5. **边界**：① 优先承伤有例外：敌方贯骨振动（pierce）绕过子代理直接打玩家（L6416-6427）——引擎注释明写；② 子代理不在「全体敌人」目标里（L5947 过滤 isMinion），可控地震等 AOE 不会误伤它；③ 敌方 drain_discard 等意图不作用于 minion（L6406 起在 enemyAct 的非 minion 分支）；④ 多个子代理并存时，敌攻由**第一个**活着的 minion 承伤（L6417 `find`）——不是分摊；⑤ 给玩家的力量增益子代理也吃（resolveTargets L5961 注释），它的攻击随之变强（applyBuff L6036-6038 刷新 intent）。

5. **边界**：① **自身递归**：若本卡在历史栈里且再次被回放——本卡打出时自己还没进栈（打出先于入栈），但**第二次打出它**时栈里已有第一次的它，回放会再触发一次回放。需要明确「回放不再触发回放」或允许嵌套并设深度上限，稿面未写；② 回放的灼烧类效果走 applySpecial（L6058）是**覆盖式**（重施会重置 v/turns 而不是叠加），回放 3 张都带灼烧时只有最后一张的灼烧数值生效——这是现引擎灼烧语义的事实；③ 回放的伤害吃当前力量/连携（L5999/L5977），不是打出时快照——增强类 buff 后回放会变强，稿面未写明要快照还是实时；④ 回放「本回合最后 3 张」若包含本卡自己打出前的最后 3 张（含本回合早先的它自己）语义已由 ① 覆盖；抽牌堆/弃牌堆里的同名卡不干扰（历史栈存实例）。
