# D10 · 孤儿卡清单

> 判定方法（交互图）：一张卡为孤儿 = ① 不提供任何有消耗方的钩子（共振供给/状态供给/凝视债/乘区）；② 不消费任何系统资源（共振/凝视/门槛）；③ 不挂通用经济（伤害←力量、格挡←敏捷、牌/血/荆棘/再生）。
> 另列「断线卡」：有钩子但钩子的消耗端已死（frail）。复算脚本内嵌 data/audit/。只报告。

## 半孤儿（唯一钩子是自闭合机制，人工补充判读）

- `u_0016` 越权的批文：脚本判它孤儿是因为**钩子不在 effect 字段里**——它的 `anmin_mark:{protocol:purge}` 与引擎协议系统交互（自伤/全体攻击的持续状态），且 purge 的「每回合自伤 2」与维护者的生命经济强相关。严格说是**半孤儿**：卡池内无配合，引擎系统内有交互。

- `share_0001` 强行供能（rule_bypass）：效果只与**层规则**交互（no_light/dry/cold），没有任何卡与它配合——它是机制展示位，孤儿性「设计使然」。
- `trem_0022` 回归墟骨（delete_random）：删牌只与「卡组厚度」这个元系统交互，全池无第二张删牌——删牌轴只有它一根柱子。
- `trem_0034` 断流 / `dive_0022` 硬矿钻（重型）：frail 供体断线（见上表）——它们的主效果有钩子，挂件是死的。
- 共振锁定 5 张（dive_0016/0023、trem_0019、anm_0020/0027）：resonance_lock 只与引擎共振状态交互，卡与卡之间无配合——但它是「经济保险」定位，锁的是自己池子的资源，不算孤儿（消费对象=全局共振）。

## 一句判断

严格判据下**零孤儿**——每张卡至少挂一个经济钩子（这是好事：卡池没有真正悬空的牌）。真正的孤立点在**机制轴**上：rule_bypass、delete_random、poison 三个机制各自只有一张卡承载——「轴只有一根柱子」，倒下就整轴消失。
