# U04 · 深井的回声（u_0004）设计书

> T331 通用牌 u_0004 的逐张设计书。四段：名字来由 / 费用依据 / 效果与引擎落点 / 补哪条弱路与不该被选的条件。数值以 T341 草案为准。

## 一、名字来由

深井里的回声会把你的话还给你，但不一定按你说的顺序——scry（看牌堆顶、自由排列）的井底叙事化。名字刻意避开「占卜/预知」这类出戏词，留在矿工的感官世界里。

## 二、费用依据

0 费。依据：scry 2 的信息价值高但即时收益 0；0 费让它在任何空闲能量位可插入，对标 StS 的 Purity/Conclude 类 0 费技巧卡的定位。1 费会让它在「过牌流」里被 trem_0043（1 费抽 2）直接挤出构筑。

## 三、效果与引擎落点

effect: {"scry": 2, "target": "self"}。引擎落点：牌堆无 scry 概念，需要新的「查看并重排」交互（逻辑+UI 都是新的，改动量中）。

## 四、它补哪条弱路

过牌流的牌序控制器；共振流的阈值调度（把 resonance_gain 卡调上来或把过载卡沉下去）；记忆代价流的方差灭火器（memory 删牌前先看一眼）。

## 五、什么情况下它不该被选

不该被选：① 牌库已经极薄时（scry 的选择价值随牌堆缩小而归零）；② 极速爆发流（每费都要变成伤害，0 费也只能塞下一点点）；③ 对 scry 结果不做战术调整的玩家（它没有直接效果，纯信息牌）。

## 十八、与预兆系统的边界（疯先知专属注记）

scry 与预兆（OMENS，[engine/core.js:937]）都改变「未来的顺序」，但方向相反：预兆是系统往你的未来里塞东西（3 回合倒计时后结算），scry 是玩家从自己的未来里挑东西。两者同场时会形成「系统给你的未来」与「你挑的未来」的双层排队——实现时 scry 只应重排 drawPile，绝不允许重排 omens 队列（[engine/core.js:952] 的预兆生成独立于牌堆），否则玩家会学会用 scry 拆预兆，疯先知的压迫感设计就漏了。

这也是它加给疯先知时最强的用法：预兆倒计时是公开信息，scry 把倒数第二张牌调上来，正好在预兆应验的同一回合打出关键牌——「在命运的间隙里塞自己的牌」，这个画面就是疯先知流派该有的样子。
