### UI 链路审计（代码行号均为 web/index.html）

- **R1 出牌链路**：`pointerdown → startCardPointer (L7916) → pointerup → doPlay (L6922)`。`doPlay` 全同步：`flyCard`（L7587，同一任务内 append 飞出残影）→ `RedAbyss.playCard`（引擎）→ `render()`（同步重建 DOM）。**点击到牌离手之间无 setTimeout / await / 动画等待**。另一路径：点卡开详情 →「打出」`cd-play (L8052)` → `doPlay`，同样同步。
- **R2 结束回合链路**：`#btn-end (L6912)` → `RedAbyss.endTurn(C)` 同步（敌人动作在调用内执行完毕）→ `render()`。敌人动作开始时间 = 点击后一次同步任务内。唯一 `setTimeout(finishCombatFlow, 450)`（L6919/L6946）是**战斗结束→进结算**的停顿，不属于「敌人开始动作」。
- **判定**：引擎侧余量约 250–400 倍门槛；UI 侧为同步直渲染，无异步间隙引入的固定延迟。**引擎层达标；浏览器端到端 <100ms/<200ms 属人工项，本次未实测**（建议用浏览器 DevTools Performance 面板复核，预期主要耗时是 render 的 DOM 重建）。

## 8. 结论与未达标清单（留白天拍板）

**达标**：R1/R2 引擎层达标（max 0.397ms / 0.267ms，余量约 250–400 倍）；动画时序表 A1–A5 五项全部落在任务书区间；反馈八件套 7 项全达 + 1 项部分（F6）；不打架 3 项全达；I1、I3 达标（I3 部分覆盖）。

**未达标 / 待办（未改，如实记录）**：
1. **I2 动画可跳过：未实现**（唯一硬性不达标）。建议全局点击加速或队列清空方案（§6）。
2. **`gazeblink` 800ms、`resflash` 1000ms 超 500ms 上限**（反馈类，任务书未给时长；建议压到 ≤500ms 或修订口径）。
3. `perf-low` 降级未覆盖 ghost-fly / floatup / resflash（建议补 3 行 CSS）。
4. F6 抖动只覆盖拖拽路径，点击不可用牌无抖动（建议在详情面板打开时对卡面加 `shakeit`）。
5. 浏览器端到端 <100ms/<200ms 与自检三项的人工复测未做；`check_perf.js` 缺失。
6. `TASK_DONE.md` 的 T27 完成记录**本补做未写入**（按补做指令只产出本档案与 `tools/_feel_check.js`，由用户白天确认后追加）。
