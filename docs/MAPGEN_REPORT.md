## 4. 已知问题与取舍（诚实写）

1. **自然死路率 = 0**：贪心走法 500 局零救援。原因：out-deg 1–3 + 每边界必有跨带边（I9）+ 随机选边，路径几乎总有未访问出路；死路主要在「多条岔路都走过后回到汇聚点」才出现，单次贪心穿越触发不了。**救援功能本身已被验证**（T57 三条强制死路实测通过 + 本模拟内嵌自证：强制死路场景下 rescueTargets 恒非空）。若设计上希望救援更常触发，可调 `node.maxInDeg` 调低（汇聚更多）或 `edge.extraBranchOdds` 调低（岔路更少）——**本次不改**（零死路 = 玩家卡死风险为零，是安全侧）。
2. **模拟走法 ≠ 真人走法**：贪心随机不含「玩家偏好」（避战斗、刷商店、追事件）——真人遇到 shop/event 的比例会高于 23–27%，遇到 combat 的比例可能更低（绕路）。类型到访的**均匀性**结论可迁移，绝对值不可直接当留存/体验指标。
3. BOSS 战只计数不模拟战斗——「实际打了几次 BOSS」的平均 3.31 是**遭遇数**，难度影响归 T61/T65 的战斗平衡。
4. 单局步数 15–26 的方差来自随机选边；最短可通关路径（按 BFS 深度，T55 统计均值 15.2）与贪心步数 19.8 的差 ≈ 4–5 格绕路，符合「方向随机」的设计意图。
5. 模拟的救援分支计数（伏击/惩罚）因 0 次救援而为 0——分支概率 50/50 的正确性由 T57 实测背书（三局分别命中 penalty/ambush/ambush）。
