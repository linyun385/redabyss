# T47 卡池结构诊断（脚本算，不猜）

## 目标
260 张卡的**结构**有没有病：不是平衡性调参，是分布与空洞的诊断。
要求所有结论都由脚本算出的数字支撑，禁止凭感觉。

## 产出 1：tools/card_audit.js
统计并落盘 `tools/card_audit.json` + 打印摘要：
- 每个职业 × 每条脉 × 每种费用(0-3+) × 每种类型(攻/技/势) × 每种稀有度 的**卡数矩阵**
- 每格的「应有量 vs 实有量」（应有量按职业卡池规模等比，公式写进脚本注释）
- 重复度：卡名 / 效果文本 / 效果组合的相似卡对（用文本相似度或 effect_code 组合指纹）
- 超模嫌疑：按费用归一后的效果强度数值（伤害/格挡/抽牌/能量 折算同一尺度，折算系数必须写明来源或假设）

## 产出 2：docs/CARD_AUDIT.md
- 矩阵热区（过载）与空洞清单：**至少 8 个具体问题**，每个写：位置（职业/脉/费用/稀有度）、证据数字、影响、补牌或调整建议
- 明确区分「结构问题（空洞/重复）」与「平衡问题（超模/废卡）」——后者只列不改（T38 已界定范围）

## 硬约束
- **不改任何卡牌数据**（本任务只诊断；改数据另开任务）
- 脚本必须**可重复跑**且自带断言（读到的卡数与 `cards/*.json` 实际条数一致，不一致就报错退出）

## 验收
- `node tools/card_audit.js` 一次跑通，输出 JSON + 摘要
- `node tools/pack_check.js all` 全绿（未被误改）
- 报告里每个数字都能在 JSON 里找到对应项

## TASK_DONE 要写
矩阵规模、发现的问题数与分类、最严重的 3 个、折算系数的假设、边界声明
