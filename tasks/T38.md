# T38 只修明显坏掉的卡（不做深度平衡）

## 重要：任务范围被刻意缩小

用户明确说了：**卡牌机制以后可能大改**，所以现在做深度数值平衡是白费。

所以本任务**只做一件事**：找出**明显坏掉**的卡并修，不做整体系数调整。

## 什么叫"明显坏掉"

只处理这三类，其他一律不动：

| 类型 | 判据 | 处理 |
|---|---|---|
| **完全无用** | 使用率 < 5% 且胜率相关性为负 | 加强到能用的程度（不追求强） |
| **无脑必选** | 使用率 > 80% 且显著正相关 | 加一点代价或降一点数值 |
| **描述与实际不符** | 卡面写的效果和代码行为不一致 | 修文案或修代码 |

**注意**：使用率低但胜率相关性为正的（难用但强），是**好设计**，不要动。

## 步骤

### 1. 跑模拟拿数据
```powershell
node tools\sim.js --class diver --runs 300
node tools\sim.js --class tremor --runs 300
node tools\sim.js --class anmin --runs 300
node tools\sim.js --class cangmin --runs 300
```

如果 `sim.js` 不输出「每张卡的使用率」，先补这个统计（它不输出就没法判断）。

### 2. 列出问题卡
写进 `docs/BALANCE_V3.md`：

```markdown
## 完全无用（使用率 < 5%）
| 卡名 | 职业 | 使用率 | 胜率相关性 | 原因猜测 | 处理 |
|---|---|---|---|---|---|

## 无脑必选（使用率 > 80%）
| 卡名 | 职业 | 使用率 | 胜率相关性 | 处理 |
|---|---|---|---|---|

## 描述不符
| 卡名 | 卡面写的 | 实际行为 | 修哪边 |
|---|---|---|---|
```

### 3. 只改这些问题卡
原则：
- 一次只改一个字段
- 改完重跑对应职业 300 局
- 记录改动前后的使用率

### 4. 不要做的事
- 不要动敌人（那是另一件事）
- 不要动 flavor（文风是 T13 的事）
- 不要追求通关率达标——**这是 roguelike，失败是设计的一部分**
- 不要"顺手优化"没问题的卡

## 目标

能把每个职业的废卡数量降到 **2 张以内**就够了。

通关率**不作为验收标准**（因为机制要改）。

## 验收

```powershell
node tools\pack_check.js all
node tools\sim.js --class diver --runs 300
node tools\sim.js --class tremor --runs 300
node tools\sim.js --class anmin --runs 300
node tools\sim.js --class cangmin --runs 300
```
