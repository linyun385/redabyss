# T67 素材全量接入 + 体积与回归（最后收口）

## 前置
T66 的样张**必须用户点头**之后才做本任务。没点头就停，写 TASK_DONE 说明「待用户确认样张」。

## 目标
把素材接进游戏，并且**不把单文件撑爆**。

## 硬约束（这条最容易翻车）
1. `tools/check_web.js` 现在有两条规则会拦：
   - 出现 `<img` → FAIL
   - 出现 `background-image:url(` → FAIL
   本任务**必须**改检查器：允许 `data:` URI，继续禁止 `http/https` 外链，并在检查器里写明改动理由。
2. **单文件体积上限**：`check_web` 现有规则是 > 3,000,000 字节判 FAIL。当前约 412 KB。
   - 预算：素材总增量 **≤ 1.6 MB**（给文本/逻辑留余量）
   - 单张：卡面 ≤ 30 KB，敌人 ≤ 20 KB，立绘 ≤ 60 KB，结局 ≤ 120 KB；统一 WebP quality 78–82，尺寸不超过 512 长边
   - 超预算就**减数量或降尺寸**，不许调高检查器阈值来过关

## 产出
1. `web/index.html` 里新增常量表 `const ART = { '<id>': 'data:image/webp;base64,...' }`，`appendArt()` 按 `card.art` 的 **id** 去查（不再直接拼 url）
2. 敌人图案区（`.enemy .eart`）、职业立绘（`.class-card .portrait`）、结局插画三处同样走 `ART` 查表
3. 遗物图标：**不用生图**，用内联 SVG 几何徽记（30 个以内），或沿用现有符号
4. 三主题（off/B/C）下素材观感对比截图，各 1 张（战斗界面）
5. `docs/art/ART_DELIVERY.md`：素材清单、体积表、闸门结果、主题兼容说明、如何替换单张图

## 验收
- `node tools/check_web.js` 0 警告（且确认它在拦外链，不是被放宽成摆设——故意塞一个 http url 测试它会红）
- `node tools/pack_check.js all` / `test_engine.js` 全绿
- 体积报告：文件总大小、素材增量、单图最大体积
- 10 张手牌 + 小图 + 右侧信息区同屏：无整页滚动条、按钮在视口内
- 三主题截图
- 相似度闸门复跑一次（接入的是过闸门的图）

接入数量、体积表、检查器改动内容与「它仍然会拦外链」的证据、三主题截图、闸门结果、边界声明（哪些图只做了机械验收没做审美判断）
