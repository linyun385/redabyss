## 零、这次任务的性质（先读这段，读不懂别开工）

这不是「写一份 JavaScript 教程」。
这是**给一份 9087 行的真实游戏代码做注解**。

区别在于：通用教程可以写「JavaScript 用 let 和 const 声明变量」然后随便举个例子。
本任务**禁止**这样做 —— 每一个知识点都必须挂在这份代码的**真实行号**上，
讲的是「作者当时为什么在这里这么写」。

### 读者是谁

不是程序员。他知道「变量」「函数」这些词大概是什么，但没有写过代码。
他想要的是：**看完之后，能看懂这个项目里的一段代码在干什么，能自己改一个数值试试。**

### 三条硬约束（违反即整篇作废）

1. **所有代码引用必须带真实行号**，格式固定：`[index.html:5687]`
   - 不许写「大约在文件的中间」「在战斗相关的函数里」这种
   - 引用前必须真的读过那一行
2. **代码摘录必须逐字复制**，一个字都不许改、不许我省略成 `...`
   - 因为验收脚本会拿摘录回源文件里逐字比对
3. **不许出现这些词**：`以此类推`、`类似地`、`限于篇幅`、`不再赘述`、`TODO`、`待补`、
   `这里省略`、`详见后文`（没有后文）

### 五条内容要求

| # | 要求 |
|---|---|
| 1 | **结论先行**：每篇开头 5 行内必须讲清「这篇在说什么、你看完会懂什么」 |
| 2 | **讲「为什么」，不只讲「是什么」**：「这里用闭包是为了把随机种子藏起来，让同一个种子每次生成同一张地图」—— 这才算讲清楚 |
| 3 | **每篇末尾给自测题**（3–5 题）+ 答案，题目必须能在代码里找到答案 |
| 4 | **不写百科句**：「JavaScript 是一门广泛使用的编程语言」这种开头，删掉重写 |
| 5 | **遇到看不懂的代码就写「没看懂」**，不许猜、不许编一个合理的解释 |

## 二、T301 追一条完整的链（最重要的一篇）

**产出**：`docs/lesson/01_PLAY_CARD.md`

选一条真实链路，从玩家动作一路追到界面变化。**建议追「打出一张攻击牌」**：

```
玩家点了一张牌
  → 哪个函数接住这个点击
  → 怎么判断能量够不够、这张牌能不能打
  → 怎么找到目标敌人
  → 伤害是怎么算出来的（有没有加成、有没有抗性）
  → 敌人的血是怎么被扣掉的
  → 界面是怎么知道要重画的
  → 玩家看到的那一下动画/数字是从哪来的
```

写法要求：

- 每一步：**行号 → 代码摘录（逐字）→ 这一段在干什么 → 为什么这么写**
- 不能跳步。如果中间经过一个函数，就要进入那个函数再说
- 结尾必须有一张**流程图**（文字版即可，用箭头串起来，每步标行号）
- 如果链路上有**还没实现的环节**（比如音效），明说「这里应该播放音效，但现在是空的」

**验收**：链路必须闭合 —— 从点击开始，到玩家看得见的变化结束。中间断掉就是没做完。

## 三、T302 语法课（一）· 最小集

**产出**：`docs/lesson/02_SYNTAX_BASIC.md`

只讲这个项目**真的用到**的语法。每个点必须配项目真实代码，且必须解释为什么这么写。

必须覆盖（按这个顺序）：

| 语法点 | 要求 |
|---|---|
| 变量与常量 | 找到代码里同时出现 `let` 和 `const` 的地方，解释为什么一个能改一个不能改 |
| 函数 | 普通函数 vs 箭头函数，项目里两种都有，为什么混用 |
| 对象与数组 | 用 `cards/*.json` 里的一张卡说明：一个对象怎么装下「名字/类型/效果」 |

| 循环 | 找一段 `for`，说明它遍历的是什么 |
| 字符串模板 | 找 `` `${}` `` 的使用，说明它比字符串拼接好在哪 |

每个点：**一段真实代码 + 逐行解释 + 一句「如果不用这种写法会怎样」**。

**验收**：6 个点全覆盖，每点至少 1 个真实行号引用；不许出现没引用代码的段落。

## 五、T304 一张卡的一生（数据怎么变成界面）

**产出**：`docs/lesson/04_DATA.md`

从 `cards/diver.json` 里挑一张真实的卡，追它的完整生命周期：

```
json 文件里那一行
  → 什么时候被读进内存
  → 变成什么数据结构
  → 战斗开始时怎么进牌库
  → 抽牌时怎么进手牌
  → 界面上那个卡面是怎么被画出来的（哪个模板 / 哪段字符串拼接）
  → 打出后 effect 里的字段是怎么被逐条执行的
```

特别要讲清：

- `effect` 里那些字段（`draw` / `damage` / `target` 等）**分别被谁读、被怎么解释**
- 加一张**新卡**最少要改哪些地方（列清单，给行号）
- 改一个**数值**（比如把某张卡伤害从 6 改成 8）要改哪里

**验收**：必须给出「加一张新卡」的最小步骤清单，每步带文件路径和行号。
