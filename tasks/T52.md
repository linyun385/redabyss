# T52 无障碍与性能体检（脚本量出来，不靠感觉）

## 目标
把「能不能读、卡不卡」变成数字。发现问题就修**小**的（CSS 级），大的只记录。

## 一、对比度体检（脚本）
写 `tools/a11y_check.js`：
- 遍历 `web/index.html` 里的颜色变量与主要文本色，按 WCAG 算对比度
- 输出 `tools/a11y_report.json`：**正文 ≥4.5 / 次要 ≥3**，列出所有不达标项（含所在选择器与层深度）
- 已知旧账：深层次要文字对比度 2.07（T44 记录过），本任务要**修掉它**（改 `--dim` 变量即可），或在报告里给出为什么不能修

## 二、色盲模拟
用 CSS filter 近似三类色觉（红盲/绿盲/蓝黄盲），对以下关键信息截图判断是否仍可区分：
- 敌人意图（攻/防/强化）
- 卡牌类型（攻/技/势）
- HUD 六项
截图存 `docs/a11y/*.png`，并在 `docs/A11Y_PERF.md` 里逐项写「仍可区分 / 靠什么区分（形状/位置/文字）」

## 三、字号缩放
90% / 110% / 130% 三档下：地图节点、手牌、日志、按钮不溢出，结束回合按钮始终在视口内。各截一张。

## 四、性能
写 `tools/perf_probe.js`（或用测量脚本）在浏览器里量：
- 首屏可交互时间（`performance.now()` 到首次可点）
- 战斗里连续 10 次结束回合的**平均帧时间**（`requestAnimationFrame` 采样）
- DOM 节点总数
输出 `docs/A11Y_PERF.md` 的表格，并与上一版对比（若没基线就写「首测」）

## 硬约束
- 只改 CSS 变量与少量样式；**不改引擎、不改数据结构**
- 不引外部字体/资源（`check_web.js` 必须绿）

## 验收
- 三个脚本可重复跑，数字落盘
- 对比度不达标项：修掉或写清楚为什么不能修
- 三检查器全绿

## TASK_DONE 要写
不达标项数量（修了几个、剩几个）、色盲三类的结论、三档字号截图、性能三个数字、边界声明（filter 近似 ≠ 真色觉）
