# T58 生态 × 深度 → 内容绑定表

## 已确认前提（2026-10-30 18:35）
- 每个（生态 × 深度带）都要有 **BOSS 池**，供运行时替换使用（生成阶段不用它）。


## 目标
用户要求：**触发什么 boss / 怪 / 精英 / 事件 / 商店装备，由「生态区域 + 深度」共同决定**。
本任务把这张表做出来，并接到生成器上。

```json
{
  "eco": {
    "<生态id>": {
      "bands": {
        "0": {"enemy": ["enemy_id"...], "elite": [...], "boss": [...], "event": [...], "shop": ["tier"...]},
        ...
      }
    }
  }
}
```
硬要求：
- **每个 (生态 × 深度带) 至少**：3 个普通敌人、1 个精英、1 个事件、1 个商店档位
- 每个生态在**深带**必须有自己的 BOSS 候选（不许所有生态共用同一个 boss）
- 所有引用的 id 必须真实存在于 `enemies/*.json`、`events/*.json`（写校验脚本，缺一个就报错）

## 产出 2：tools/check_bindings.js
- 读绑定表 + 实际数据，校验：id 存在、数量达标、无重复、每生态深带有 boss
- 输出覆盖率表（生态 × 带 × 类型 的填充率）
- 不达标退出码非 0

## 产出 3：接线
- `tools/mapgen.js` 生成节点时按 `(eco, band)` 从表里取内容，写进 `Node.binding`
- 生成时**不能**出现「查不到内容」的节点：查不到就回落到同带默认池，并在日志里记一条兜底
