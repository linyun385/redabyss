# T330 · 通用牌组与流派体系设计（给 GLM 的夜间任务）

> 委托人：用户。原话：
> 「还是要有通用的牌组的，这块最大的问题在于**流派设计**上。如果完全没有通用的牌组，
> 流派就会成为一种**角色所衍生出来的概念**，而不是**这个角色适合玩这个流派**。
> 这个角色虽然玩这个流派不强，但是很有意思。省掉通用牌组来换平衡本身就得不偿失，
> 而且对于事件层来讲也是不合理的。」
>
> 执行者：GLM / ZCode
> 产出目录：`game/docs/design/stream/`
> 相关任务：T320–T324（机制诊断）。**T321 的冗余结论和 T322 的方向建议先看**，
> 本任务接着那两篇往「通用牌 + 流派」上做。

## 零、先搞清楚命题（读不懂别开工）

现在的实际情况（已实测）：

| 事实 | 数据 |
|---|---|
| 卡池 | 266 张，**100% 归属 4 个职业**，零张通用 |
| 代码里的通用概念 | **没有**（搜 `colorless` / `universal` 无命中） |
| 唯一跨职业共用 | 开局那 2 张基础牌（`一击` / `缩起`），硬编码在 `index.html`，不在 json |
| 五脉分布 | 四个职业**都覆盖全部五脉**，但各有主脉（下潜者光+矿、震语者震、维护者矿、疯先知光） |

用户指出的问题是：**流派现在只能是「角色衍生物」**。

举例说明这两种的区别 —— 这是本任务的核心，必须理解：

- ❌ 「下潜者的光脉流」—— 流派长在角色身上，换角色就没了
- ✅ 「光脉流」—— 流派本身独立存在，**四个职业都能玩，只是强弱不同**
  - 下潜者玩光脉流：强（主脉）
  - 震语者玩光脉流：不强，但有别的路（比如光脉给震脉做铺垫）—— **这个"不强但有趣"才是价值**

**没有通用牌，第二条路根本不存在**，因为震语者手里没有任何过桥的牌。

## 二、T331 通用牌池设计

**产出**：`docs/design/stream/T331_UNIVERSAL_POOL.md`

设计一个**所有职业都能拿到**的通用牌池。必须回答：

### 1. 规模

多少张？（对比参考：杀戮尖塔约 20 张无色牌 / 320 张卡 ≈ 6%）
按红渊 266 张卡算，6% 约 16 张。**给出你的建议数字和理由。**

### 2. 分层

通用牌至少要分三种角色，各自多少张：

| 层 | 作用 | 大致数量 |
|---|---|---|
| 过渡 | 早期能拿、不依赖任何流派，帮任何角色撑过前期 | ? |
| 桥梁 | **让 A 脉的卡能接上 B 脉**，这是流派跨职业的关键 | ? |
| 构筑核心 | 稀有，一件就能撑起一个流派方向 | ? |

★ **桥梁层是本任务最重要的一层**。用户说的「不强但有意思」全靠它。
一张好的桥梁牌长什么样：`dive_00XX` 那种「光脉卡同时给震脉充能」的结构 —— 你要自己找例子，
找不到就说明现在**根本没有这种牌**，那更要设计。

### 3. 每张牌的具体设计

给每一张通用牌：

| 项 | 要求 |
|---|---|
| 名字 | 中文，符合世界观（地底、倒吊、红光、矿工、旧光者） |
| 类型 | 攻击 / 技能 / 能力 |
| 稀有度 | 普通 / 罕见 / 稀有 |
| 费 | 能量值 |
| 效果 | 必须写成能直接进 json 的结构，比如 `{damage:9, target:'single'}` |
| 它帮哪个流派 | 对应 T330 里诊断出的某个流派 |
| 它为什么通用 | 说清「为什么这张牌任何职业拿都有用」 |
| 它跟五脉什么关系 | 无脉 / 单脉 / 双脉，为什么 |

**不许给「万金油」建议**（比如「抽 2 张」）—— 那已经有 66 张牌在做。
每一张都要有**别的卡做不到**的事。

## 三、T332 角色 × 流派矩阵

**产出**：`docs/design/stream/T332_MATRIX.md`

这是本任务**最核心的产出**。做一张表：

| 流派 \ 职业 | 下潜者 | 震语者 | 维护者 | 疯先知 |
|---|---|---|---|---|
| 例：光脉流 | 强（主脉） | 弱但可行 | 弱但可行 | 强（主脉） |
| 例：矿脉流 | 强 | 弱 | 强 | 中 |

要求：

1. 行列都要填满，**不许留空**
2. 每一格如果填「弱但可行」，必须写清**靠什么牌撑起来**（具体到卡 id 或 T331 里设计的通用牌）
3. 每一格如果填「不可行」，要说明是**缺牌**还是**机制上根本不成立**
4. 矩阵里必须有**至少 3 个「弱但有趣」的格子** —— 这是用户要的核心体验
5. 最后统计：**共有多少条「非主脉但能成立」的路？** 给数字

★ 这张表如果全是「强/不可行」两极，说明设计失败 —— 中间地带才是乐趣来源。

## 四、T333 事件层与通用牌的关系

**产出**：`docs/design/stream/T333_EVENTS.md`

用户的判断是「没有通用牌对事件层不合理」。你要说清**为什么不合理**，并给方案。

必须回答：

1. **现在事件给的是什么？** 从 `events/all.json` 里的 `result` 字段看，事件奖励有 gold / damage / 牌？逐类统计
2. 如果事件给牌，从哪个池里抽？**给出代码位置**（`[index.html:行号]`）
3. **为什么没有通用牌会让事件变得不合理** —— 用具体事件举例：
   - 同一个事件，四个职业拿到的奖励体验是否一致？
   - 有没有事件因为「只能给本职业牌」而失去意义？
4. **改造方案**：哪些事件应该改给通用牌？给具体事件 id 和改法

## 五、T334 改动的代价（诚实评估）

**产出**：`docs/design/stream/T334_COST.md`

加通用牌不是免费的。说清代价：

| 代价 | 具体是什么 |
|---|---|
| 平衡复杂度 | 一张通用牌要在 4 个职业 × N 个流派里都成立，测试量翻几倍 |
| 现有卡的定位要被重估 | 哪些现在「独占某个功能」的卡，会因为通用牌出现而失去存在意义？给 id |
| 五脉系统会不会被稀释 | 通用牌如果无脉，会不会让「脉」这个核心系统变轻？ |
| 商店/事件的抽取逻辑要改 | 涉及哪些代码位置？ |
| 卡面美术成本 | 通用牌要不要专属美术？多少张？ |

★ 这一节**不许美化**。用户要的是真实代价，不是方案推销。
