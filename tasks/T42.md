## 第 0 步：视觉能力自检（必须先做，不许跳过）

在做任何生图之前，先确认**你能不能读图**。

问用户要一张图，或者用 `tools/ref/` 下已有的参考图（如果没有，让用户提供一张）。

然后回答：

```
这张图里有什么？
主色调是什么？
它像什么风格的画？
```

**判断标准**：
- 如果你能准确描述内容 → 你有视觉能力，**后面的风格验收交给你**
- 如果报错、或说"我读不到图片" → 立刻停下，在 `TASK_DONE.md` 写：
  `本环境无视觉输入，风格验收需人工`
  然后**只做机械验证**（尺寸、非空白、命名规范），不要猜。

**不许编造图片内容。** 猜对和真看到是两回事。

## 第四步：接入模板

T36 已经给卡牌留了图案区（`.art`，CSS 类名以 T36 的记录为准）。

接入规则：卡牌 JSON 加 `art` 字段：

```json
{ "id": "dive_0001", "name": "光导透镜（残）", "art": "cards/diver/001_light_lens.png", ... }
```

前端渲染时：
- 有 `art` → `.art` 设 `background-image`
- 没有 → 显示脉的占位符号

**建立命名规范**（写进 `docs/ART_SPEC.md`）：
```
web/art/cards/<职业>/<三位序号>_<英文短名>.png
web/art/enemies/<层级>_<英文短名>.png
web/art/portraits/<职业>.png
```

## 风格验收（看你有没有视觉能力）

如果你第 0 步证明能读图，逐张判断：

1. 缩到 64px 还能看出是什么吗
2. 只看黑白，靠线条还成立吗（靠颜色才成立 = 错）
