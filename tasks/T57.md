# T57 死路救援 + 路线推进（玩法接上）

## 已确认前提（2026-10-30 18:35）
- **BOSS 是运行时判定的**：第一次跨带必出 BOSS；之后按 p0 逐带衰减（有下限、不为 0）；命中时把该跨带的事件格**运行时替换**为 BOSS（类型与内容一起换，生成结果不变）。
- 参数写进 tools/mapgen_spec.json：boss.firstAlways、boss.p0、boss.decay、boss.min。


## 前提
T55 生成器、T56 渲染都就绪；现在把「点节点进事件 → 推进路线 → 死路救援」跑通。

## 目标
1. **推进**：玩家点一个**可达**节点 → 进入对应类型的事件（战斗/精英/随机/商店/事件/BOSS）→ 事件结束后该节点标记 `visited`，解锁它的出边
2. **迷雾**：`visible = visited ∪ 邻接(visited,1)`；推进后立刻重算并重绘（小图 + 总图）
3. **死路救援**（用户明确要求）：
   - 检测 dead-end：无「未访问出边」且不是 finalBoss
   - 界面上给出一个明确的按钮：「另寻一路」
   - 代价随机二选一：`penalty`（扣血/扣金币，比例写进参数）或 `ambush`（随机触发一场战斗）
   - 救援后玩家移动到「最近的未访问节点」的入口，并保持已有迷雾
4. **最终 BOSS**：最底带 `finalBoss` 节点只能从最后一层深度线进入；击败 → 结算（沿用现有通关流程）

## 参数（写进 `tools/mapgen_spec.json`，不要散落在代码里）
`rescue.penaltyHpPct`、`rescue.penaltyGoldPct`、`rescue.ambushChance`、`rescue.pickRule`（nearest / sameBandFirst）

## 硬约束
- 不改 `engine/core.js` 的战斗结算；节点类型 → 事件只用现有入口（`startCombat` / 事件 / 商店 / 营火）
- **不许**用「重开局」来绕过死路
- 救援事件必须在战斗日志里留一行可读记录（玩家看得懂发生了什么）

## 验收
- 构造 3 条死路（用固定 seed 或调试按钮强制），逐条走一遍：按钮出现 → 代价生效 → 新路径可继续
- 走完一整层：从起点到 `finalBoss` 能通关（可用调试按钮直接跳到 BOSS 测结算）
- 迷雾：进入新节点后，只多亮出它周边一圈（截图对比）
- 三检查器全绿；10 张手牌 + 小图不溢出
