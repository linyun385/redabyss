# INBOX 09 · U 批：UI 现状盘点（10 个区域）

> **本批目标**：把 `web/index.html` 当前版本的 UI 现状**按区域盘清楚**，给后面三批提供事实基础。
>
> **★ 能力边界，先读这段**：
> 你**不能开浏览器**，所以你做的是**代码级 + 规范级审计**，不是视觉判断。
> 允许写：「这个元素在 1280×720 下按 CSS 计算占 X px」——因为可算。
> **禁止写**：「看起来有点挤」「视觉上不平衡」——那是设计机在浏览器里看的，不是你能断言的。
> 你可以写「按现有 CSS，10 张手牌在 1280 宽下每张 X px，低于可读字号 12px 的判定线」——这是事实。

## 产出：`docs/design/ui/00_inventory.md`（一个文件，10 节）

每个区域一节，固定四段：

1. **结构**：DOM 骨架（元素 id/class 层级）+ 负责渲染的函数名 + 行号
2. **尺寸**：关键元素在 1280×720 与 1920×1080 下的计算尺寸（宽高/字号/间距），标出计算依据（哪个 CSS 规则/哪个 clamp）
3. **状态**：这个区域有哪些状态（正常/禁用/悬停/选中/拖拽/溢出），每种状态谁改类名
4. **已知问题**：只写能给出**代码证据**的问题（行号 + 现状 + 为什么是问题 + 违反了什么规范）
