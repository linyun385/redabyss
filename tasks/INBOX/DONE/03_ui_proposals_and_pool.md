# INBOX 11 · U 批：设计提案（P 批）+ 方向池（D 池）

> 前置：01、02 批完成。本批做**新东西**——不是修问题，是提案。
> **所有提案都是「建议」，不是「已定」。** 落盘后等设计机在浏览器里验证再定。

## 一、P 批：12 个设计提案（`docs/design/ui/03_proposals/`，每个一份）

每题固定五段：**现状 → 玩家在这里会遇到什么 → 方案（2–3 个，带取舍）→ 推荐哪个及理由 → 落地成本（改哪段/多少行/要不要改引擎）**。

| # | 题目 | 要回答的核心问题 |
|---|---|---|
| P01 | 伤害与受击的反馈序列 | 打出一张牌到敌人掉血，中间该有几拍？每拍多长、屏幕上发生什么 |
| P02 | 出牌到命中的轨迹 | 牌从手牌飞到目标的过程，视觉上怎么表现才不突兀（现在是不是瞬间消失） |
| P03 | 敌人意图的可读性 | 玩家能不能一眼算出「这回合挨多少」。现在展示的是什么，缺什么 |
| P04 | 状态图标系统 | weak/burn/poison/thorns/vitality/regenerate/dexterity/strength 等，现在有没有可视化，该怎么做 |
| P05 | 手牌 10 张的布局 | 现有布局在 1280/1920 下各是什么样，给 3 个替代方案（等宽缩放 / 扇形重叠 / 两排）并算尺寸 |
| P06 | 费用与能量的即时反馈 | 能量不够时玩家能不能立刻知道；拖起来才发现的成本是多少 |
| P07 | 层规则触发的视觉提示 | 8 条层规则（no_light/dry/heat_tick/rad_tick/burn_hand/lock/wake…）触发时，玩家怎么知道「这一层在搞我」 |
| P08 | 共振与凝视的临界感 | 10/20/30 三档、过载线，HUD 现在是不是一个静态数字；靠近时该不该变 |
| P09 | 卡牌详情面板的信息层级 | T53 的右侧常驻面板，信息排布是不是最优；和手牌、和拖拽的关系 |
| P10 | 战斗节奏引导 | 玩家不知道自己「现在该做什么」的时刻有哪些；能不能靠 UI 消掉 |
| P11 | 地图的「我在哪」 | 当前格/可走格/已走格/未探明，四种状态现在怎么区分，够不够 |
| P12 | 结算页的信息呈现 | 一局结束，玩家最想知道什么；现在给了什么、顺序对不对 |

## 二、D 方向池（P 批做完就取，不用问）

> **每个方向 = 自己写一份小任务书 → 做 → 落盘 `docs/design/ui/pool/D<编号>_<切法>.md` → 取下一个。**
> **每个方向的公式是固定的：10 个区域 × 1 个切法。** 所以每个方向产出 10 条，不长，但要求每条都能落到具体元素。

| # | 切法（对 10 个区域逐个问） |
|---|---|
| D1 | **第一眼**：玩家看向这个区域时，最先看到的是什么？那是不是最该先看到的？ |
| D2 | **误操作**：在这个区域，玩家最容易点错/拖错/看错什么？UI 有没有拦 |
| D3 | **键盘路径**：从进入这个界面到离开，不用鼠标能不能走完？每一步按什么 |
| D4 | **小屏适配**：1024×768 下这个区域会怎样？哪个元素最先崩 |
| D5 | **色盲可辨**：把颜色去掉（转灰度图想象），这个区域还分得清状态吗？分不清的是哪几个 |
| D6 | **信息密度**：这个区域一屏塞了多少条信息？哪条可以砍、哪条必须加 |
| D7 | **状态提示**：这个区域有几种状态？每种状态玩家能不能看出来 |
| D8 | **动效时机**：这个区域现在有动效吗？该有的没有、不该有的太多，分别是哪 |
| D9 | **空/错状态**：数据为空、加载失败、数值为 0 时，这个区域显示什么？会不会崩 |
| D10 | **一致性**：这个区域的按钮/面板/间距/字重，和别的区域是不是同一套语言 |
| D11 | **美术协调**：这个区域的质感（纸/墨/描边）和卡牌版画是不是一件事 |
| D12 | **新手第一次**：一个没看过说明的人，第一次到这个界面会先做什么？会不会走错 |

## 四、兜底任务（真没得做时）

`docs/design/ui/04_css_audit.md`：对 `web/index.html` 的样式块做**机器级审计**——
统计魔法数字（非变量的 px 值有多少个、分布在哪些规则）、重复规则（同一组属性写了几遍）、
未被引用的类名、内联 style 的数量与位置、!important 的数量。
**这是纯统计，不判断好坏**，但结果能告诉设计机「这套 CSS 该不该重构」。
