## T340 · 删卡施工单

**产出**：`docs/design/delivery/T340_DELETE_OPS.md`

把 `T335_PRUNE.csv` 的 58 行变成**逐条可执行操作**。每一条必须包含：

| 列 | 要求 |
|---|---|
| 卡 id | 原样 |
| 所在文件 | 具体到 `cards/xxx.json` |
| 删除方式 | 「整条删除」还是「保留 id 改字段」（比如改成通用牌） |
| 影响面 | 这张卡有没有被 `deck` / `starter` / 事件 reward / 遗物池引用？用 grep 查，写明在哪几处 |
| 连带操作 | 删了之后哪个 json 的计数要对上、哪个自检会失败 |

★★ **最要紧的是「影响面」这一列**。删一张卡最容易出的事不是卡没了，是**别的地方还在引用它**，游戏一跑就崩。每条都要真的搜过，不许写「应该没有」。

排序：按 `cards/` 文件名分组，同文件内的操作连续，方便一次改完一个文件。

末尾给一张**执行顺序表**：先改哪个文件、改完跑什么自检、通过再动下一个。

## T341 · 通用牌数据草案

**产出**：`docs/design/delivery/T341_UNIVERSAL_JSON.md`

把 T331 设计出的通用牌，写成**可以直接贴进 json 的草案**。每张牌给一个完整的对象：

```json
{
  "id": "u_0001",
  "name": "通·双芯灯管",
  "class": "universal",
  "cost": 1,
  "rarity": "common",
  "effect": { "...": "..." },
  "flavor": "……"
}
```

要求：

1. **字段名必须照抄 `cards/dive.json` 里真实卡的结构**，不许自己发明字段。
   先去读一张真卡，逐字段对齐，把「不同职业卡里字段不一致」的地方也列出来。
2. id 用 `u_XXXX` 起，**不许和现有 539 个 id 撞**（用 json 查，不许用 md）。
3. `effect` 必须落在 `engine/core.js` 已实现的 effect 类型里 —— 写之前先搜引擎，
   找出**已支持但卡池里还没用**的 effect 类型，优先用它们（这样不用改引擎）。
4. 每张牌末尾写一行：**它补的是哪条弱路**（引用 T332 的格子，如「维护者×凝视」）。
5. 给一张汇总表：牌数、费用分布、稀有度分布、覆盖了 T332 里多少条弱路。

★ 如果某张牌的效果引擎里根本没有，单独列进「需要改引擎」小节，**标出来不实现**。

## T342 · 弱流派补牌清单

**产出**：`docs/design/delivery/T342_WEAK_PATHS.md`

T332 说 14 条弱路里 11 条靠通用牌撑着。这份单子回答：**每条弱路还差什么？**

对 14 条逐条写：

| 项 | 内容 |
|---|---|
| 格子 | 职业 × 流派 |
| 现状 | 现在有几张牌、最强的那张是哪张（id） |
| 缺口 | 缺的是数量、是数值、还是机制 |
| 补法 | 补职业牌（给具体设计）还是靠通用牌（哪张） |
| 优先级 | 高 / 中 / 低，理由一行 |

★★ **优先级要敢下判断**。如果某条路你觉得不值得救（比如双世界流对其他三个职业就是不该成立），
直接写「**建议放弃**」并给理由 —— 这比硬凑一张牌有价值。
