# T72 生态分布与权重重构（不再"一层一个环境"）

## 用户原话（2026-10-31 14:54）
> 「环境生态的分布及其权重也太简单了，几乎就是一层一个环境，在游戏性和设定上都不合理，建议让 GLM 去重读一下环境生态设定」

## 根因（已定位，写清楚免得它再猜）
`tools/mapgen_spec.json` 里每个生态都带 `homeBand`（1–8），生成时按 `canonical=0.72 / adjacent=0.2` 权重让**主场生态占 72%** —— 结果就是"一层一个环境"。
8 层 8 生态一一对应的设计只在**名义**上成立，视觉与遭遇上变成单一色带。

## 必读（重读，不改设定，只改分布）
- `docs/mapgen/MAPGEN_DESIGN.md`（生态枚举与层规则）
- `docs/ECO_ENEMIES.md` / `docs/ECO_EVENTS.md` / `docs/ECO_RELIC_CARD.md`（每个生态的"气味"）
- `layers/layers.json`（层规则：no_light / dim / dry / bright / heat_tick / rad_tick / burn_hand）
- `docs/art/REF_CULTIST_CLASSIFY.md`（配色语言）

## 硬要求
### A. 每带不再单生态
- 每带出现生态数 **2–4 个**（8 带全部满足）
- 单生态在单带内的面积占比 **≤ 60%**（现在 72%+）
- 主场生态保留"主导"地位，但权重降到 **0.40–0.50**；邻带生态 **0.15–0.25**；其余均分

### B. 过渡带（关键）
- 相邻两带的生态集合**交集 ≥ 1**（例如 D3 的干旱区要延伸到 D4 边缘）
- 边界处允许"咬合"：同一生态块可以跨过带线 1–3 格
- 同生态在单带内的连通块 **≤ 3**（别碎成棋盘）

### C. 与层规则绑定
- 生态出现的**权重**要受层规则调制（如 `no_light` 带里发光生态权重 ×0.5），写进 spec，不许硬编码
- 玩家能感知的差异 = 颜色 + 敌人池 + 事件池（T58 的绑定表按 ecoband 已有，无需改）

### D. 参数全部进 `tools/mapgen_spec.json`
新增：`ecoMix.{minEcosPerBand,maxEcosPerBand,canonical,maxShare,blendWidth}`，旧 `homeBand/canonical 0.72` 改为兼容降级说明。
