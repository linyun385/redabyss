# T15 第一轮验收与修复

## 目标
把整个游戏按 `DESIGN.md` §13 的验收清单**逐条实测**，修掉所有问题，写报告。

## 步骤

### 1. 数据完整性
```powershell
cd C:\Users\Administrator\Desktop\杂七杂八\红渊\game
node tools\pack_check.js all
```
必须 `全部通过`。有 FAIL 就修数据（修完重跑）。

### 2. 引擎回归
```powershell
node tools\test_engine.js
```
必须 `全部通过`。如果失败，说明有人改了 `engine/core.js` 却破坏旧行为——对照 `DESIGN.md` 还原。

### 3. 前端检查
```powershell
node tools\check_web.js
```

### 4. 手工实测（必须真的玩，不能只看代码）
用浏览器打开 `web/index.html`，至少玩 **3 局完整流程**：

| 局 | 要求 |
|---|---|
| 局 1 | 用「下潜者」，打到死或通关，记录到达层数 |
| 局 2 | 用「震语者」，打到死或通关，记录到达层数 |
| 局 3 | 专门测边界：故意用带代价的牌，验证代价生效；故意让共振过载 |

**每局都要按 F12 看控制台，有报错就记下来。**

### 5. 逐条核对 DESIGN.md §13

| # | 检查项 |
|---|---|
| 1 | index.html 能打开无 error |
| 2 | 能完整打完一局 |
| 3 | diver / tremor 卡牌数量达标 |
| 4 | 无重复 id / 卡名 |
| 5 | flavor 无禁用词 |
| 6 | 敌人数量与 layer 正确 |
| 7 | 四个 Boss 名称正确 |
| 8 | 遗物数量达标 |
| 9 | 事件各 3 选项 |
| 10 | 所有 JSON 可解析 |

### 6. 额外质量抽查（这部分要动脑）

**抽 5 张卡**：flavor 是不是在描述机制？有没有让我想问"然后呢"？
**抽 3 个敌人**：出招表有节奏变化吗？
**抽 3 个事件**：三个选项真的不一样吗？

### 7. 写报告
创建 `docs/VERIFY.md`：

```markdown
# 验收报告
## 数据 / 引擎 / 前端（各段摘要）
## 三局实测（表）
## §13 逐条（每项 通过/不通过 + 依据）
## 抽查（5 卡 + 3 敌人 + 3 事件的具体评价）
## 已知问题（逐条，写清影响）
## 边界声明（没验证的部分）
```

## 修 bug 的原则
1. **只修，不重构**
2. 每修一个，重跑对应自检
3. 修不好的写进「已知问题」，**不要隐瞒**

## 完成
追加写 `TASK_DONE.md`，notes 写：3 局结果 + 已修 bug 数 + 剩余问题数。
