# T27 战斗顺滑（可测量）

## 原则
"顺滑"不是形容词，是三个数字：**响应快、不打架、有反馈**。

## 验收标准（先写测试，再改代码）

### 1. 响应
- 点击卡牌到牌离手：**< 100ms**
- 点击结束回合到敌人开始动作：**< 200ms**

### 2. 动画时序
| 动作 | 时长 |
|---|---|
| 卡牌飞出 | 180–240ms |
| 伤害数字上浮 | 400ms 后消失 |
| 敌人意图切换 | 200ms 淡入 |
| 世界切换（苍民） | 300–500ms |
| 回合切换提示 | 600ms |

**不要超过 500ms 的动作**，除了世界切换和 Boss 阶段。

### 3. 不打架（最容易出问题）
连续快速出 3 张牌时：
- 动画不能互相覆盖
- 伤害数字要错开位置（不能叠在一起看不清）
- 不能因为动画卡住输入

实现建议：一个简单的**动作队列**，动作依次播放，但**输入不等待动画**。

### 4. 反馈
每个玩家操作都必须有反馈，一条都不能漏：

| 操作 | 反馈 |
|---|---|
| 出牌 | 卡飞出 + 手牌重排 |
| 造成伤害 | 敌人闪烁 + 数字上浮 |
| 获得格挡 | 盾图标脉冲 |
| 共振跨阈值 | 屏幕边框闪红 |
| 凝视 +1 | HUD 数字跳动 |
| 卡牌不可用 | 轻微抖动 + 原因浮字 |
| 敌人死亡 | 变灰 + 淡出 |
| 胜利 | 短暂停顿后进奖励 |

## 实现要求
- 用 `requestAnimationFrame`，不用 `setTimeout` 堆动画
- 所有动画可被"跳过"（点击加速）
- 低配保护：如果一帧超过 50ms，自动降级（减少特效）

## 自检
在 `tools/check_perf.js` 里写一个简单检查（可以人工测）：
1. 打开游戏，连续快速出 5 张牌，画面不撕裂、不叠字
2. 敌人死亡瞬间点继续，不报错
3. 战斗中切标签页再回来，状态不丢

写进 `docs/FEEL.md` 记录实测结果。
