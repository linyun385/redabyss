# T30 趣味性设计

## 判断标准
好玩 = **有选择 + 有意外 + 有故事可讲**。

三个都要做，缺一个就会变成"刷分游戏"。

## 一、有选择：至少 3 种可通关的 build

每个职业至少能拼出 **3 条不同的赢法**。不是"这三条都能赢"，是"这三条**打法完全不同**"。

要求：
- 每条 build 的核心卡不超过 8 张
- 两条 build 之间**至少要有一张卡是冲突的**（拿了 A 就不该拿 B）
- 写进 `docs/BUILDS.md`，每条给一个"一句话爽点"

示例格式：
```
## 下潜者 · 供能流
核心：把遗物堆到 6 个以上，靠"共振过载"反杀
爽点：你明明快死了，但下一回合整个屏幕在闪
冲突：和"零遗物"流互相排斥
```

## 二、有意外：随机性设计

### 1. 做 8–12 个**卡牌组合彩蛋**
两张特定卡在同一场战斗里都打出过，触发额外效果。

要求：
- 不写在卡面上（让玩家自己发现）
- 触发时给一行特殊文案
- 记录在 `docs/EASTER_EGGS.md`（给开发者看的清单）

举例方向（自己设计）：
- 同一张卡打出两次
- 某个脉连打到第 5 张
- 在特定层用特定卡

### 2. 稀有事件
在每个层加 1 个**极低概率**的特殊事件（5% 以内），内容要有冲击力。
不要加"给你一堆金币"这种。

## 三、有故事可讲：死亡与胜利都要留痕

- 死亡结算界面要显示**这一局最有记忆点的一件事**（比如"你在第 5 层拆了 7 台机械，威胁等级到了 9"）
- 通关要显示**这一局的关键选择**（拿了哪些稀有卡、走了哪条岔路）
- 加一个 `docs/RUN_LOG_FORMAT.md` 说明记录格式

## 四、要避免的
- 不要加"每日签到""成就点数"这类手游设计
- 不要加"看广告复活"
- 不要为了趣味牺牲可读性（玩家得看得懂发生了什么）

## 自检
```powershell
node tools\check_web.js
```
手工：
1. 试出至少 2 个彩蛋，确认提示能显示
2. 死一局，确认结算有"记忆点"
3. 通关一次，确认显示关键选择

## 完成
追加写 `TASK_DONE.md`，notes 写：做了几条 build、几个彩蛋、结算改了什么。
