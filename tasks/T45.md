# T45 卡牌 roguelike 借鉴调研（不依赖任何本地环境）

## 目标
把三款对标作品的**机制层**拆开，找出本项目可以借的东西，以及明确不借的东西。
产出是**可执行的提案**，不是读书笔记。

## 对象
1. Slay the Spire（卡牌构筑 + 爬塔的事实标准）
2. Monster Train（多层战线 + 卡组混合）
3. 密教模拟器（只要它的叙事承载方式，不要它的机制）
4. 可选：Balatro（倍率/组合的爽感结构）

## 方法
- 用浏览器查官方 wiki / 开发者访谈 / 高赞拆解文，**每条记来源 URL**
- 每款至少 5 条机制要点，写清：它是什么 → 解决什么问题 → 本项目现在有没有 → 若采纳怎么改（具体到卡 / 遗物 / 界面 / 层结构）
- 论文式二手转述要标明「原文 / 我转述」

## 产出 docs/RESEARCH_BORROW.md
结构：
```
## 一、Slay the Spire
### 机制 1：<名字>
- 它做什么：
- 为什么有效：
- 本项目现状：
- 建议：采纳 / 不采纳（理由）
- 来源：<URL>
```
要求：**≥15 条机制条目**，其中 **≥5 条明确写「不采纳」并给理由**（敢说不借什么，比罗列借鉴更有价值）。

## 严禁
- 直接抄文案或数值表（借鉴 ≠ 复制；只写机制与设计意图）
- 写「参考了 XX 的成功经验」这种空话——每条必须落到本项目某个具体文件/界面/卡池

## 验收
- `docs/RESEARCH_BORROW.md` 存在，条目数达标，每条有来源
- 没改任何游戏代码（本任务不动 `web/`、`engine/`、数据）
- `node tools/check_web.js`、`node tools/pack_check.js all` 仍全绿（证明没误伤）

## TASK_DONE 要写
条目数、采纳/不采纳各几条、最值得做的 3 条提案是哪三条、边界声明（哪些来自原文、哪些是我的推断）
