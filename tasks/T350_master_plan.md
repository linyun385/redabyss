## 为什么做这个

昨晚产出了 **120 个文件、散在 15 个目录**：design / stream / universal / patch / recycle / round2 / delivery / world / enemy / event / combo / ending / death / onboard / copy2 / lore2。

问题是：**没人读得完，也没人知道哪份是最终结论**。同一件事可能有三篇说过、结论还不一致。

这个包的目标：把它收成**一份能照着干的方案**，其余全部降级为附件。

---

## 第一步：建总索引（先做，别跳过）

**产出**：`docs/design/master/00_INDEX.md`

做法：
1. 扫 `docs/design/` 下全部`.md`（约 120 篇），**每篇只读开头 20 行 + 所有标题行**，不要通读
2. 给每篇记一行：`路径 | 归属方向 | 一句话结论 | 字数 | 可信度（高/中/低）`
3. 按方向分组，同方向内按时间排序
4. 标出**疑似重复**（两篇讲同一件事）和**疑似矛盾**（结论冲突）

★ 这一步不判断对错，只建地图。产出一张表，不写散文。

---

## 第二步：按主题合并成「章节」

**产出**：`docs/design/master/01_` ~ `06_` 六个章节文件

按这六个主题合并（不是按目录合并）：

| 章节 | 主题 | 主要来源 |
|---|---|---|
| `01_CARDS.md` | 卡池怎么改：删哪些、加哪些、通用牌怎么落地 | T335 / T340 / T341 / T342 / recycle / universal |
| `02_STREAMS.md` | 流派与职业：14 条路怎么立起来、哪条放弃 | T330 / T331 / T332 / patch |
| `03_ENGINE.md` | 引擎要改什么：四处改动 + 为什么非改不可 | R3_roadmap 阶段二 / CONFLICTS / D 系列 |
| `04_CONTENT.md` | 内容与叙事：世界观、敌人、事件、结局 | world / enemy / event / ending / death / onboard |
| `05_TERMS.md` | 术语与命名裁决 | D12 / GLOSSARY / CONFLICTS |
| `06_RISKS.md` | 风险与已知坑：哪些结论证据弱、哪些要靠猜 | 全篇 |

每个章节的写法：
- **开篇一句话**：这一章要解决什么
- **结论先行**：先给最终结论，再展开
- **每条结论后面跟来源**：`（见 R3_roadmap.md 阶段二）`
- **矛盾处标出来**：`⚠ 两处说法不一致：A 说 X（出处），B 说 Y（出处）。本方案取 A，因为……`
- 章末给一张**「本章待确认」**表

★ 合并时**不许丢结论**。如果两篇说法冲突且判断不了，两个都留着并标 ⚠。

## 第三步：出总纲

**产出**：`docs/design/master/MASTER_PLAN.md`

这是用户唯一需要读的一份。要求：

1. **一页纸能看完的主线**（约 800 字）：现在在哪、要往哪走、分几步
2. **路线图**：沿用 R3 的四阶段，但补齐每阶段的「做完之后游戏变成什么样」
3. **每步的验收标准**：怎么算做完了（可机械验证的最好）
4. **依赖图**：哪些必须串行、哪些能并行（R3 已理清硬/软/无依赖，直接用）
5. **7 件拍板事的最终建议**：一件一段，A/B 选项 + GLM 的推荐 + 理由 + 打开就能看到的文件行号

★ 这份**不许超过 6000 字**。超了就删，总纲的价值在于短。

## 第四步：施工卡（可选的加厚）

**产出**：`docs/design/master/cards/` 下每步一张

把第一阶段 6 项 + 第二阶段 6 项，每项做成一张操作卡：

```markdown
## 步骤 N：<做什么>

**改哪个文件**：`cards/dive.json`（第几处）
**具体怎么改**：…
**改完跑什么**：`node tools/pack_check.js cards` → 期望 `全部通过`
**失败了怎么退**：`git checkout cards/`（或备份文件名）
**这一步做完，游戏会变成**：…
```

★ 只写不改（任务书禁止改代码）。

## 硬规则

1. **文档类任务，不许改任何 `cards/*.json`、`engine/*`、`web/*`、`tools/*`**。
2. **每章必须有「本章待确认」表** —— 没有说明你没在判断。
3. **不许用「综合来看」「整体而言」「值得注意的是」**。
4. 引用别人结论必须带出处文件名。
5. 矛盾不许掩盖，标 ⚠ 并给倾向。
6. 每完成一步，追加 `TASK_DONE.md` 一条。
7. **不许停下来问**。需要判断就按「对项目最有利」自己定，写进「决定记录」。

## 做完之后

如果四步都完了还有额度：**回头把第一步里标「可信度低」的篇目逐篇复核**，能补的补，补不了的在 `06_RISKS.md` 里记清楚为什么低。

全做完，在 `MASTER_PLAN.md` 末尾写一节「这个方案的薄弱处」，然后停。
