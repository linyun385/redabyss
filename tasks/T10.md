# T10 岔路地图（把线性流程变成选择）

## 前置
T6 已完成（8 层线性推进）。

## 问题
现在是「每层固定 3 个节点依次走」，玩家没有选择。杀戮尖塔的核心乐趣是**看地图做取舍**。

## 产出
1. `layers/layers.json` 扩展成岔路结构
2. 前端画出层内地图片让玩家点选

## 数据结构
每层的节点从数组改成有连接关系的图：

```json
{
  "id": 3,
  "name": "干旱空洞区",
  "rows": [
    [{ "type": "combat" }, { "type": "combat" }],
    [{ "type": "event" },  { "type": "elite" }],
    [{ "type": "event" },  { "type": "combat" }],
    [{ "type": "elite" }]
  ]
}
```

规则：
- 每行 1–2 个节点
- 只能走到**下一行的相邻节点**（左中右三选一，越界则只能选可用的）
- 每层最后一行是单一节点（战斗或 Boss）
- **总数控制在 4–5 行**，不要更多

## 前端
- 每层进入时显示该层地图（用 Unicode / CSS 画，不用图片）
- 当前位置高亮，可选节点闪烁
- 走过的节点变暗
- 点击可选节点即进入
- 顶部仍然显示「第 X 层 · 第 Y 行」

## 保持兼容
- `nodes` 数组结构保留，引擎读 `rows` 时优先用 `rows`，没有则回退到 `nodes`
- 8 层的 `name` 和 `id` 不许改

## 设计要点（这一段是重点）
岔路不是随便分叉，要让玩家**有理由选**：
- 一条路给卡牌，一条路给遗物
- 一条路是精英（危险但给遗物），一条路是事件（安全但收益不确定）
- 至少有一层，两条路的终点是不同的 Boss 前置资源

在 `TASK_DONE.md` 里写一句话说明每层的岔路在让玩家权衡什么。
