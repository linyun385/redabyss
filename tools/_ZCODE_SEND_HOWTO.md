# 给 ZCode 发消息 · 可用方法（2026-11-05 02:11 验证通过）

## 结论

**`tools/glm_nudge.py` 能用。** 2026-11-05 02:11 实测：消息变成聊天记录里的用户气泡，输入框清空，出现「工作中 4.0 秒」。

## 三步（必须按这个顺序，不许跳）

```powershell
cd C:\Users\Administrator\Desktop\杂七杂八\红渊\game

# 1. 把要说的话写进文件（中文直接走命令行会乱码）
#    tools\_nudge.txt，UTF-8

python tools/glm_nudge.py --text-file tools\_nudge.txt

# 3. 看截图 *_nudge_pasted.png，确认文字进了输入框，再加 --send
python tools/glm_nudge.py --text-file tools\_nudge.txt --send
```

## 关键参数

| 项 | 值 |
|---|---|
| 输入框窗口内比例坐标 | **(0.63, 0.887)** ← 2026-11-05 02:10 按截图校准 |
| 实际像素（1875×1537 窗口） | (1965, 1363) |
| 点击方式 | `SetCursorPos` + `mouse_event`，**不用 pyautogui.click**（150% 缩放下会点偏） |
| 文本传递 | **必须走 `--text-file`**，命令行直传中文会变乱码 |

## 怎么判断真的发出去了（§7.4 要求至少一条）

1. **截图里看到消息变成用户气泡**（右侧、深色框）
2. 输入框清空、placeholder 变回「继续输入以排队后续修改」
3. 下方出现「工作中 N 秒」

**`rc=0` 不算成功。** 这是 2026-11-04 三次假成功留下的教训。

## 不要用 send_robust.py

它的 `INPUT_BOX = (0.45, 0.893)` 是 10-30 校准的老坐标，窗口布局变了会点到别的地方（它自己注释里记着踩过：0.59 是发送按钮、150% 缩放点偏）。用 `glm_nudge.py`。

## 什么时候需要发

| 场景 | 要不要发 |
|---|---|
| GLM 队列耗尽、按规矩停了 | **要**，告诉它 INBOX 有新任务 |
| GLM 报错停住 | **要**，先看截图确认报错内容，再决定发什么 |
| GLM 正在跑 | **不要**，会打断它 |
| 用户睡着 | 可以发（这是被授权的），但**不要叫醒用户** |

## 发之前必须确认窗口状态

先 `pet_act shot` 截屏看一眼：
- 会话正常、输入框空着 → 可以发
- 有报错弹窗 / 正在输出 → 先别发
